# Harness 对照与能力缺口升级计划

日期：2026-10-19  
范围：`RAG/ue-rag` + `AIAgentProject`  
前提：[`Plan/20261016-1700-AI蒸馏与技能闭环升级计划.md`](20261016-1700-AI蒸馏与技能闭环升级计划.md) 的脚手架已经在代码里。`WORKFLOW.md` 记到 2026-10-17：`learned_skills.json`、`failure_patterns.json`、`clarify_policy.json`、`distill.py`、动作候选、索引队列、菜单 2 与菜单 3 共用 `plan_windows`。本计划不重做这些文件，也不换运行时。

目标：用 2026 年已经跑在生产里的 Agent Harness 当尺子，标出当前 UE-AI 工作流还缺的能力，并给出仍留在现有闸门里的升级顺序。

## 0. 这份计划怎么用

对照的是四份公开材料，不把二次转述里的 API 名当成要接入的接口：

沿用 10 月 16 日计划里的边界：

- 不把 `--query` 接成 Cursor 每句话的默认动作。

## 1. 判断摘要

当前系统已经是一个垂直 Harness，强项集中在治理和硬验收。10 月 16 日计划补上的是「学过的句子」和「失败/澄清的影子文件」。成熟 Harness 多出来的，是长任务怎么交接、验收条款怎么在开工前写成默认失败、蒸馏候选怎么回放之后才提升。

一句话：

> 闸门留着。补上交接文件、默认失败的验收合同、回放之后才提升的技能。编译器继续当裁判，模型继续不当裁判。

`data/skills/learned_skills.json` 现有 1 条已提升技能，`source_runs` 为空。`failure_patterns.json` 有 1 条 `error C3861`。`data/distill/` 只有 `.gitkeep`。蒸馏函数写明 `model: False`，不执行。

## 2. 七层对照

| 层 | 成熟 Harness 的做法 | 当前 `ue-rag` | 缺口 |
| --- | --- | --- | --- |
| 执行环境 | 命令跑在沙箱或可替换后端里，坏了就丢弃这份环境 | 改的是本机 `Source/AIAgentProject` 和正在运行的编辑器。编译前关掉 `UnrealEditor.exe`。源码有字节快照 | 关卡属性没有事务。索引侧评测已写明没有 Transaction/Undo，见 `eval/reports/20261016-171408-cancel.md` |
| 工具 | 一小套稳定工具，参数有 schema，结果可再取所以可以清掉 | 闭环动作表 8 个（`agent/catalog.py`）。契约 6 个（`contract/tools.json`）不进动作表。官方 830 个只在 Cursor 扫描路径 | 三套工具不汇合。闭环里的模型不能临时选用契约工具 |
| 上下文 | 压缩、工具结果占位、会话外笔记；子代理要么隔离要么继承父级 | `agent/context.py` 发给模型的是原句、最近一条「裁判失败」、当前角色最近 6 条工具结果。`state["messages"]` 和 checkpoint 仍是全量 | 成功写出的 diff 会掉出这 6 条。没有会话外交接文件。窗口是新 `thread_id`，只带这一扇的句子 |
| 生命周期 | 初始化写出功能清单；之后一轮只做一个功能；停下来留下进度和提交 | 开跑前拆完全部窗口。扇内 `fix` 可以重试。续接靠 sqlite checkpoint 和 `data/runs/...json` | 没有「本扇做完哪一条、下一条是什么」的文件。扇间不能按证据改计划 |
| 观测 | 一次决策能对上技能版本、上下文来源、停因、父子 span | `data/events`、`data/traces`、`data/costs.jsonl`、`eval/report.py` 的静态 HTML | 对不上 `skill_id`、停因、这次放进上下文的是哪几类消息 |
| 验收 | 条款先全部为失败，换一个没写过这段代码的上下文来对证据。能点界面就点界面 | 裁判是编译、蓝图编译、坐标、Automation。`integrate_verify` 验幂等、拒答、延迟、断线、未知态 | 玩法读数不在一句话的合同里。`AIAgent.Enemy.Patrol` 只挂在 `eval/tasks/side/demo-c-patrol.json` |

## 3. 已经有的，本计划不动

这些对得上成熟 Harness，再做一遍只会把闸门拆松：

- 图的边固定：`retrieve → plan → execute → build → test → observe → fix`。`verify` 非空时模型不能 `finish`。
- 人审：任务书确认、`s/c/r` 只问一次，选择写入 `confirm`。
- 续接：`done` 扇复用结果，中断扇用原 `thread_id`。源码失败走 `data/snapshots`。
- 只读裁决并行，写编辑器和 `cpp_build` 串行。
- 理解器只从动作表选动作。表外动作进候选，人审并补上验证才入表。
- 整句集成成功且 `unresolved` 为空才把技能升成 `promoted`。规划完还没跑赢的只进影子。
- `fix` 先查 `failure_patterns.json`，症状对不上再查一条 `ue_error`。失败任务不入库。
- Token：技能卡片不带 schema，理解器约 1KB，角色上下文按工具切开。
- 评测：`check_routes.py`、`check_upgrade.py`、`check_distill.py` 离线打印 `routes ok`、`upgrade ok`、`distill ok`。

## 4. 还缺的能力

按「一句话生成会巡逻的敌人」和「拿仓库给人看时讲得清」一起排。前面的挡路，后面的是讲不清。

### 4.1 验收合同没有挂到这句话上

旁路任务 `demo-c-patrol.json` 已经要求三件读数：相对出生点有位移、玩家靠近后距离缩小、距离内 `OnMeleeAttack` 被调用。过滤器是 `AIAgent.Enemy.Patrol`。它 `judge_first: true`，不改源码。

自然语言路径不产生这份合同。`agent/supervise.py` 只有句子里同时出现过滤器和「自动化 / 测试」才写入 `automation_filter`。目标句是「生成会巡逻、发现玩家后追击、近距离攻击的敌人」，三个读数都不会变成 `verify`。

`integrate_verify` 加的是基础设施矩阵，不是这三件读数。`blueprint_compile` 返回空只说明图能编过。这和 [`Plan/20261015-2100-周计划缺口与面试能力升级.md`](20261015-2100-周计划缺口与面试能力升级.md) 引用的 CraftBench-UE 是同一类空洞：资产检查通过，运行时仍然失败。

成熟 Harness 的对应物是开工前的 sprint contract：每条验收从 `passed: false` 开始，没有证据就不能改成通过。本仓库的裁判种类够用，缺的是一句话把它们填进合同。

### 4.2 扇与扇之间没有交接文件

Anthropic 的长任务靠 `claude-progress.txt` 加 git 历史，下一轮先读这个，再动手。Deep Agents 的隔离子代理只拿到任务句，父级已经读过的文件会再读一遍；所以他们另做了 fork。

当前窗口更接近隔离子代理：新 `thread_id`，消息里只有这一扇的句子。工件按名字传 `{ref, in_level}`。checkpoint 里有全量消息，续接恢复的是同一扇的对话，不是「上一扇留下的证据清单」。

`visible_messages` 再切一刀，模型看不到全量。最近 6 条里如果都是 `read_source`，更早的 `apply_unified_diff` 不会出现在请求里。全量仍留在 sqlite 里，恢复时又把已经没用的工具原文带回来。

缺的是一份不叫模型写的交接：这一扇做了什么、哪条裁判通过、哪条还是失败、下一扇该读哪份证据。

### 4.3 蒸馏停在分类，没有回放门

`agent/distill.py` 只读最多 40 个事件文件、20 个 trace、各 40 个 run json。它做的是按 sha1 去重，把 `intent`、`window_result`、带 `error C` 的备注、`confirm` 里的路径收成五份 jsonl。

它不读：

- `data/archive/<run_id>/` 的文件哈希和矩阵结果
- `data/snapshots` 与 unified diff
- `documents/历史解决方案.md`、`documents/排障条目.md`
- `.cursor/memory/任务记录/`
- `data/ledger.json`

失败样本的 `symptom` 固定写成 `"error C"`，错误码被截掉。教师模型那一步没有写。`compare_actions` 只比较已提升技能和旧路由拆出的动作名，`executed` 恒为 `false`。

所以 10 月 16 日计划里的「影子 → 回放 → 人审 → 提升」只落地了影子和人审。回放没有发生。技能库不会自己变厚。`learned_skills.json` 那一条 `when` 是「可交互」，`source_runs` 是空数组，它是种子，不是某次 run 蒸馏出来的。

### 4.4 上下文没有「可再取的结果可以清掉」

成熟做法把工具结果分成必须留下的和可以再调用取回的。清掉的是正文，留下工具名。压缩是整段对话换成一份摘要，成本高，而且会改写事实。本仓库不适合先上压缩：理解器已经卡在 1KB 上下，再为压缩打一次模型，和现有成本目标相反。

适合先做的是确定性规则：

- 发给模型的列表里，最近一条成功的 `apply_unified_diff` 和最近一条裁判失败永远保留，不受 6 条上限排挤。
- checkpoint 里更早的工具正文换成「工具名 + sha1 + 可再读」，不删工具调用记录。
- 摘要不交给模型生成。交接文件用裁判 JSON 拼。

### 4.5 三套工具在闭环里只看得见一套

`catalog.py` 的动作是 `compile_project`、`compile_blueprint`、`edit_cpp`、`bind_blueprint`、`place_actor`、`judge_pickup`、`set_pickable`、`move_actor`。`integrate_verify` 由代码追加。

`contract/tools.json` 的 `query_actor`、`query_blueprint`、`find_asset`、`build_project`、`run_automation_test`、`get_build_error` 给网关和外部客户端。`eval/reports/architecture.md` 写明它们不进这 8 个动作。

Cursor 路径用 `scan_mcp_tools.py` 看卡片。闭环路径的规划者看不到卡片，也看不到契约 schema。

这是收口，也是缺口：巡逻读数需要的 Automation 过滤器和只读查询，在动作表里没有一格。表外候选制度是对的，缺一条「人审之前，代码可以把已有契约工具登记成只读动作」的窄通道。只读，仍然不执行写。

### 4.6 观测对不上一次决策

Arize 那张表要求每次循环能回答：停在第几轮、为什么停、上下文从哪来、用了哪版技能、拒绝时用的是哪版策略。

当前事件有 `intent`、`tool_call`、`judge`、`skill_promoted`、`distill_candidate`。`intent` 存动作名、`unresolved`、理解器 token。一次 L0 命中不会写下 `skill_id` 和 `version`。`context.py` 的切片不产生事件。拒绝写在 `note` 文本里，没有 `policy_version`。

静态 HTML 够用，不另起常驻观测服务。缺的是字段，不是仪表盘。

### 4.7 执行环境就是这台正在用的编辑器

沙箱解决不了这件事。UE 编辑器加载的是本机模块，微虚机里没有这套引擎。编译前关编辑器是为了放开 `AIAgentProjectEditor` 的 DLL，这个行为保留。

缺的是写 Actor 之后的恢复。源码有字节快照。关卡默认不保存，重载能回到打开时的样子，但同一次编辑器会话里写过的属性没有事务可撤。`set_pickable` 写的是实例字段。失败扇如果已经写了一半，续接看到的是半截属性。

不新扫 830 个工具。现有评测记录已经说明索引里没有 Transaction。本阶段在写属性前把读到的字段放进快照，失败且任务没有 `keep_source` 时写回，仍然不保存关卡。

### 4.8 两个入口不共享 Harness 状态

Cursor 按 `AGENTS.md` 说话，不调用 `run_task.py`。菜单 2 和菜单 3 走 `plan_windows`。技能提升、交接、验收合同只发生在第二条入口。人在 Cursor 里改完 C++ 再去菜单里跑，菜单看不到这次改动的证据，除非重新编译进了索引。

本计划不把菜单接成 Cursor 默认动作。要补的是一份两边都能读的交接目录：Cursor 改完工程、按规矩写了任务记录之后，菜单开跑时能读到「上次留下的未完成条款」。读的是文件，不把 Cursor 对话灌进图。

## 5. 优劣

### 相对这些 Harness，当前工作流更稳的地方

- 成功由 `core/judge.py` 判定。Anthropic 在 2026-03 的长任务里单独做验收员，就是因为实现者给自己打分会偏高。这边编译和断言已经在模型外面。
- 写关卡、PIE、改图默认拒绝，拒绝点在 `editor_exec.py` 和 shell hook，不靠模型遵守提示。
- 循环的边是代码。模型填当前节点的工具，改不了下一跳。UE 里一次写错会动到关卡，这个控制权留在代码里是对的。
- 模型和供应商可以换。`UE_LLM_MODEL` 缺省 `deepseek-chat`。Claude Agent SDK 和 OpenAI 沙箱都把运行时绑在自家模型或自家托管环境上。
- 单次理解的 token 是卡住的。Anthropic 那次完整 Harness 跑一个应用大约 6 小时、费用约是单代理的 20 倍。本仓库的日常任务不走那条成本曲线。
- 技能进 L0 之前要整句跑赢。会话中途自动往技能文件里追加，会把没验证的步骤变成下次的快路径。

### 相对这些 Harness，当前工作流做不到的地方

- 长任务的现场在 sqlite 和事件流里，不在一份下一轮先读的短文件里。中断后续接的是对话，不是条款。
- 一句话覆盖不到运行时读数。巡逻的 Automation 在旁路 JSON，目标句仍停在 C++ 半边加人绑的蓝图步骤。
- 技能库不随成功 run 变厚。蒸馏不回放，提升看的是这一次集成，不看候选是否比旧路由更少 `unresolved`。
- 发给模型的上下文会丢掉较早的成功 diff，checkpoint 又留着全部工具正文。
- 闭环动作表、六工具契约、官方 MCP 卡片各走各的。只读查询进不了自然句。
- 一次命中了哪条技能、因哪条规则停住，事件里对不上。
- 编辑器会话里的属性写没有事务。源码回滚覆盖不到这一半。
- Cursor 里的修改和菜单里的 run 不共享未完成条款。

## 6. 升级原则

继续用现在这张 LangGraph。从成熟 Harness 借三件已经能对上现有文件的东西：

1. 交接文件。用裁判和窗口结果拼，不叫模型写总结。
2. 验收合同。每条从 `passed: false` 开始，只有对得上的 `judge.kind` 能把它改成通过。
3. 回放门。候选技能先在离线规划里和源 run 比动作序列，一致或 `unresolved` 更少，才允许人审提升。

明确不借的：

- 让模型拥有循环、自己决定何时结束。
- 为了压缩再打一次模型。
- 把编辑器放进 Docker 或通用代码沙箱。
- 每句话都跑计划者、实现者、验收员三轮模型。验收员只在合同里有代码裁判覆盖不了的条款时出现，而且它不能把 `passed` 改成 true。
- 自动绑行为树、动画、受击。步骤仍写 `Plan/`。

## 7. 分阶段

### P0 决策字段（1–2 天）

不改路由，只让一次 run 能回答 Arize 那张表里的四个问题。

动作：

- `intent`、`learned_route`、`skill_promoted` 带上 `skill_id`、`version`、`status`。L0 命中手写规则时 `skill_id` 为空，`source` 写 `rules`。
- `window_result` 和 `run_end` 增加 `stop_reason`：`ok`、`paused`、`retry_exceeded`、`read_stall`、`judge_failed`、`unresolved` 之一。
- 新增事件 `context_slice`：只记计数，`user`、`judge_fail`、`tool_kept`、`tool_dropped`。不记工具正文。
- 拒绝写入 `policy`：`save`、`pie`、`allow_writes`、相关 `UE_ALLOW_*` 的当前值。不记新的策略语言。

验收：

```powershell
python eval/check_harness.py
```

打印 `harness ok`。不叫模型，不写场景。`check_routes.py` 仍打印 `routes ok`。

### P1 交接文件（2–3 天）

动作：

- 每扇结束写 `data/handoffs/<run_id>/<window_id>.json`。
- 字段：`did`、`evidence`（`kind`、`ok`、`summary` 截断）、`unmet`、`next`、`artifacts`。
- 内容来自这一扇的 `window_result` 和两份裁判。不调用模型。
- 续接时面板和下一扇的用户消息带上这份 JSON。不带上一扇的工具原文。
- 任务记录目录只在人已经写下当天文件时读取未完成标题；没有文件就不编。

验收：

- 删掉 handoff 目录后，续接仍能靠原来的 checkpoint 跑，只是消息里少这一段。

### P2 验收合同（3–4 天）

动作：

- 任务书确认时，每个范围写 `criteria[]`：`id`、`text`、`evidence_kind`、`passed: false`。
- `evidence_kind` 只允许 `cpp_build`、`blueprint_compile`、`editor_assert`、`automation`、`manual`。
- `observe` 在 `judge.ok` 且 `judge.kind` 等于 `evidence_kind` 时把对应条款改成 `passed: true`。
- `manual` 保持 false，留给 `Plan/` 里的人绑步骤。模型输出改不了它。
- 句子含「巡逻」且点名了敌人时，代码追加一条 `automation` 条款，过滤器 `AIAgent.Enemy.Patrol`。人没有在句子里要求 PIE 就不加 `pie`。
- 全部自动条款通过、仍有 `manual` 时，整句记「部分完成」，和现在的失败扇口径一致。

验收：

- 巡逻句的合同里有 `AIAgent.Enemy.Patrol`，`passed` 在 Automation 失败时仍是 false。
- 模型回复里写「已完成」不会改合同。

## 10. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 交接文件把长错误原文又灌进下一扇 | `summary` 截断，和现在 trace 的截断同一档；工具正文不进 handoff |
| 合同条款和裁判种类对不齐，永远 false | `evidence_kind` 用枚举，对不上就停在这一条并写明，不猜另一个裁判 |
| 巡逻 Automation 在编辑器没开时失败，整句被写成失败 | 和现在一样记失败，不改成「不能」。`manual` 条款单独列出 |
| 教师蒸馏固化错动作 | 默认关闭。打开也只写 `candidates.jsonl`。提升还要过回放和现有的集成成功条件 |
| 清掉工具正文后修不好 bug | 保留工具名和 sha1；`read_source` 可以再读。最近成功 diff 不清 |
| 属性写回写错对象 | 只写回快照里那几个字段，路径不唯一就不写 |
| 只读动作把契约工具变成第二条写入口 | 本阶段只登记 `query_actor` 和 `run_automation_test`，写前缀规则不改 |

回滚：

- 停写 handoff 不影响旧续接。
- 合同生成可关，退回现在的 `verify` 数组。
- `UE_DISTILL_TEACHER` 默认空。
- 新只读动作从动作表删除即可，契约 server 不动。
- 属性快照写回失败时保持现在的行为：不保存，重载关卡回到打开时。

## 13. 完成定义
