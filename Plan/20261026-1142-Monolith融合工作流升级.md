## 0. 这份计划怎么用

下一轮在新分支上按第 10 节逐段做。操作手册仍是 [WORKFLOW.md](../WORKFLOW.md)。环境变量只认 [RAG/ue-rag/.env](../../RAG/ue-rag/.env)，读法与 [config.py](../../RAG/ue-rag/config.py) 的 `_env_str` / `_env_bool` 相同。键名同步写进 [.env.example](../../RAG/ue-rag/.env.example)，示例文件只列名，不写密钥。

## 1. 结论

`RAG/monolith-master` 是 Unreal 编辑器插件 **Monolith 0.24.0**（Beta，MIT，UE 5.7 / 5.8）。它用大约 26 个命名空间、1400 多个 action，对外收成 `{namespace}_query(action, params)` 加 `monolith_discover` / `describe_query`。作者明确拿它替换「每个动作注册成一个工具」的 MCP。本仓库官方路径正是这种形态：52 个工具集、830 个工具，端口 `http://127.0.0.1:8000/mcp`。

两边都改同一类资产，名字还会撞车（`connect_pins`、`add_variable`、编译蓝图）。官方认图 DSL 和 `pin_id`，Monolith 认 `graph_name` 和 `node_id`。按能力拆给两边，失败重试会换一套身份再写一次，闸门也认不出。所以它们是竞争关系：后端整段切换，不在一次任务里拼用。

`Skills/` 里 18 份带 YAML 头的文件是 Monolith 自己的说明书，不是本仓库的技能。新分支另写只认 discover / describe / exec 的技能。正文只写在 `.codex/skills`。`.cursor/skills` 是 Cursor 镜像，`.agents/skills` 是联到 `.codex/skills` 的发现入口，不各写一份。不把这 18 份设成自动技能，也不把动作大表拷进这三处。

Monolith 盖得比官方宽的部分（行为树、GAS、动画蓝图、Niagara HLSL、UMG、源码索引、Reflection Intelligence）随 `backend=monolith` 一起可用，不再单独做成「官方不够时才呼叫」的旁路。公开命名空间里没有 PCG。`backend=monolith` 时 PCG 直接失败并说明原因，不改去调官方 MCP。

关卡 Actor 在 `mesh` 命名空间：`spawn_actor`、`move_actor`、`get_actor_info`。`editor-cube` 可以在新后端上重做，裁判要按 Monolith 的返回重写，不能复用 `get_actor_transform` 的字段。

## 2. 插件事实（实现时别猜）

- 源码在 `RAG/monolith-master`，20 个 `Source/Monolith*` 模块。运行时放进 `AIAgentProject/Plugins/Monolith`，用本机 UE 5.8.2 从源码编译。发布包 DLL 锁引擎版本，不能直接拿来开 5.8.2。
- 编辑器 HTTP 端口 **9316**，绑全部网卡。自动更新保持关。不受信任的网络上挡住非本机入站。
- `monolith_discover(namespace)` 默认只有名字和一行说明。参数用一次 `describe_query("action_schema", ...)`。禁止 `detail=true` 把整份 schema 拉进上下文。
- 可选模块（`ai`、`gas`、`combograph`、`logicdriver`、MetaSound）以当次 `monolith_discover()` 的结果为准。没注册就报「命名空间未加载」，不在代码里写死一份残缺白名单，也不因此去调官方工具。
- `bEnableProceduralTownGen` 保持插件缺省（关）。调度器不单独屏蔽它：插件自己打开后，discover 能看见就可以调用。
- 离线 `monolith_query.exe` 属于 Monolith 后端的只读能力，仅 `backend=monolith` 时使用。它不替换 `search_ue_project`。向量库不是官方 MCP，两条后端都保留。

命名空间与现有域的对应，供新技能卡片使用：

| material | 材质 |
| animation | 动画 / Control Rig |
| niagara | Niagara |
| mesh | 静态网格，另含关卡 Actor 的生成与移动 |
| ui | UMG |

| gas / combograph / logicdriver / audio / input / localization | 官方路径没有对等作者面 |

## 3. `.env` 配置

文件：`E:\UEProject\AIWork\RAG\ue-rag\.env`。  
示例：`E:\UEProject\AIWork\RAG\ue-rag\.env.example` 追加键名，值为空。  
实现落在 `config.py`：`editor_backend()`、`monolith_url()`、`monolith_root()` 每次读环境变量，缺省与下表一致。hook 和 DSH 网关像 `graph_write_policy.env_flag` 一样直接读这份 `.env` 文件，避免只在 import 时钉死。改完 `.env` 后新开进程再跑任务。

### 3.1 后端开关

| 键 | 缺省 | 取值 |
| --- | --- | --- |
| `UE_EDITOR_BACKEND` | `official` | `official` 或 `monolith`，大小写不敏感 |
| `UE_MONOLITH_URL` | `http://127.0.0.1:9316/mcp` | 仅 `monolith` 时作为编辑器地址 |
| `UE_MONOLITH_ROOT` | `E:\UEProject\AIWork\RAG\monolith-master` | 说明书与离线查询的源码位置。已加载的插件在工程 `Plugins/Monolith` |

`UE_MCP_URL` 保持现在的缺省 `http://127.0.0.1:8000/mcp`，只在 `official` 时使用。`backend=monolith` 时忽略它，不允许当作回退地址。

非法值（空字符串以外的其他拼写）拒绝一切编辑器调用，错误原文写出允许的两个值。未写这个键等于 `official`，现有脚本行为不变。

一次运行在入口读一次，写进该 run 的事件。运行中改 `.env` 不改变这次已经选定的后端。

### 3.2 写许可（第二条轴，与选哪台服务器无关）

五个已有键两条后端都生效，缺省仍是 false：

| 键 | 管的写 |
| --- | --- |
| `UE_ALLOW_BLUEPRINT` | 官方蓝图写工具；Monolith 的 `blueprint` 非只读 action |
| `UE_ALLOW_MATERIAL` | 材质图 |
| `UE_ALLOW_UMG` | UMG；Monolith 命名空间是 `ui` |
| `UE_ALLOW_ANIM` | 动画蓝图 / Control Rig；Monolith 命名空间是 `animation` |
| `UE_ALLOW_NIAGARA` | Niagara |

Monolith 多出来的作者面用同文件里的新键，缺省 false。`backend=official` 时这些键不放行任何官方工具。

| 键 | 管的写 |
| --- | --- |
| `UE_ALLOW_AI` | `ai`（行为树、黑板、StateTree、EQS、感知、导航） |
| `UE_ALLOW_MONOLITH_WRITE` | 其余命名空间的非只读 action：`gas`、`combograph`、`logicdriver`、`audio`、`mesh`、`level_sequence`、`input`、`localization`、`config`、`source`、`project`、`editor`，以及 Reflection Intelligence 里的写操作 |

只读前缀两条后端通用：`get` / `list` / `find` / `read` / `search` / `discover`，另加 `validate` / `compare` / `audit` / `explain` / `resolve`。`compile_blueprint`、`compile_widget` 视为编译裁判，允许，且不顺便保存。拿不准的 action 当写。

`save`、`pie`、`run_python`、`load_level` 不跟 `UE_ALLOW_MONOLITH_WRITE` 走。它们仍看任务书上的 `save` / `pie`，缺省来自已有的 `UE_DEFAULT_SAVE`、`UE_DEFAULT_PIE`。`run_python` 仅当该任务明确写出 `allow_python: true` 才放行。

想把 Monolith 的写全部打开，在 `.env` 里写成：

```text
UE_EDITOR_BACKEND=monolith
UE_MONOLITH_URL=http://127.0.0.1:9316/mcp
UE_MONOLITH_ROOT=E:\UEProject\AIWork\RAG\monolith-master
UE_ALLOW_BLUEPRINT=true
UE_ALLOW_MATERIAL=true
UE_ALLOW_UMG=true
UE_ALLOW_ANIM=true
UE_ALLOW_NIAGARA=true
UE_ALLOW_AI=true
UE_ALLOW_MONOLITH_WRITE=true
```

未改 `.env` 时仍是官方后端、改图关闭。接入代码与放行开关分开：命名空间在 Monolith 分支上全部接到调度器；上面这些键决定这次能不能写。

## 4. 分支与代码

新分支：`feat/monolith-backend`。官方实现留在原函数里，外面加选择层。`UE_EDITOR_BACKEND=official` 时调用栈和返回形状与现在一致，三条评测不改断言。

Monolith 与选择层全部新文件，放在 `RAG/ue-rag/backends/`：

```text
backends/select.py       读 UE_EDITOR_BACKEND；选错入口直接拒绝
backends/official.py     转发现有 scan_mcp_tools / call_mcp_tool / editor_exec
backends/monolith.py     discover、describe、exec。不按 action 手写 1400 个函数
```

`monolith.py` 的契约：

1. `discover(namespace)`：向 9316 要该命名空间的名字和一行说明。不传 `detail=true`。stdout 约 200 字，过长截断。
2. `describe(namespace, action)`：只要这一个 action 的参数。
3. `exec(namespace, action, params)`：执行一次。先过第 3.2 节的写许可。
4. 入口若发现本次后端是 `official`，三个函数都拒绝，原文含 `UE_EDITOR_BACKEND=official`。
5. 官方入口若发现本次后端是 `monolith`，同样拒绝，原文含 `UE_EDITOR_BACKEND=monolith`。禁止捕获这个拒绝后再调另一边。

同一编辑器任务仍最多 8 次调用。`get_graph_data` 不带过滤时适配层拒绝，先用 `get_graph_summary`。

裁判按后端分叉，合同种类保持 `blueprint_compile`、`editor_assert`、`cpp_build`、`automation`：

- `official`：沿用现在的工具和「编译成功返回 null」。
- `monolith`：编译改走 `blueprint_query("compile_blueprint")` 或 `ui_query("compile_widget")`；Actor 位置改走 `mesh_query("get_actor_info")`。判定字段在第一次实读后写进适配层，不猜官方字段名。

DSH 不把 Monolith 服务器配进会注入全部 schema 的客户端。`backend=monolith` 时，现有 `scan_editor_tools` / `get_editor_tool_schema` / `exec_editor_tool` 转到 `backends/monolith.py`。工具个数不增加。`allow_writes` / `save` / `pie` 仍只从人写的 `session_task.json` 读。
