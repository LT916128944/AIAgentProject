## 0. 三句话结论

1. Niagara **完全空白**：`CATALOG` 无一等动作，验收无 `_KIND_BY_ACTION` 映射；粒子需求今天落 `solve`（模型 discover `niagara` 命名空间→exec 原语，automation 收口，兜不住）。
2. 工具层有 **5 个 Niagara toolset**（Info/Component/Blueprint/System/Assets），能力足够；缺的是**确定性执行 kernel + 只读状态复核 + 回灌**。
3. 升级分两级：**A 级**“在对象上加 NiagaraComponent 引用已有 System 并设 User 参数”（低垂果实）；**B 级**“建/改 System 资产：发射器/模块/渲染器/参数”（大件）。

## 1. 现状与证据

| 项 | 现状 |
| --- | --- |
| 一等动作 | **无** |
| 工具集 | `NiagaraToolset_Component`（组件挂载/参数）、`_System`（系统资产/发射器/模块栈）、`_Assets`（资产读写）、`_Info`、`_Blueprint`（Niagara 蓝图） |
| 路由实测 | “加一个爆炸粒子，死亡时播放” → `solve` |
| 验收 | 无专门 kind；solve 的 automation 收口对“加了粒子和效果”基本不可验 |

## 2. 本域“模型-脚本”边界

- **模型**：产 **Niagara Spec**——A 级：`{target actor, system ref, user params, activate}`；B 级：`{system asset, emitters:[{name}], modules:[{stack,module,params}], renderers, user params}`。
- **脚本**：A 级用 `NiagaraToolset_Component` 加组件/设参数；B 级用 `_System/_Assets` 建/改系统与栈；**只读复核**：组件存在且 System ref 对、User 参数读回==期望；或系统发射器/模块栈读回==Spec；资产保存。
- **硬规矩**：模型只产 Spec；写经 `UE_ALLOW_*` 写闸；`activate/save` 跟任务策略。

## 4. 分期

- **P0 清点（0.5d）**：`scan_mcp_tools --query "niagara component add system parameter"` / `"niagara modelemitter"` 摸清 5 个 toolset 的动作与读回能力。
- **P1 A 级 Spec+kernel+复核（1.5d）**：`agent/niagara_spec.py`；挂组件/设 User 参数；读回组件与参数。
- **P2 B 级 Spec+kernel（3d）**：建/改 System（发射器/模块/渲染器/参数）；读回栈结构做 verifier。
- **P3 回灌修复（1d）**；**P4 沉淀**（常见特效“爆炸/火焰/拖尾”参数化毕业）。

## 5. 守卫
