## 0. 三句话结论

1. 后处理**没有专用工具集，也没有一等动作**，今天落 `solve`；它是“**在对象属性上设置 FPostProcessSettings**”（PostProcessVolume 或 Camera 的组件），没有“建一个后处理节点”的独立原语。
2. 所以本域升级 = **属性路径式 Spec**：`{目标(体积/相机), settings{bloom/exposure/vignette/...}, enabled/unbound}` → 脚本按属性路径 `set` → **只读读回**校验设定值。
3. 难点在 `FPostProcessSettings` 字段多且嵌套；先做**最常用一小组**（泛光/曝光/暗角/色调），其余按需扩。

## 2. 本域“模型-脚本”边界

- **模型**：产 **PostProcess Spec**：目标（关卡 PostProcessVolume 或 相机组件）、一组 setting→value（如 BloomIntensity、AutoExposure、VignetteIntensity）、是否 enabled/unbound。
- **脚本**：定位/建 PostProcessVolume（或取相机组件）→ 按属性路径设 `Settings.*` → **只读读回**每个 `Settings.<key>` == 期望 → 保存。
- **硬规矩**：模型只产 Spec；写经写闸；只对“已声明的 setting 白名单”设值（防止瞎设嵌套结构）。

## 3. PostProcess Spec 草案

```jsonc
{"kind":"post_process",
 "target":{"type":"volume","name":"PP_LevelDefault","unbound":true}, // 或 {"type":"camera","actor":"BP_PlayerCamera"}
 "settings":{"BloomIntensity":1.2,"VignetteIntensity":0.4,"AutoExposureMinBrightness":0.5,"AutoExposureMaxBrightness":2.0},
 "verify":["Settings.BloomIntensity==1.2","Settings.VignetteIntensity==0.4","unbound==true","saved"]}
```

## 4. 分期

- **P0 清点（0.5d）**：`scan_mcp_tools --query "post process volume settings"` / 用 `object/list_widget_properties` 式读回，确认 `FPostProcessSettings` 里最常用字段的属性路径与可读回性。
- **P1 Spec+kernel+读回复核（1.5d）**：`agent/postprocess_spec.py`：定位/建 Volume、写 settings、读回比对。
- **P2 相机组件变体（0.5d）**：同样 Spec 支持“相机组件 PostProcessSettings”。
- **P3 回灌修复（0.5d）**；**P4 沉淀**（“加泛光/调暗角”模板毕业）。

## 5. 守卫

`check_postprocess_spec.py`（setting 白名单、读回==期望、越界结构拒绝、target 定位唯一才动）、`check_postprocess_route.py`（“加泛光/调曝光/加暗角”稳定进链）。登记 `offline.yml`。

## 6. 风险与取舍

- 无专用原语 → 全靠**属性路径**：字段名/嵌套要 `list_widget_properties` 式读回确认，**不猜**；只支持白名单字段，未知字段回灌模型/暂停。
- “设上了”≠“画面好看”：到“值读回==期望”为止；观感人工。

## 7. 立即三件事

2. 落 Spec + kernel + 读回复核（先 Bloom/Exposure/Vignette）。
3. `check_postprocess_spec`。
