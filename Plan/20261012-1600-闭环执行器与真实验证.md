## 3. 已确认决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 谁执行编辑器工具 | 新建 `core/editor_exec.py`，Cursor CLI 和 LangGraph 都调它 | 卡住点是两套客户端 |
| 默认执行模式 | `UE_EXEC_MODE=real`。`mock` 仅当显式设置，Mock 分支从默认路径拿掉 | 假编译会让 fix 清空字符串后直接「成功」 |
| 写操作确认 | 取消 `input()`。写工具必须出现在任务的 `allow_writes` 里，否则返回 `{ok:false, error:"write refused"}` | 无人值守不能等回车。没列入的写等于拒绝 |
| 存盘 / PIE | 任务 JSON 里 `save: true` 或 `pie: true` 才允许对应工具。默认两个都 false | 沿用现在的「默认不保存、不 PIE」 |
| 裁判 | `core/judge.py` 返回结构体，observe 只读 `ok` 和 `errors` | 不再用 `"succeeded" in text` |
| 本轮三种真任务 | `editor_assert`、`blueprint_compile`、`cpp_build`。Automation 作为 `cpp_build` 成功后的可选第二裁判 | 前两个工具已验证；C++ 编译没有 MCP 工具 |
| 补丁怎么落地 | 编辑器：现有 MCP 写工具。C++：新增本地工具 `read_source` + `apply_unified_diff`，路径锁在 `Source/AIAgentProject` | 图里没有改文件的工具，fix 才会只剩一句话 |
| fix 的职责 | 把裁判的 `errors` 写进 messages，清空 `judge`，回到 plan。plan 必须再发出工具调用 | 现有边 `fix → plan` 可复用。不清空就永远停在失败上；只清字符串则假成功 |
| 检索增量 | 给 `retrieve` 加 `where`。文档和错误记忆走现有 JSONL + `ingest_assets.py`，`source_type` 用 `ue_doc` / `ue_error`。不做 BM25 | 卡住的是「找不到实现和旧错误」，不是排序算法 |
| 蓝图 Graph | 本轮不导出节点 | 没有现成导出器。任务必须带 `refPath`，或 RAG 的 `ue_asset` 唯一命中 |
| Skill | 从 `.cursor/skills/*/SKILL.md` 的 front matter 生成 `data/skill_cards.json`（name + description）。retrieve 后把最相关的一张描述塞进 plan 提示 | 不建注册服务。Agent 今天完全不读 Skill |
| 评测 | `eval/tasks.json` 三条 + `eval/report.py` 打表。跑之前 `Source/` 必须干净 | 没有重置，成功率不成立。三条够证明环是真的 |
| 回滚 | 不存盘的关卡改动靠不保存；C++ 靠 `git checkout -- Source`。本轮不找 Transaction 工具 | 索引里没有已验证的事务工具 |
| 路径 | 引擎、工程、Python 全部改读环境变量，缺省仍是现在的本机路径 | `config.py` 已有 `PROJECT_ROOT` |

未确认就不做：换 Embedding、把 `run_agent.py` 设成 Cursor 日常入口、改 `.cursor/rules` 让模型自动跑完整环。日常对话仍走 `WORKFLOW.md`。本计划交付的是一条命令。

### 4.2 单一执行器（卡住点 3、7）

- **新建** `RAG/ue-rag/core/editor_exec.py`

```text
exec_tool(toolset, tool, args, *, task) -> {ok, data|error}
```

行为：

1. `tool` 属于保存或 PIE（`save_assets`、`save_actor`、`StartPIE`、`StopPIE`）时，任务没开对应开关就拒绝。
2. 短名命中写前缀（与现在 `nodes.py` 的 `WRITE_HINTS` 同一份，挪到这个文件）且不在 `task["allow_writes"]` 里，拒绝。读工具不拦。
3. 通过则 `get_ue_mcp_client().call_ue_tool(...)`。
4. 返回完整结构体。不在这里截 200 字。

- **修改** `scripts/call_mcp_tool.py`  
  改为调用 `exec_tool`。CLI 没有任务文件时，`allow_writes` 只含本次 `--tool`，`save`/`pie` 默认 false。stdout 仍截到约 200 字，供 Cursor。
- **修改** `agent/nodes.py` 的 `execute_ue_tool`  
  本地工具（`search_ue_project`、`get_project_summary`、以及下面的 `read_source` / `apply_unified_diff`）仍走 Python。其余走 `exec_tool`。删除 `input()` 和默认 Mock。`UE_EXEC_MODE=mock` 时保留现在的两个假 Actor，且裁判也走假结果；real 模式下 `INJECT_*` 不生效。

### 4.3 真裁判（卡住点 2）

- **新建** `RAG/ue-rag/core/judge.py`  
  统一返回：

```text
{ok: bool, kind: str, summary: str, errors: [{file, line, message}]}
```

| kind | 调用 | 成功条件 |
| --- | --- | --- |
| `editor_assert` | 任务里写明的一个读工具，例如 `get_actor_transform` | `ok==true`，且 `expect` 里的字段相等（先只支持 location 的 x/y/z 数值，容差 1 uu） |
| `blueprint_compile` | `editor_toolset.toolsets.blueprint.BlueprintTools.compile_blueprint`，参数 `{blueprint:{refPath}}` | 客户端 `ok==true` 且 data 为 null / 空。这是事实库里已记下的成功形态 |
| `cpp_build` | 子进程 `UnrealEditor-Cmd.exe Project.uproject -run=Compile` 或本机已能用的等价命令；超时取 `UE_MCP_TIMEOUT` | 退出码 0，且日志里没有 `error C` |
| `automation` | `DiscoverTests` 一次（同进程缓存），再 `RunTestsByFilter`，再 `GetTestResults` | 结果 JSON 里失败数为 0。解析失败则 `ok:false`，不要把原文里的单词 `passed` 当成成功 |

`cpp_build` 的具体命令在实施时先在终端跑通一次再写死到 `judge.py`。若 `-run=Compile` 在 5.8 上不可用，改用引擎目录下的 `Build.bat AIAgentProjectEditor Win64 Development -Project=... -WaitMutex`。两种都不是新轮子，是编辑器自带的编译入口。选通的那一个，另一个不要留着。

日志解析只抽 `error Cxxxx` 和 `fatal error` 行，最多 20 条。蓝图编译失败把 MCP 返回的原文放进 `errors[0].message`。

- **修改** `agent/nodes.py` 的 `build_node` / `test_node`  
  `build_node` 在 `kind` 为 `cpp_build` 或 `blueprint_compile` 时调用 `judge`。`test_node` 在任务带 `automation_filter` 或 `editor_assert` 时调用对应裁判；没有测试声明则返回 `{ok:true, kind:"skip", errors:[]}`，observe 把 skip 当成通过。  
  删除「注入失败然后下一轮必然成功」的分支。
- **修改** `observe_node`  
  只看 `judge["ok"]`。失败才 `retry_count+1`。两者都 `ok` 才 `is_completed=true`。不要再搜消息里的 `finish` 来宣布编译任务成功。`require_build` 改名为任务里的 `verify` 列表是否非空；空则保持现在的 `finish` 工具。

### 4.4 计划变成补丁（卡住点 1）

- **新建** `RAG/ue-rag/agent/task_schema.py`  
  一个任务：

```json
{
  "id": "bp-gun-compile",
  "query": "编译 BP_Gun 并确认没有编译错误",
  "verify": [{"kind": "blueprint_compile", "refPath": "/Game/BP_Gun.BP_Gun"}],
  "allow_writes": [],
  "save": false,
  "pie": false,
  "max_retries": 3
}
```

- **修改** `plan_node`  
  系统提示里的项目上下文改为 `rag_core.retrieve(user_query, top_k=5)` 的 `content` 拼接，再加 `skill_cards` 里距离最近的一条 description。删掉写死的 `AEnemySpawnPoint`。  
  `require` 验证的任务仍然不给 `finish`。提示改为：工具调用是唯一能改工程的方式；空工具调用会直接进入裁判；裁判失败后你会在下一条里看到 `errors`。
- **新建本地工具**（放在 `tool_router.LOCAL_TOOLS`，`execute_ue_tool` 分发）  
  - `read_source(path, start_line, end_line)`：相对 `UE_SOURCE_ROOT`，拒绝 `..`。一次最多 80 行。  
  - `apply_unified_diff(path, diff)`：同一路径锁。只接受 unified diff，用 `patch` 不可用时用 Python 应用 `@@` 块。应用前文件必须与 diff 的旧行一致，否则返回冲突，不写一半。
- **修改** `fix_node`  
  不再只请求「不超过 80 字」。把 `errors` 作为下一条 user 消息：文件、行、原文。清空 `build_result`/`test_result` 改成清空 judge 结构，迫使下一轮重新裁判。`fix_plan` 可以留着给 trace，但不作为成功条件。  
  C++ 错误的下一轮 plan 应能调用 `read_source` 再 `apply_unified_diff`。编辑器错误的下一轮应能调用允许列表里的 MCP 工具。

- **新建** `RAG/ue-rag/agent/run_task.py`  
  `python agent/run_task.py --task eval/tasks/bp-gun-compile.json`  
  复用 `graph.py` 的 `builder` 和 `SqliteSaver`。每次新 `thread_id`。结束打印 judge 和重试次数，退出码 0/1。  
  `run_agent.py` 保留给手工对话，但默认 `UE_EXEC_MODE` 同样是 real，不再默认 Mock。
