# 2026-10-12 后续升级：多 Agent、自动改编译测、分层检索

本文件原先是升级计划。2026-10-12 已按这个顺序落地。不新造 UE MCP，不换向量库产品，不把 `run_task.py` 设成 Cursor 里每句话的默认动作。

现状以 `WORKFLOW.md` 为准。已落地的窄闭环见 `Plan/20261012-1600-闭环执行器与真实验证.md`。

## 1. Summary

三件后续工作，按这个顺序做。前一件没验收，不开始后一件。

1. **自动闭环**：一句话任务自己改 C++、自己编译、自己测试、失败再改。编译入口先证明再写死。
2. **多 Agent**：在现有图外面加分工，而不是再写一套 HTTP。
3. **分层检索**：先用便宜的检测丢掉大部分候选，再对剩下的做向量和重排。当前语料只有一百多条，慢在每次把整句丢进同一个向量模型，不在库太大。

## 2. 现在没有多 Agent

`agent/graph.py` 是一张图、一个 `deepseek-chat` 客户端、一份系统提示。`retrieve`、`plan`、`execute`、`build`、`test`、`observe`、`fix` 是这条链上的节点，不是互相委托的角色。

没有的东西：

- 没有监督者把一句话写成任务 JSON。任务仍是人手写的 `eval/tasks/*.json`。
- 没有「只许改 C++」「只许叫编辑器」「只许裁判」的分开提示和分开工具集。同一个 `plan_node` 同时看见本地 diff、编辑器工具和检索。
- 没有 Agent 之间的交接记录。trace 只记节点名、工具短名、`ok`、耗时、token。
- Cursor 日常链不调用 `run_task.py`。人确认计划之后，改文件的是 Cursor 里的模型，不是闭环进程。

所以：窄闭环能跑三条固定任务，多 Agent 协作还没有整合。

## 4. 分层检索：网上已有的架构

当前 `retrieve()` 对每句 query 做一次 `bge-small-zh-v1.5` 全库向量查询。工具选择是另一份 collection 的另一次编码。类名、`/Game/...` 路径这类专有名词会弱，而且每次 plan 都付整次 embedding 的代价。

公开架构里，和「又要快、又要准」对应的是**由便宜到贵的漏斗**，不是一个更大的向量模型。交叉编码器不能扫全库：每个 query-文档对都要一次前向。贵的阶段只看短名单。

| 来源 | 层 | 对本仓库的含义 |
| --- | --- | --- |
| [FUNNELRAG](https://aclanthology.org/2025.findings-naacl.165.pdf)（NAACL 2025 Findings） | 粗召回（BM25，长块，例如 top 80）→ 交叉编码器预排 → 更细粒度的 listwise 再排。候选变少，粒度变细，模型变贵 | 先按文件/类召回，再在命中的文件里看函数块。不要对 800 个工具的全文做交叉编码 |
| [Pistis-RAG](https://arxiv.org/abs/2407.00072) | matching 缩小空间 → pre-ranking → ranking → re-ranking，后面才是推理和汇总 | 第一层用 `source_type` / 路径 / 类名把 `ue_cpp`、`ue_asset`、`ue_doc`、`ue_error`、`ue_tools` 分开，而不是五类混在一次向量查询里 |
| [Two-step retrieval](https://brendanjameslynskey.github.io/RAG_08_Two_Step_Retrieval_Architecture/) | 便宜的高召回扫全库，贵的高精度只重排短名单。质量在 k≈50–100 饱和，延迟随 k 线性涨 | 重排名单封顶。语料仍是一百多条时，不引入 LLM 重排 |
| [Cascade rerankers](https://zeroentropy.dev/concepts/cascade-rerankers/) | BM25 或稠密召回 → 可选 bi-encoder 把名单砍小 → cross-encoder。四层以上通常不划算 | 本仓库最多三层检测。第四层（LLM 当裁判排序）不放进热路径 |
| [TREC 2022 多阶段排序](https://ar5iv.labs.arxiv.org/html/2308.12039)、[TREC 2025 RAG](https://trec.nist.gov/pubs/trec34/papers/UTokyo.rag.pdf) | 稀疏（BM25 / SPLADE）与稠密互补，RRF 融合后再重排。LLM 重排能明显抬 nDCG，也明显加延迟 | 类名和资产路径走稀疏；中文描述走现有 bge。LLM 重排留到题集证明向量排序不够时 |

不采用的：换 Embedding 产品、把技能全文向量化、为一百多条语料上分布式 ANN。

## 5. 已确认决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 多 Agent 落在哪 | 仍用 `agent/graph.py` 的边。监督者、C++、编辑器、裁判是不同的系统提示和工具子集，交接写进现有 trace | 上一轮刚把执行器和裁判收成一条出口。再写第二套图会把两套客户端的问题换个名字带回来 |
| 谁写任务 | 新增监督者步骤，把一句话收成现在的任务 JSON（`verify`、`allow_writes`、`save`、`pie`） | 自动的缺口是「没有人手写 JSON 就进不了环」，不是缺编译器 |
| 人确认 | Cursor 日常改 `Source/` 或蓝图，仍先写 `.cursor/memory/plans/` 等确认。确认之后调用 `run_task.py`，不再由对话模型直接改文件 | `ue-cpp-plan` 的门禁还在。自动指的是确认之后的改、编译、测试、再改 |
| C++ 怎么改 | 继续 `read_source` / `apply_unified_diff`，路径锁在 `Source/AIAgentProject` | 已经能打补丁。不要改成模型整文件覆盖 |
| 编译进程 | 实施时先列 `UnrealEditor-Cmd.exe` 的候选参数并各跑一次干净工程。只有退出码 0 且日志没有 `error C` 的那一条写进 `judge.py`。`-run=Compile` 已失败，计划里不再试第二次 | 用户要求编译走 Cmd。5.8 上这条命令不存在，不能把已知失败写死 |
| Cmd 候选都失败时 | 自动编译保持现在这条已通过的 `Build.bat AIAgentProject Win64 Development -WaitMutex`。Cmd 继续只负责无界面导出。计划在验证表里记「Cmd 不能编译」 | 有一条能编出 `error C` 的命令，比空等一个不存在的 commandlet 有用 |
| Live Coding | 编辑器开着时不编 `AIAgentProjectEditor`。自动编译用游戏目标，除非实测出现能绕过 Live Coding 的 Cmd 参数 | 2026-10-12 已看到 UBT 拒绝编辑器目标 |
| 测试 | 编译 `ok` 之后，任务带了 `automation_filter` 才跑 Automation。没有过滤器则 `editor_assert` 或 skip，和现在一样。无命中过滤器是失败，不是 `failed: 0` | 无命中过滤器会报错。不能靠单词 `passed` 判成功 |
| Cmd 编译 | 保持 `Build.bat`。`-run=Compile` 已知失败，不再试。引擎里没有另一条编译 commandlet。2026-10-12 `Build.bat AIAgentProject Win64 Development -WaitMutex` 退出码 0 | 有一条能编出结果的命令 |
| 检索层数 | 路由 → BM25 与 bge 的 RRF。短名单重打分在 22 条题集上 Recall@5 没有高于纯向量，热路径撤掉 | 漏斗文献里第四层主要加延迟 |
| 题集 | 先有 20 条「问句 → 应当命中的 `source_path`」再谈换模型。没有题集不改 embedding | 上一轮明确不做 Rerank，是因为当时没有题集。这一轮补题集，不补模型 |

未确认就不做：多个模型供应商、Agent 市场、蓝图 Graph 全量导出、Docker、评测网页。

## 6. Proposed Changes

### 6.1 自动闭环（先做）

- **新建** `RAG/ue-rag/agent/supervise.py`  
  输入一句话，输出与 `agent/task_schema.py` 相同的 JSON。`verify` 只能从四种 kind 里选。写不出 `refPath` 或唯一 C++ 路径时返回错误，不猜。
- **修改** `agent/run_task.py`  
  增加 `--query "..."`。内部先 `supervise`，再跑现有图。`--task` 保留，评测仍用固定 JSON，避免监督者漂移把三条基线跑歪。
- **编译探测**（写进 `judge.py` 之前）  
  在终端对干净工程各跑一次，日志只留退出码和最后几行：
  1. `UnrealEditor-Cmd.exe <uproject> -run=Compile`（已知失败，记录即可，不再当候选）
  2. Cmd 的帮助或引擎文档里另外点名的编译 commandlet，若没有则记「无」
  3. 现有 `Build.bat AIAgentProject Win64 Development -WaitMutex`
  写进裁判的只有实测通过的一条。
- **新建** `eval/tasks/cpp-fix-keep.json`  
  与 `cpp-typo` 相同的错误注入，但任务声明 `keep_source: true` 时不还原，并在编译通过后跑 `export_cpp_metadata.py`。默认评测仍还原，避免把试探错误留在工作区。这条任务只在人明确说「留下修改」时跑。
- **修改** `fix` 之后的测试  
  `cpp_build` 通过且任务有 `automation_filter` 时，`test_node` 必须跑 Automation。失败回到 `fix`，带上 `failed` 计数和测试名，不把原文里的 `passed` 当成成功。

Cursor 侧只加一句说明到 `WORKFLOW.md`：人确认计划之后，可以用 `run_task.py --query` 把改、编译、测试交给闭环。未确认不调用。这一步放在自动闭环验收之后。

### 6.2 多 Agent（自动闭环验收之后）

不增加新的图边名字。把 `plan_node` 按任务种类拆开提示和工具：

| 角色 | 何时 | 工具子集 | 不碰 |
| --- | --- | --- | --- |
| 监督者 | `--query` 进入时，一次 | 无编辑器、无 diff。只输出任务 JSON | 不改文件 |
| 检索 | `retrieve` | `search_ue_project`（带 `where`）、`get_project_summary` | 不写 |
| C++ | `verify` 含 `cpp_build` | `read_source`、`apply_unified_diff` | 不调用 MCP 写工具 |
| 编辑器 | `verify` 含 `editor_assert` 或 `blueprint_compile` | `allow_writes` 里的 MCP 工具，加只读的 `find_actors` | 不改 `Source/` |
| 裁判 | `build` / `test` | 无 LLM。只调用 `judge.py` | 不解释成功 |

交接：监督者的 JSON 放进现有 `state["task"]`。trace 增加 `role` 字段。DeepSeek 仍是这些角色的模型，本阶段不换模型。

### 6.3 分层检索（题集先于模型）

- **新建** `RAG/ue-rag/eval/retrieval_questions.json`  
  至少 20 条。每条有 `query`、`expect_source_path` 或 `expect_id`。覆盖类名、资产路径、中文设计稿标题、一条已知 `error C`。
- **新建** `core/retrieve_funnel.py`，`rag_core.retrieve` 改为调用它。三层：

```text
0 路由    专有名词（类名、/Game/、error C）直接 where + 路径精确匹配，命中唯一则停止
1 召回    未停止时：BM25（类名、路径、标题）与现有 bge 各取 top 20，RRF 合并
2 短名单  只对合并后的 top 20 做一次轻量重打分（仍用已加载的 bge，或一个小 cross-encoder）
```

- 工具检索走同一漏斗的 `ue_tools`，卡片仍然不带 `input_schema`。`--schema` 只对漏斗选出的那一个工具调用。
- `plan` 里的技能卡片继续用现成 JSON，不向量化全文。路由已经选了域之后，只在该域的几张卡片里挑最近的一张。
- 两个 `SentenceTransformer` 单例收成一个。这是当前延迟的第一刀，不依赖新模型。
- 验收看题集的 Recall@5 和单次查询耗时，不看「换了更大的模型」。Recall@5 不高于现在的纯向量，就撤掉第 2 层，留下路由和 BM25。

## 7. 实施顺序

1. 编译探测。写死实测通过的那一条。Cmd 全失败则在本文件打勾「保持 Build.bat」，然后才做自动任务。
2. `supervise.py` + `run_task.py --query`。用「修掉 TestActor 的编译错误」这句现成话跑通：出现一次失败裁判、一次 `apply_unified_diff`、结束 `ok: true`、工作区按任务声明还原或保留。
3. 带 `automation_filter` 的任务：编译通过后测试失败能回到 `fix`。过滤器必须是编辑器里真实存在的一条，禁止用无命中过滤器凑 `ok`。
4. 拆角色提示和工具子集。三条旧 JSON 仍由 `eval/run_eval.py` 跑过。
5. 检索题集 20 条，先量现在的 Recall@5 和耗时。
6. 路由 + 共享 embedding + BM25。再量一次。没有提升则不加重排。

## 8. Assumptions

- 实施时编辑器开着，MCP 在 `8000`，Live Coding 仍启用。自动编译不依赖关掉编辑器。
- DeepSeek 仍是 `deepseek-chat`。
- 语料规模维持在「百条到几千条」。若资产全量导出后超过这个量级，再把第 2 层从 bge 重打分换成 cross-encoder，不在本计划里提前换。
- 人没有确认 `.cursor/memory/plans/` 时，监督者不得写 `Source/`。
