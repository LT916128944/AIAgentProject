## 1. 结论

同一句需求今天防的是「两个人读同一份重定向文件」，防不住「两个终端各打一句」和「一个菜单、一个 DSH 同时写编辑器」。活着的 run 只被问一句 Y，放行没有记录。

写策略不要收成同一个 bool。菜单缺省可以保存，DSH 缺文件必须拒绝。要收的是入口：两处都调用同一个函数，函数按剖面返回，第三处不许再手写一套 `allow_writes`。

## 2. 现在实际怎么走

`start.bat` 菜单 3 在重定向之前把 `UE_RAG_STDIN` 改名为 `.consumed`，改名失败就退出。`agent/run_guard.claim_stdin` 用 `os.replace` 做同一件事。进程死在改名之后，`.consumed` 会留下，下一次直接报占用。

`warn_live_runs` 发现 30 分钟内有心跳就返回 2。`start.bat` 看到 2 就 `set /p` 问 Y。Y 不写任何事件。无心跳的 running 由 `sweep_orphan_runs` 改判 orphaned，不杀进程。`eval/check_orphan_run.py` 钉的是 orphan 和第二次 claim 拒绝。

DSH 的编辑器写锁在 `server/dsh_bridge.py` 内部：并发一个成功一个 busy，900 秒无心跳算 stale，伪造 pid 算 stale，只读不占锁。菜单 2 / 菜单 3 不占这把锁。`eval/check_dsh_lock.py` 已进 CI。

`config.task_policy` 给菜单展开 `save` / `pie`，缺省跟随 `UE_DEFAULT_SAVE` / `UE_DEFAULT_PIE`（都是 true）。`server/dsh_bridge.py` 只读 `data/dsh/session_task.json`，文件缺失或读失败时 `allow_writes=[]`、`save=false`、`pie=false`。图写（蓝图、材质、UMG、动画、Niagara）已经走 `core/graph_write_policy.py`，本计划不拆它。

`UE_SOLVER_ENABLED` 的代码缺省是 false。`WORKFLOW.md`「当前系统」写「缺省 false」。`README.md` 写「本机已开」，指的是这台机器的 `.env`。`eval/check_solver_budget.py` 已断言没写环境变量就是关。这不是两个缺省，是「缺省」和「本机」被放在一起比较了。

## 3. 改法

### P1 — 活 run 默认拒绝

`warn_live_runs` 继续只负责发现。`start.bat` 看到返回值 2 时直接退出，退出码 2，打印心跳里的 run_id。不再 `set /p`。

菜单进程要带 `--force` 才允许在有活 run 时继续。放行时在该 run 的事件里写 `run_start.forced_by`，带 pid 和被越过的 run_id。没有 `--force` 就退出，不写事件。

验收加在 `eval/check_orphan_run.py`：临时目录里放一条未过期心跳，不带 `--force` 的入口函数返回 2；带 `--force` 返回 0 且事件文件里有 `forced_by`。

### P2 — 编辑器写锁收成一份

把 `dsh_bridge.py` 里的占锁、判 stale、释放抽到 `core/editor_lock.py`。锁文件仍是现在 DSH 用的那一个路径，不另建 `backend.lock`。锁体增加 `backend`（`config.editor_backend()` 的返回值）、`run_id`、`pid`、心跳时间。

DSH 网关和菜单 2 / 菜单 3 的编辑器写都调用它。只读不占锁，这条保持。第二个写者失败，错误文本带持有者的 pid、backend、run_id。900 秒 stale、伪造 pid 算 stale，这两条保持，`check_dsh_lock.py` 继续绿。

官方后端和 monolith 后端只要都是写，就互相挡住。锁不按后端分成两把。

### P3 — 残留的 `.consumed` 可以回收

`claim_stdin`：目标文件已经不在，只剩 `.consumed`，且没有任何未过期心跳时，把 `.consumed` 交回这次调用并返回 ok。有未过期心跳时仍返回 busy。

验收加在 `check_orphan_run.py`。不改「两个活进程同时改名，只有一个成功」。

### P4 — 一个函数，两套剖面

在 `config.py` 增加 `run_policy(entry, task)`。

- `entry="menu"`：行为等于今天的 `task_policy` 加上调用方已经放进 task 的 `allow_writes`。缺省 save/pie 仍是 true。
- `entry="dsh"`：只认 `session_task.json` 读出来的那份。缺文件仍是全拒绝。模型参数里仍然没有这几个字段。

返回的键集合相同：`allow_writes`、`save`、`pie`。两套剖面的 bool 不必相等。

`dsh_bridge.py` 的读文件改走这个函数。`agent/sequence.py`、`agent/run_windows.py` 里组装执行用 task 的地方改走 `entry="menu"`。`task_policy` 留作薄包装，避免一次改完全部调用点。

验收加在 `eval/check_risk.py`：同一份 task，menu 剖面与今天的 `task_policy` 一致；dsh 剖面在临时空目录下是全拒绝；dsh 剖面不读取 task 参数里的 `allow_writes`。再用 AST 看 `server/dsh_bridge.py` 不再自己拼那三份缺省字典。

### P5 — 求解开关只钉表述

`eval/check_risk.py` 增加三条文本断言，不读模型、不改文档：

1. `agent/solver.py` 在环境变量未设置时返回关。这条若与 `check_solver_budget.py` 重复，就调用同一函数，不复制判断。
2. `AIAgentProject/WORKFLOW.md`「当前系统」那一节含「缺省 false」。
3. `AIAgentProject/README.md` 若出现「本机已开」，则 `RAG/ue-rag/.env` 里 `UE_SOLVER_ENABLED` 必须是 true。`.env` 不存在时，README 不得写「本机已开」。

漂移时打印文件路径和期望句，退出码 1。不调用 `export_project_context.py`，不把求解开关写进 `project_context.json`。
