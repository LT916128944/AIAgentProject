## 升级原则

1. **先修可信度，再扩能力**：合同假通过洞不修，整句 run 的“成功”不可信，功能越多越危险。

2. **每个动作必须声明后端能力**`official` / `monolith` / 只读/写 / 参数形状 / 失败降级，不能运行时猜。

3. **回滚要可验证**：不是“写了 props.json 就算回滚”，要有故障注入测试和幂等逆操作。

4. **95 分要真实证据**：整句 run N 次成功率、故障注入通过率、换机部署时间、CI 时间、回滚成功率。

5. **人工边界要产品化**`patrol-presentation` 不能长期停在“人自己看 Plan/”，要有模板、校验器、人工签证据。
