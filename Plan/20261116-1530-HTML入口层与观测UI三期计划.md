## 0. 三句话结论

1. **入口要做成 DSH 那样，缺的不是样式，是三个契约**：拖进来的路径算「引用」还是「需求」、谁把裁决写回进程、UI 从哪读进度。三个契约今天一个都没有，所以现在做 HTML 只能做「假对话框」。
2. **执行入口仍然必须是 CLI 子进程，不能是进程内调用。** `run_guard` 的活 run 互斥（[`run_guard.py:187`](../../RAG/ue-rag/agent/run_guard.py)）、`UE_RAG_STDIN` 的原子改名占位（`start.bat:95-102`）、`editor_lock` 的跨进程文件锁都长在「一个进程一条 run」这件事上；UI 要做的是**给这个进程喂一行、读它的落盘文件**，不是替它跑。
3. **拖拽能给的只有路径 token，语义得人补一栏。** 因此 UI 必须：给每个附件标角色（关卡/资产/目录/源码/文档）→ **把最终 prompt 原文摆在输入框下面** → 对「多条 `/Game` 路径」「绝对源码路径」这类会被下游静默吞掉的情况当场报错。原型已按这三条做。

### 1.2 缺的（这才是「做不出 DSH 感」的原因）

| 缺什么 | 现场 | 后果 |
| --- | --- | --- |
| **没有「提问」事件** | 人审门与裁决都是 `input()`：`brief_flow` 的 `reader`（[`brief.py:1365`](../../RAG/ue-rag/agent/brief.py)）、`_decide_window`（[`run_windows.py:2685`](../../RAG/ue-rag/agent/run_windows.py)）、`run_multi._decide`。事件里只有 `confirm`——那是**答完之后**写的 | UI 不知道该在什么时候弹按钮；只能靠人肉盯 stdout |
| **没有安全的「追加一行」通道** | 实测：`input()` 读到 EOF 立刻抛 `EOFError`，后追加的行读不到（探针见 §1.4-2） | 想在跑起来之后补一句裁决，今天做不到 |
| **追加行会被当成下一条需求** | `conventions.md` 已记：非交互喂的兜底裁决行若没被暂停消费，会被 REPL 当成下一条需求 | 天真实现会静默跑出**第二条 run** |
| **路径没有「引用」语义** | `_intent_query_paths`（[`plan_windows.py:1113`](../../RAG/ue-rag/agent/plan_windows.py)）只取**唯一**一条 `/Game`；`_clause_rows`（`:1655`）只按 `，,；;。` 切 | 两条路径静默失效；换行粘的路径与主句合成一条半句 |
| **源码路径必须相对** | `resolve_source`（[`core/source_edit.py:13`](../../RAG/ue-rag/core/source_edit.py)）拒绝绝对路径与 `..` | 拖一个绝对路径进去，`read_source` 直接 `path refused` |
| **关卡槽位不挑路径** | 实测 `resolve_level("/Game/Blueprints/BP_TestActor")` 返回 `ok=True`（把蓝图路径当关卡名） | 把任意 `/Game` 路径当「关卡提示」会静默改语义 |

### 1.4 本次实测（六条，都会影响设计）

1. **`start.bat` 的 `--force` 在菜单 2/3 里失效。** `:multi` 写的是 `call :warn_live_runs`（`start.bat:77`），子程序里 `%~2` 为空 ⇒ `if /I "%~2"=="--force" exit /b 0`（`:124`）永不成立。复制一份 start.bat 打桩实测：`3 --force` → **退出 2**；改 `:warn_live_runs` 判 `FORCE_ARG` 后 → `3 --force` 退 0、`3` 退 2、无参菜单退 2。**这是 UI 三期要依赖的口子，得先修。**
2. **`input()` 到 EOF 立刻抛错，追加行读不到。** 同一份脚本：纯 `input()` → `[1] EOFError`；换成「EOF 后 6 秒 idle 重试」的 stdin 包装 → 先后读到 `c` 与 `/Game/Maps/L_NewTest3`。**「跑起来之后还能补一句」必须走这个包装，或改成文件收件箱。**
3. **`chcp 65001` + 重定向 stdin 会丢已缓冲输入。** 探针里 `chcp` 之后 `readline()` 全是 `''`。`start.bat:3` 已经跳过 chcp，UI 走文件重定向时同样不许 chcp。
4. **`_clause_rows` 不按换行切半句。** `A需求\n\n/Game/Maps/L_NewTest3` 是**一条**半句；`A需求。/Game/Maps/L_NewTest3` 是两条。且附件那条是否被判 `covered` 取决于命中哪套规则（实测：`hud-rules` 下 `/Game/UI` 是 covered；`edit_cpp` 下 `Public/FpsPawn.h` 是 uncovered；`place_blueprint` 下 `/Game/Blueprints` 是 covered）。**结论：附件不能靠「运气 covered」，必须有一条专门的路径半句规则。**
5. **`_intent_query_paths` 有唯一性闸门。** 一条 `/Game` 路径 → 返回它；两条 → 返回 `[]`（不报错）。所以「同时拖 2 个资产」今天等于**两个都不生效**。
6. **无 tty 时 rich 走非终端分支。** `Console().is_terminal=False`；`board` 的 E 键线程依赖 `msvcrt.kbhit()`（[`board.py:280-283`](../../RAG/ue-rag/agent/board.py)）。`start.bat:105` 的 stdin 路径已经写死 `--plain`——**UI 驱动也必须是 `--plain`，画面从文件读。**

## 2. 我的判断（有取舍的地方直接说）

| 议题 | 我的选择 | 理由 / 反对的选项 |
| --- | --- | --- |
| 壳的形态 | 本地 `127.0.0.1` + 系统浏览器；不套 Electron / WebView2 | 零构建、零依赖、与 DSH 同源；套壳只会多一层「谁拥有窗口」的问题。本机已装 Edge 157 + WebView2，需要再议 |
| 执行方式 | **子进程**跑 `start.bat` / `run_windows.py`，UI 只喂一行、只读文件 | 反对「进程内直接 `from agent...`」：写锁、心跳、stdin 占位、退出码 2 全在一进程一 run 的假设上，进程内调等于把互斥重做一遍 |
| 观测与驱动 | **两个模块，共用一份投影**：`observer`（只读，无写路径）+ `entry`（唯一写入 = 子进程 stdin 一行 / 收件箱一行） | 反对「一个模块两件事」：会让「证据只从落盘文件读」这条原则在代码里失去形状 |
| 端口 | 单进程 **8011**（1410 §4.1 的 observer 并进来）；8010 是 `gateway.py` 与 `check_scorecard.HEALTH_PORT` | 两个进程读同一批文件只会多一处漂移点；真要拆，拆线就是「有没有写」 |
| 侧边栏范围 | 只读，根 = `UE_PROJECT_DIR`，屏蔽 `Binaries / Intermediate / Saved / DerivedDataCache / .vs`（铁律 2） | 不做重命名/删除/新建；文件写只能经 `apply_unified_diff` |
| 拖拽 | 从侧边栏拖 = 带完整路径；从资源管理器拖 = **只有文件名**，当场标「外部文件（拿不到路径）」 | 浏览器安全模型给不了 `File.path`。可以用 `showDirectoryPicker` 补，但那是权限弹窗 + 非标准，先不做 |
| 附件语义 | 每个附件必须带**角色**，默认按路径猜，人可改；**不猜的一律不塞进 prompt** | 见 §1.2 最后两行：路径一旦进句子就会改拆句结果 |
| 装配预览 | 输入框下方常驻等宽预览，显示**将要交给 CLI 的原文**，可复制 | 反对「黑盒发送」：下游有 3 个静默失效点（多路径、绝对源码、文件名），必须让人看见 |
| 决策通道 | 三期做「收件箱文件 + `--ui-inbox`」，**不做「往 stdin 追加行」当主路径** | 追加行有两个坑：读到 EOF 就停（§1.4-2）、补一句若没被消费就变成新需求。收件箱天然是「一问一行、可追溯」 |

## 3. 三层结构

```
┌─ 浏览器 127.0.0.1:8011 ───────────────────────────────┐
│ 侧边栏(只读树)   对话框(输入框+附件chip+装配预览)   运行面板(卡片/边/gauge) │
└───────────────┬──────────────────┬────────────────────┘
                │ GET 投影          │ POST 驱动（唯一写）
┌───────────────▼──────────────────▼────────────────────┐
│ server/entry.py  （只 import config/core/server）      │
│  ├ 投影：读 data/runs/**, data/events/*.jsonl, handoffs │
│  ├ 装配：prompt_builder.build()  ← 纯函数，无 IO        │
│  └ 驱动：subprocess(start.bat|run_windows --plain)      │
└───────────────┬───────────────────────────────────────┘
                │ stdin 文件 / inbox 文件 / 退出码
┌───────────────▼───────────────────────────────────────┐
│ run_windows.py（原样保留一进程一 run、写锁、心跳、退码 2）│
└───────────────────────────────────────────────────────┘
```

**三条不许破的线**（写进 `server/entry.py` 的 docstring，并配静态断言）：

1. 投影只读文件，不 import `agent`，不碰编辑器，不调用模型。
2. 驱动只有一个写面：写请求文件（`data/ui/req/<ts>.txt`）与收件箱行（`data/ui/inbox/<run_id>.jsonl`，三期）。
3. UI 的「进度」全部来自落盘文件；stdout 只当人类可读日志展示，**不解析成状态**。

### 4.2 侧边栏

- 树节点：目录（可折叠）/ 文件。只读，双击 = 展开或预览路径，拖 = 生成附件。
- 搜索框按名过滤（不做内容检索；内容检索走 `search_ue_project`，不重复造）。
- 扩展名决定默认角色：`.umap`→关卡，`.uasset`→资产（`WBP_*` 仍按资产），`.h/.cpp/.cs`→源码，`.md/.json/.txt`→文档，目录→目录。
- 目录太大时按需展开（`GET /api/tree?path=...`），**一次只回一层**，不递归整棵树（铁律 2 的同类约束）。

### 4.3 附件 chip

每个 chip 显示：路径尾段 + 角色下拉 + 归一化后的 token（悬停看全文）+ 删除。

| 角色 | 归一化 | 进 prompt 的方式 | 为什么 |
| --- | --- | --- | --- |
| 关卡 | `Content\Maps\L_NewTest3.umap` → `/Game/Maps/L_NewTest3` | 若句子里没点名，追加 `。参考关卡：/Game/Maps/L_NewTest3` | `resolve_level` 认这条 |
| 资产 | `.uasset` 去扩展名 → `/Game/UI/WBP_HUD` | 追加 `。参考资产：<path>`；**同一次最多一条**，多则报错 | `_intent_query_paths` 只认唯一一条（§1.4-5） |
| 目录 | `Content\UI` → `/Game/UI` | 同上，作**唯一**目录提示 | 同上；且它是 `link_asset` 的 folder hint |
| 源码 | `Source\AIAgentProject\Public\FpsPawn.h` → `Public/FpsPawn.h` | 追加 `。参考文件：Public/FpsPawn.h` | `resolve_source` 只收相对路径（§1.2） |
| 文档 | 相对 `UE_PROJECT_DIR` → `documents/harness/boundaries.md` | 追加 `。参考文档：<rel>` | 纯上下文，不参与落点 |
| 外部文件 | 只有文件名 | **不塞进 prompt**，列出「需手工补路径」 | 拿到的是假路径，塞进去只会误导 |

### 4.4 装配预览与告警

预览下方固定一块「装配说明」，逐行说清这段字从哪来，并按严重度给三类提示：

- **红（不许发送）**：附件里有 2 条以上 `/Game` 路径；源码附件是绝对路径；附件 token 含中文或空格。
- **黄（能发但要人看一眼）**：`<script>` 类 `resolve_level` 会接受任意 `/Game` 路径；句子里已经有 `/Game` 且与附件不同；附件来自外部文件（只有文件名）；句子为空只有附件。
- **灰（信息）**：本次将走的那条通道（非交互 stdin 文件 / 常驻 REPL）、`--force` 是否带上、预计退出码含义。

### 4.5 运行面板

沿用 1410 §5/§6 的卡片与连线口径（字段全部有出处，没有的字段不画）：

- 顶栏 gauge：`并发 x/max`、`写锁 Wn`／**没有 `editor_gate` 事件时显示「写锁 —」，不显示「空闲」**、`队列 n`（`queue_ms>0`）、`完成 a/b`、`停因`。
- 卡片：状态徽标 + `attempt/(max_retries+1)` + 秒表（有 `started_at` 才走，历史 run 只显示 `elapsed`）+ `↓未完成 N/M` + `↑下一扇`。
- 连线四分支按相对位置选接点（1410 §6 原样），不引前端框架。
- 点卡片 = 该扇 `data/runs/.../<run_id>.cli.jsonl` 的尾部；**这只是日志，不是状态**。

### 4.6 决策面板（三期才有真数据）

- 只有出现 `question` 事件时弹出，带 `kind`（`brief` / `decide` / `filter`）、`prompt` 原文、`options`。
- 按钮文案与 CLI 逐字对齐：`确认`、`确认缺口`（`brief.GAP_ACK_PHRASE`，[`brief.py:287`](../../RAG/ue-rag/agent/brief.py)）、`放弃`、`c 跳过`、`s 停止`、`r <路径>`。
- 每次点击在按钮下方显示**将要写入的那一行原文**（一句话，逐字），并可撤回（撤回 = 不写）。
- **不做**「取消正在跑的扇」「中途改任务书」：那是第二个裁决入口（1410 §8-7 保持有效）。

## 5. 提示词装配规范（本计划的硬核心）

六条规则，每条都能被离线断言钉住：

| # | 规则 | 依据 | 断言 |
| --- | --- | --- | --- |
| A1 | **人的原句一字不动放最前**，不 trim 内部空白、不改标点 | `_clause_rows` 按 `，,；;。` 切分，改标点等于改拆句 | 输入 == 输出前缀 |
| A2 | 附件一律 `。` 开头、自成一句、顺序 = chip 顺序 | 换行不切半句（§1.4-4），`。` 才切 | 每个附件恰好产生一条半句 |
| A3 | 每条附件句必须被 `_clause_accounted` 认成「引用」而不是新需求 | 见下 A3 的落地改动 | `eval/check_entry_paths.py`：带/不带附件的 `planned.source` 与扇数相同 |
| A4 | `/Game` 路径**全篇最多一条** | `_intent_query_paths`（§1.4-5） | 装配器返回 `warnings` 含 `multi_game_path` 时 `ok=False` |
| A5 | 源码/文档路径一律相对（源码相对 `UE_SOURCE_ROOT`，文档相对 `UE_PROJECT_DIR`） | `resolve_source` 拒绝绝对路径（§1.2） | 绝对路径 ⇒ `ok=False` |

**A3 需要的落地改动（唯一一处 agent 侧改动，二期做）**：

`_clause_rows`（`plan_windows.py:1655`）今天对一条纯路径半句只能靠「刚好被某套规则认领」才 `covered`。加一条与现有「`别/不要/无需/不用` 算 constraint」同形状的判定：

```python
# 纯路径半句是引用，不是新需求。与下面「别/不要」那条同一个形状：
# 它不是要执行的东西，而是给归地的一条提示。
if _is_reference_clause(clause):
    rows.append({"clause": clause, "status": "constraint"})
    continue
```

`_is_reference_clause` 只认三种形状（不猜别的）：
- 整条（去掉 `参考关卡|参考资产|参考路径|参考文件|参考文档|路径|文件|目录|资产|源码` 前缀与空白后）是 `/Game(/[A-Za-z0-9_]+)+`
- 或 `Public|Private/<名字>.h|cpp`
- 或 `documents/<...>`

**为什么必须加**：不加的话，UI 的「拖一个源码文件」会让原本强命中的规则链变成 `uncovered` → 掉进理解器（多一次模型调用，且可能改变落点）。实测证据：`edit_cpp` 规则下 `Public/FpsPawn.h` 是 `uncovered`，而同一形状的 `/Game/Blueprints` 在 `place_blueprint` 下是 `covered`——**结论依赖运气，不能进产品**。

**第 3 期踩到并修掉的真缺陷（1 个，真机才发现）**
