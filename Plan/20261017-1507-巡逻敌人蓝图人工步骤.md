# 巡逻敌人蓝图人工步骤

C++ 半边是 `UTestEnemyPatrolComponent` 和 `ATestEnemy`。组件绕出生点巡逻，发现玩家后追击，近距离调用 `OnMeleeAttack`。行为树、动画、受击表现由人绑。本文不改图。

## 人绑

1. 打开 `BP_TestEnemy` 的事件图。父类是 `ATestEnemy`，组件是 `UTestEnemyPatrolComponent`。
2. 从组件事件 `OnPatrol` 的白色执行引脚接到巡逻表现。不要在这里写追击或伤害。
3. 从组件事件 `OnChase` 的白色执行引脚接到追击表现。发现距离看组件上的 `DetectRadius`。
4. 从组件事件 `OnMeleeAttack` 的白色执行引脚接到近战表现。这个事件不造成伤害，不播动画，次数在 `MeleeAttackCount`。
5. 行为树、动画蓝图、受击受击盒由人在编辑器里接。闭环不自动绑。

## 只读核对

- `StartPatrol` 之后应进入巡逻。`bEnableChase` 为真且玩家进入 `DetectRadius` 后应追击。
- 距离进入 `AttackRange` 后 `MeleeAttackCount` 增加，间隔不短于 `AttackInterval`。
- 编译看 `cpp_build`。蓝图只编译已有资产，不改 Graph。
- 不保存关卡，不 PIE，除非这句话单独要求。

## 不做

- 不自动连接行为树、动画通知、受击判定。
- 不按类名凭空生成实例。场景里没有敌人时，放置扇单独失败。

## 2026-10-27 复核附录（U2）

- `AIAgent.Enemy.Patrol` automation 实测 1 passed / 0 failed（monolith `editor.run_automation_tests` 只读跑）。这个测试在临时世界里直接驱动 `UTestEnemyPatrolComponent::TickComponent`，只验 C++ 半边（巡逻位移/追击距离/近战次数），不经过蓝图——所以它绿了不代表表现接好了。
- `ATestEnemy` 的行为是完整 C++ 状态机（`TickPatrol`/`TickChase`/`TickAttack`），**不需要也不会跑行为树**。monolith `ai` 命名空间有全套 BT 作者面（160 个 action，见 `ue_mcp_verified.json`），但给这个敌人建 BT 是装饰品，没有建。
- monolith 蓝图词表（`add_node`/`resolve_node` 干跑实测）没有「覆写组件 BlueprintImplementableEvent」的节点类型：CustomEvent 会新建同名自定义事件而不是覆写，`ComponentBoundEvent` 只管 multicast 委托。三个事件的表现接线维持人工，仍是本文上面那四步。
- 动画一条对现在的 `ATestEnemy` 不适用（Actor，无骨架无网格动画）；受击表现要等伤害链路（`ApplyAttack` 已有，伤害数字/特效未做）。
