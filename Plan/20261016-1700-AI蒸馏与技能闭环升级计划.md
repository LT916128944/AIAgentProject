# AI 蒸馏与技能闭环升级计划（查漏补缺版）

日期：2026-10-16  
范围：RAG/ue-rag + AIAgentProject  
目标：在保留现有裁判、闸门、人审门、可续接和只读并行的前提下，把 L3 从“学句式”升级为“学技能”，把工程记忆升级为跨会话策略记忆，把失败、澄清、人工修正变成可蒸馏信号。

## 0. 这份计划怎么用

本计划里的“蒸馏”是广义蒸馏：

- 教师：强模型 / 现有 `UE_LLM_MODEL` / 人工修正 / 成功 run / 失败修复轨迹。
- 学生：`learned_skills.json`、`failure_patterns.json`、`clarify_policy.json`、`intent_examples.jsonl`。
- 蒸馏产物不直接进执行链，先 shadow，再回放，再人工审，再提升。
- 不换供应商，不改 `base_url`，不把 `--query` 接成 Cursor 每句话默认动作。
- 不自动保存关卡，不 PIE，不改蓝图 Graph，除非对应 `UE_ALLOW_*` 为 `true`。
- 模型不能自己宣布成功，裁判仍以 `cpp_build`、`blueprint_compile`、`editor_assert`、`automation` 为准。

## 1. 判断摘要

你的系统强在：

- 裁判闭环：编译、蓝图编译、坐标断言、Automation 都有硬验收。
- 工程安全：路径不唯一就停，动作表外暂停，不猜路径。
- 可观测：事件流、机读 run、归档、台账、面板、快照、续接。
- 人审门：任务书、范围、未完成清单、依赖、估时、确认/编辑/放弃。
- 垂直深度：UE 5.8、C++ 补丁、MCP、编辑器闸门、拾取裁决、巡逻敌人 C++ 半边。
- 成本控制：技能卡片不带 schema，理解器 1KB 上下，L0 零模型，角色上下文切片。

与 Hermes 类通用自主智能体相比，差距在：

- 学习对象太窄：`learned_routes.json` 学的是句式，不是技能。
- 失败学习偏手工：`历史解决方案.md`、`排障条目.md` 要人写、人导出。
- 记忆分散：run、event、archive、ledger、checkpoint、任务记录、历史方案各一套。
- 自主性弱：路径不唯一就停，动作表固定，人审门多。
- 索引一致性靠人：新建蓝图只提示 `index_stale`，不自动 `asset.bat`。
- 菜单 2 未接理解器：单循环仍是纯手写规则。
- 端到端未完成：巡逻敌人行为树、动画、受击仍由人绑。

所以升级方向不是拆掉闸门，而是：

> 在闸门内蒸馏，在裁判后学习，在回放中验证，在人工确认后提升。

## 2. 目标与非目标

### 目标

1. 建立蒸馏数据契约：把 run、event、trace、diff、裁判、`r` 补路径、人工编辑变成结构化样本。
2. 把 `learned_routes.json` 升级为 `learned_skills.json`，兼容旧路由。
3. 建立失败模式蒸馏：从 `fix` 成功轨迹提取“症状 → 原因 → 工具序列 → 验证”。
4. 建立澄清策略蒸馏：从人工 `r` 补路径中学习“缺哪个槽、问什么、接受什么格式”。
5. 自动索引一致性：新建蓝图后排队 `asset.bat`，编辑器关闭时自动执行或提示可执行。
6. 动作目录插件化：允许候选动作经人审后入表，不直接执行表外动作。
7. 菜单 2 接理解器：保留手写规则为 L0 种子，弱命中/未命中走 L1/L2。
8. 任务书长期目标：从 `ledger` 和未完成技能自动生成“尚未完成清单”。
9. 端到端巡逻敌人：C++ 半边闭环 + 蓝图人工步骤 + 只读裁决 + 编译测试。
10. 防退化评测：`check_distill.py`、回放、A/B、影子模式、版本化、可回滚。

### 非目标

- 不自动绑行为树、动画、受击表现。
- 不自动改蓝图 Graph，除非 `UE_ALLOW_BLUEPRINT=true`。
- 不自动保存关卡，不自动 PIE。
- 不换模型供应商，不改 `base_url`。
- 不让模型自己宣布成功。
- 不把 800 多个 schema 拉进对话。
- 不把 `--query` 设成 Cursor 每句话默认动作。

## 6. 分阶段计划

### P0 数据契约与影子蒸馏（1–2 天）

产物：

- `data/distill/` 目录。
- `agent/distill.py`：只读 run/event/trace，输出候选，不执行。
- 事件流新增：`distill_candidate`、`skill_promoted`、`skill_rejected`。
- `eval/check_distill.py`：离线检查数据契约。

验收：

```powershell
python agent/distill.py --dry-run
python eval/check_distill.py
```

打印 `distill ok`，不调用真实模型，不写场景。

### P1 从 learned_routes 到 learned_skills（3–5 天）

动作：

- 新文件 `data/skills/learned_skills.json`。
- 兼容读旧 `learned_routes.json`。
- `SkillMemory` 字段：
  `id`、`version`、`when`、`roles`、`goals`、`preconditions`、`action_sequence`、`verification`、`failure_recovery`、`confidence`、`source_runs`、`conflicts`、`lru`。
- `plan_sequence` 和 `plan_windows` 先读 `learned_skills`，再读旧路由。
- 整句集成成功且 `unresolved` 为空才提升；失败恢复需至少 2 次裁判成功。

验收：

- 旧 `learned_routes.json` 仍可读。
- 同构句子零模型命中率不降。
- `check_routes.py` 仍打印 `routes ok`。

### P2 失败模式蒸馏（3–5 天）

动作：

- 新文件 `agent/failure_memory.py`、`data/skills/failure_patterns.json`。
- 从 `fix` 成功轨迹提取：
  `symptom`、`error_kind`、`root_cause`、`fix_tools`、`validation`、`confidence`、`source_runs`。
- `fix` 先查 `failure_patterns.json`，再查 `ue_error`。
- 不编造历史，标题对不上不用。

验收：

- 同类 `error C` 重试次数下降。
- `cpp-typo` 仍通过，还原逻辑不变。
- 失败任务不入库，不编造改法。

### P3 澄清策略蒸馏（2–3 天）

动作：

- 新文件 `agent/clarify_policy.py`、`data/skills/clarify_policy.json`。
- 从人工 `r /Game/...`、`r Public/类名.h` 提取：
  `missing_slot`、`question_template`、`accepted_forms`、`resolution`、`confidence`。
- `grounding.py` 推不出时只问一次 `r`，问题模板从策略库选。
- 路径仍要唯一，不猜。

验收：

- 人工 `r` 次数下降。
- `ATestActor` 的 `BP_TestActor` 缺路径仍会暂停。
- 不按类凭空生成实例。

### P4 自动索引一致性（2–4 天）

动作：

- 新建蓝图资产的 run 收尾写 `index_stale` + `index_hint`。
- 新增 `index_auto_refresh` 事件。
- 编辑器关闭时自动排队 `shortcuts\asset.bat`；编辑器开着时提示人执行。
- 续接不重复提示。
- L2 归地 `linked` 分支检查索引新鲜度。

验收：

- 新建蓝图后索引可刷新。
- `index_stale` 不再只靠人记。
- 不自动关编辑器，除非任务本来要编译。

### P5 动作目录插件化（3–5 天）

动作：

- `agent/catalog.py` 支持注册、版本、冲突、人审状态。
- L1 可以提出新动作候选，但表外动作不执行、不写快路径。
- 候选动作经人审 + 回放 + 裁判后入表。
- 事件流记录 `action_candidate`、`action_promoted`。

验收：

- 表外动作仍暂停。
- 入表动作有 `version`、`conflicts`、`verification`。
- 不把候选动作直接交给执行器。

### P6 菜单 2 接理解器（3–5 天）

动作：

- `plan_sequence` 保留手写规则为 L0 种子。
- 弱命中/未命中走 `understand.py` → `intent.py` → `grounding.py`。
- L1 失败才回退老规划者，重试上限 1 次。
- 菜单 2 和菜单 3 共用动作表、检索库、编辑器执行器。

验收：

- “编译工程后启动编辑器，然后测试 ATestActor 能否被 ATestPawn 拾取”仍走通。
- 单循环可理解句增加。
- 路径不唯一仍暂停。

### P7 任务书与长期目标闭环（2–4 天）

动作：

- `brief.py` 从 `ledger.json` + 未完成技能 + `unresolved` 生成“尚未完成的全部主要内容”。
- 范围窗口按 id 或唯一动作原样继承快路径候选。
- 确认后追加 `integrate_verify`。
- 失败扇无下游依赖时整句记“部分完成”。

验收：

- 任务书能列“A 完成；B 失败”。
- 台账范围级 `done / partial / pending` 可回写。
- 人不审不执行。

### P8 端到端巡逻敌人（5–10 天）

动作：

- C++ 半边：`UTestEnemyPatrolComponent`、`ATestEnemy`。
- 三个事件：`BlueprintImplementableEvent`。
- 一句话目标：生成会巡逻、发现玩家后追击、近距离攻击的敌人。
- 行为树、动画、受击表现由人绑。
- 只读裁决 + 编译 + 测试 + 人工步骤生成。

验收：

- C++ 编译通过。
- 巡逻读数画面与 trace 对得上。
- 蓝图人工步骤写入 `Plan/`。
- 不承诺自动绑图。

### P9 防退化与 A/B（3–5 天）

动作：

- `eval/check_distill.py` 覆盖：
  数据契约、技能提升、失败模式、澄清策略、索引刷新、动作候选、菜单 2 理解、任务书长期目标。
- 回放历史 run：候选技能应产生相同或更好结果。
- 影子模式：候选只记录建议，不执行。
- A/B：旧 `learned_routes` vs 新 `learned_skills`。
- 置信度阈值、版本化、冲突检测、可回滚。

验收：

```powershell
python eval/check_routes.py
python eval/check_upgrade.py
python eval/check_distill.py
```

通过时打印 `routes ok`、`upgrade ok`、`distill ok`。

## 7. 蒸馏管线详细设计

### 输入

- `data/events/<run_id>.jsonl`
- `data/runs/YYYYMMDD/<run_id>.json`
- `data/archive/<run_id>/`
- `data/traces/*.jsonl`
- `data/ledger.json`
- `learned_routes.json`
- `.cursor/memory/任务记录/`
- `documents/历史解决方案.md`
- `documents/排障条目.md`
- 人工 `r` 输入、任务书编辑、`s/c/r` 裁决。

### 清洗

- 去重：按错误原文 sha1、意图 JSON sha1、动作序列 sha1。
- 脱敏：密钥、用户名、绝对路径本机段。
- 分类：成功 / 失败 / 纠正 / 暂停 / 拒绝 / 人工编辑。
- 过滤：`unresolved` 非空的整句不回写成强技能。

### 标注

- 意图：动作名、槽位原始 token、参数、constraints、unresolved。
- 动作序列：窗口、依赖、工具、裁判、工件。
- 失败：症状、错误 kind、根因、修复工具、验证。
- 澄清：缺槽、问题、接受格式、解析结果。
- 技能：when + roles + goals + preconditions + action_sequence + verification + failure_recovery。

### 教师蒸馏

- 输入：脱敏后的 run 摘要 + 意图 JSON + 动作序列 + 裁判结果 + 人工 `r` + diff + 错误原文。
- 输出：候选 `SkillMemory`、`FailurePattern`、`ClarificationPolicy`、`IntentExample`。
- 约束：只从动作目录选动作，不编路径，不编工具名。
- 默认使用现有 `UE_LLM_MODEL`，不替换在线供应商配置。

### 回写

- `learned_skills.json`：正式技能，LRU 上限可调，默认 50 → 200。
- `failure_patterns.json`：失败恢复，按错误 kind 分桶。
- `clarify_policy.json`：澄清策略，按 missing_slot 分桶。
- `intent_examples.jsonl`：意图样本，供后续小模型或提示选择。
- 旧 `learned_routes.json` 保留只读兼容，不再新增。

## 9. 安全闸门与防退化

- 影子模式：候选只写 `data/distill/candidates.jsonl`，不执行。
- 回放：用历史 run 回放，候选应产生相同或更好结果。
- 人工审：动作候选、技能提升、失败模式提升都要人确认。
- 置信度：成功 + 裁判 ok + 无 unresolved 才强提升；失败恢复需至少 2 次成功。
- 版本化：`version`、`supersedes`、`conflicts`。
- 可回滚：保留旧技能，删 `learned_skills.json` 条目即可作废。
- 不猜路径：路径唯一命中才直连，推不出只问一次 `r`。
- 模型不宣布成功：裁判仍以 `cpp_build`、`blueprint_compile`、`editor_assert`、`automation` 为准。
- 不自动保存关卡，不 PIE，不改蓝图 Graph，除非开关为 `true`。

## 10. 验收指标

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 同构句子零模型命中率 | 有 `learned_routes` | ↑ 20% |
| L1 调用次数 | 弱命中/未命中 | ↓ 30% |
| 人工 `r` 次数 | 缺路径时一次 | ↓ 30% |
| 同类错误重试次数 | 依赖 fix | ↓ 20% |
| 编译/测试一次通过率 | 窄闭环通过 | ↑ |

## 11. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 蒸馏噪声固化错误 | 影子模式 + 回放 + 人工审 + 裁判验证 |
| 过拟合固定任务 | A/B + 新句回放 + 不只看同构句 |
| 技能冲突 | `conflicts` 字段 + 版本化 + 人审 |
| 索引过期 | P4 自动刷新 + `index_hint` |
| token 成本反弹 | L0 优先，理解器 1KB 上下，角色切片 |
| 人工审瓶颈 | 先只提升高置信候选，低置信只记录 |
| 跨机器路径泄漏 | 脱敏，路径只存相对或变量 |
| 动作表膨胀 | 插件化 + 版本 + 冲突 + 人审 |
| 蓝图自动改图失败 | 保持 `UE_ALLOW_BLUEPRINT=false` 默认，人工步骤 |

回滚：

- 删 `learned_skills.json` 单条。
- 恢复 `learned_routes.json` 只读兼容。
- `catalog.py` 动作可禁用。
- `failure_patterns.json` 可清空。
- `clarify_policy.json` 可回退到默认问一次 `r`。
