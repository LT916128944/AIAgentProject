## 1. Summary

Monolith 已经是本机编辑器后端，但蓝图仍然按写死的资产名和「表里没有就不执行」在调用之前停住。下一轮去掉这些预先判死的硬编码。`UE_EDITOR_BACKEND=monolith` 时，没见过的蓝图先走 Monolith 试修复。同一目标最多 3 次。第 3 次仍失败就止损：Monolith 不具备这个能力，不再重试，不改连官方 8000，不换成另一张蓝图。

## 3. 已确认决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 什么叫死板 | 调用 Monolith 之前，用资产白名单、`不猜`、`unplannable` 把蓝图窗判成零窗口或暂停 | 用户要的是没处理过的蓝图先试 MCP，而不是再写一份人工步骤 |
| 尝试次数 | 同一张蓝图、同一个目标，最多 3 次修复 | 超过 3 次说明 Monolith 本身做不到，及时止损 |
| 一次尝试算什么 | `describe` 若需要则紧挨着同一次 `exec`，然后做一次编译或只读复查。这一串算 1 次。`discover` 只在还不知道 action 名时发生，并算在这一次里 | 3 次是 3 次修复，不是 3 次查 schema，也不是每个工具各 3 次 |
| 成功 | 该次复查通过就停，不再用满 3 次 | 避免多改 |
| 第 3 次仍失败 | 窗口 `ok: false`。`error` 含「已尝试 3 次，Monolith 不具备该能力」和最后一次错误原文。不第 4 次 | 止损 |
| 止损之后 | 不改连 `8000`。不换另一张蓝图。不把失败改写成待办。不新写一份人工连线 `Plan/` 当作完成。依赖这扇的窗口不跑 | 失败要可见，不能静默换成另一条路径 |
| 开关是 false | `UE_ALLOW_BLUEPRINT`（以及材质 / UMG / 动画 / Niagara 各自的开关）为 false 时立刻拒绝，次数记 0 | 这是人关的写许可，不是试了 3 次仍不会 |
| 解析不出资产 | 0 个或多个同名资产算一次失败，中间不暂停问人 | 「不猜」改成计入 3 次，而不是改成随便挑一个 |
| 后端 | 只在 `UE_EDITOR_BACKEND=monolith` 走这 3 次。`official` 保持现在的拒绝和原路径 | 排他后端计划不在本轮推翻 |
| 不改谁 | `backends/select.py`、`backends/monolith.py` 的拒绝文案、PCG「无此命名空间」、`.env`、游戏 C++ | 止损不能变成第二套编辑器 |

## 4. Proposed Changes

下一轮按这个顺序改。

1. **`agent/run_windows.py`** — `_run_window` 里蓝图和图动作的 `attempts` 改为 3，去掉 `GRAPH_ACTIONS` 的 `attempts = 1`。第 3 次失败的 `summary` / `error` 使用第 3 节的止损句。依赖未成功窗口的后续窗口维持现在的「依赖没完成就不跑」。
2. **`agent/plan_windows.py`** — 删掉这三处预先判死：
   - `create_widget_blueprint` 的「只新建 `/Game/UI/WBP_HUD`」
   - `edit_widget_blueprint` 写死的 `WBP_HUD` 路径
   - `bind_blueprint` / `compile_blueprint` 的「没有唯一蓝图路径，不猜」作为最终状态  
   句子里已有 `/Game/...` 或唯一 `BP_` / `WBP_` 名，就放进槽位并标成可执行。没有唯一名字的，窗口仍然可执行，把解析留给执行层的 3 次尝试。`UE_ALLOW_*` 为 false 时仍 `waiting_external`，不发尝试。
3. **`data/skills/lexicon.json`** — 蓝图、控件图、材质图、动画蓝图、Niagara 图，以及会因此被零窗口截住的「输入 / 开火 / FPS / 空白关卡」行：去掉「命中即不执行」。可以留下动词到建议命名空间的注释（`blueprint`、`ui`、`input`、`mesh`），但 `unplannable: true` 不再让 `materialize` 产出空窗口。非蓝图的编译工程、移动 Actor 等已经有动作的行不动。
4. **`agent/sequence.py` 与 `agent/catalog.py`** — 蓝图修复窗口走 Monolith `exec`，不走官方 `exec_tool`。一次尝试内的调用顺序：还不知道 action 才 `discover`，然后 `describe` 一个 action，然后 `exec`，然后编译或只读复查。失败把 Monolith 的 `error` 原文留在该次记录里。`compile_project`、`edit_cpp` 不进入这 3 次计数。
5. **技能正文** — `ue-manual-blueprint-skill`：`UE_ALLOW_BLUEPRINT=true` 且后端是 monolith 时，不写人工连线清单来代替执行。false 时仍不调用写图工具。`.codex/skills` 与 `.cursor/skills` 两份一起改。
6. **评测** — 改掉断言「只许 `WBP_HUD`」「没有唯一路径就永久不猜」「FPS 句必须零窗口」的用例。新评测用假的 `backends.monolith.exec`，不连 9316，覆盖下面四条。

## 5. Assumptions

- 本机 `.env` 继续是 `UE_EDITOR_BACKEND=monolith`，且 `UE_ALLOW_BLUEPRINT=true`。下一轮不改这份文件。
- 「修复」指让这张蓝图达到该窗口自己的复查（编译通过，或句子点名的那一个读数）。不是在 3 次里自由发挥一整套未点名的玩法。句子仍然可以同时包含建关卡；建关卡不占用蓝图的 3 次。
- 若下一轮发现某条评测把「零窗口能力缺口」当成全系统的不变量、而不只是蓝图硬编码，停在那一条，不要为了通过测试把止损改回零窗口。

若要否定「解析不出唯一资产也算一次失败、中间不问人」，下一轮先停，不要改成自动挑第一个同名资产。
