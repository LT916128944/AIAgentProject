# 20261117-1612 — 蓝图（Blueprint 图）域兜住升级计划

- 日期：2026-11-17 16:12 · 状态：计划
- 母文件：[`20261117-1610-UE5全域模型脚本边界总览.md`](20261117-1610-UE5全域模型脚本边界总览.md)
- 相关：`agent/sequence.py`（`_run_action`/`bind_blueprint`/graph）、`agent/plan_windows.py`（`_build_graph_task`/GRAPH_ACTIONS）、`agent/harness._KIND_BY_ACTION`、`eval/check_blueprint_stop.py`、`check_criteria_binding.py`、`check_producer_judges.py`、`check_widget_event_binding.py`

## 0. 三句话结论

1. 蓝图有 `create_blueprint / compile_blueprint / bind_blueprint / bind_slot` + 图任务（`GRAPH_ACTIONS`/`_build_graph_task`），验收 `blueprint_compile`/`editor_assert`——**部分兜住**。
2. 但“图节点/连线”的落地仍是**弱执行**：靠有限的图 DSL/单点 discover，**没有统一的 Graph Spec 描述 + 拓扑只读复核**；出错靠重试而非“错误回灌改图”。
3. **蓝图图是动画蓝图/材质图/Niagara 蓝图/UMG 图/ControlRig 的共同地基**，所以这份优先级最高：把它 Spec 化做好，其它图域能复用大半 kernel 与 verifier。

## 1. 现状与证据

| 项 | 现状 |
| --- | --- |
| 一等动作 | `create_blueprint, compile_blueprint, bind_blueprint, bind_slot`（+ 图任务路径 GRAPH_ACTIONS） |
| 验收 | `blueprint_compile`（图编译过）/ `editor_assert`（producer 判词，`check_producer_judges` 钉） |
| 图落地 | `_build_graph_task` + 图 DSL；`nodes.py` 有蓝图节点类映射（如 `K2Node_*` / `ComponentBoundEvent`） |
| 守卫 | `check_blueprint_stop`（图写拦截）、`check_criteria_binding`（绑定）、`check_widget_event_binding`（控件事件走 blueprint.add_node 而非“无 action”） |

**结论**：能建空蓝图、能编译、能绑槽；**任意图（节点+连线+引脚+默认值+变量+事件桩）没有确定性 Spec+kernel+拓扑复核**。

## 2. 本域“模型-脚本”边界

- **模型**：产 **Graph Spec**（在哪个 Blueprint、哪个 Graph/Event，放哪些节点、节点类、引脚连接、默认值、暴露变量、事件桩）。
- **脚本**：`add_node`（按类）→ `connect`（引脚级）→ 设默认值/变量 → 编译；**只读复核**：节点类存在、边连到正确引脚、变量已生成、编译过。
- **硬规矩**：模型不直接 exec 图写；只产 Graph Spec；写经图写闸（`graph_write_policy` / `UE_ALLOW_BLUEPRINT`）+ 编译复核。

## 3. Graph Spec 草案（可跨图域复用）

```jsonc
{
  "blueprint": "/Game/Blueprints/BP_Door.BP_Door",
  "graph": "EventGraph",
  "variables": [{"name": "bOpen", "type": "bool", "default": false}],
  "nodes": [
    {"id": "ev",  "class": "K2Node_Event",    "event": "ReceiveBeginPlay"},
    {"id": "set", "class": "K2Node_VariableSet","var": "bOpen", "defaults": {"bOpen": true}},
    {"id": "print","class": "K2Node_CallFunction","function": "PrintString", "defaults": {"InString": "opened"}}
  ],
  "edges": [
    {"from": "ev.exec", "to": "set.exec"},
    {"from": "set.then", "to": "print.execute"}
  ],
  "verify": ["node:set", "node:print", "edge:ev.exec->set.exec", "compile_ok"]
}
```

> 只写“结构与接线”，不写“游戏逻辑自由代码”；复杂逻辑仍建议走 C++（C++ 域）或蓝图函数的既有文本入口，避免图越攒越乱。

## 4. 分期

- **P0 清点（0.5d）**：用 `scan_mcp_tools --query "blueprint add node connect pin"` 与已有一等动作，列清蓝图图现能做的动作（增节点/连引脚/建变量/事件/编译/读回）。
- **P1 Graph Spec + kernel（3d）**：`agent/graph_spec.py`：`validate_graph_spec`（类/引脚存在性用 `list_widget_properties` 类似查询或图 describe）+ `build_graph_spec`（add_node/connect/var/compile）。
- **P2 只读拓扑 verifier（1.5d）**：读回图（节点/边/引脚/变量），逐条比对 `verify`；缺节点/错引脚/变量没生成 → 结构化失败。
- **P3 回灌修复（1d）**：把 verifier 结构化错误喂回模型改图（≤2 次）。
- **P4 跨图域复用（1d）**：把 kernel/verifier 参数化给 animBP / material graph / niagara blueprint / UMG widget graph 用（各图域只换“节点类白名单 + 引脚表”）。

## 5. 守卫

`check_graph_spec.py`（Spec 校验/kernel 幂等/拓扑复核/成环/表外节点）、`check_graph_repair.py`（复核失败回灌）、`check_graph_route.py`（“建蓝图并连 BeginPlay→Print”稳定进链、不支持点名暂停）。登记 `offline.yml`。

## 6. 风险与取舍

- 图节点/引脚 schema 巨大：**不整份注入**，按需 `scan_mcp_tools --schema <full_name>` 单点取（守 AGENTS 铁律 1/2）。
- “图能编过”≠“逻辑对”：verifier 只保证“结构和接线符合 Spec + 编译过”；行为验证靠 PIE/automation（本域不假装做了）。
