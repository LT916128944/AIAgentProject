## 2. 现在的两条链

系统是两条入口，共用 Chroma `ue_assets` 和 [core/editor_exec.py](../../RAG/ue-rag/core/editor_exec.py)。README 第 3 节那张 FastAPI 编排图还没有对应进程。

```text
用户
 ├─ Cursor 日常链
 │    AGENTS.md + 三条 alwaysApply 规则
 │    → scan_mcp_tools.py（卡片，无 input_schema）
 │    → call_mcp_tool.py（stdout 约 200 字）
 │    → editor_exec.py → 官方 UE MCP :8000
 │
 └─ 命令闭环（RAG/ue-rag，Python 用该目录 .venv）
      start.bat 选 1  chat.py          检索一次后回答，不改工程
      start.bat 选 2  run_agent.py     单 Agent 图；没有任务文件时写操作被拒绝
      start.bat 选 3  run_task.py      --task 跑固定 JSON；--query 先 supervise
           supervise.py 把一句话收成任务 JSON，路径不唯一就返回错误
           → LangGraph 单图（graph.py）
                retrieve → plan → execute → plan
                         → 无工具且 verify 非空 → build → test → observe
                                                            ↘ 失败 → fix → plan
           → 本地 read_source / apply_unified_diff
           → 或 editor_exec.py → 官方 UE MCP :8000
           → judge.py 当裁判，无 LLM
```

图的边没有按角色拆开。[agent/roles.py](../../RAG/ue-rag/agent/roles.py) 只按 `verify` 的 kind 换这一轮的提示和工具子集：

| 角色 | 条件 | 看得见的工具 |
| --- | --- | --- |
| `loop` | 没有 `verify` | 本地工具加检索出的编辑器工具，并带 `finish` |
| `cpp` | 只有 `cpp_build` | `read_source`、`apply_unified_diff` |
| `editor` | `editor_assert` 或 `blueprint_compile` | `allow_writes` 里的写工具，加 `find_actors`、`get_actor_transform` |
| `mixed` | 同时有 C++ 和编辑器裁判 | 上面两组一起 |
| `supervisor` | 只在 `--query` 写任务时 | 不改文件。trace 记 `role=supervisor` |
| `judge` | `build` / `test` / `precheck` | 无 LLM |

`verify` 非空时模型没有 `finish`，不能自己宣布成功。`judge_first: true` 的任务第一轮不调用模型，直接进裁判。

## 5. 和主流 workbench 的对照

2026 年这几家产品的共同分层是：短的常驻规则、按需加载的 Skill、MCP 懒加载、hook 做确定性拦截、subagent 使用隔离上下文、外部测试决定终态、人看 diff。来源包括 Claude Code 的扩展点说明、Cursor / Codex / Devin 的 harness 比较，以及「规则 / Skill / MCP / hook 各管一层」的上下文工程写法。

| 层 | 主流做法 | 本仓库 |
| --- | --- | --- |
| 常驻规则 | `AGENTS.md` / `CLAUDE.md` 保持短；路径规则按文件匹配 | `AGENTS.md` 加三条 `alwaysApply` 规则。规则不按路径缩减 |
| Skill | 会话里先看见 description，命中后再读正文 | Cursor 侧按 description 路由，再读用到的那一节。闭环只塞一张 description |
| MCP | 工具多时不要把全部 schema 放进上下文 | 已对齐。830 个工具（52 个工具集，索引版本 2026-09-21，引擎 5.8.2）只扫卡片，`--schema` 打开一个 |
| 终态 | 编译和测试当法官，模型说成功不算 | 已对齐。`judge.py` 返回 `{ok, kind, summary, errors}`。`observe` 只看 `ok` |
| 人确认 | IDE 里看 diff，或计划模式等确认 | Cursor 改 UE 前把计划写到 `.cursor/memory/plans/`，这条写在规则里，没有 hook。闭环用 `allow_writes`，默认 `save: false`、`pie: false` |
| hook | 工具调用前后用脚本拦截，不靠提示词 | 闭环的拒绝在 `editor_exec.py`（写前缀、保存、PIE、蓝图改图开关）。Cursor 侧没有 hook |
| subagent | 子任务用单独的上下文或单独的虚拟机 | 同一张图、同一个模型、同一条 `messages`。trace 有 `role`，上下文不隔离 |
| 评测 | 固定任务、可重置、能报成功率和成本 | 3 条窄任务加 22 条检索题。trace 在 `data/traces/`，已 gitignore |
| 沙箱 | 进程或内核级限制写路径 | 应用层路径锁：C++ 相对 `Source/AIAgentProject`，拒绝 `..`。没有操作系统沙箱 |
| 回滚 | git 或编辑器事务 | 本仓库目前没有 git。`cpp-typo` 用文件字节快照还原。关卡靠不保存。没有 UE Transaction |

已经和主流对齐、下一轮不要推倒的决定：

- 官方 Unreal MCP 是编辑器出口。不新造第二套 HTTP。
- 工具返回进 Cursor 时截到约 200 字。执行器内部保留完整 `{ok, data|error}`。
- 检索先用便宜的专有名词和 BM25，向量只处理没被唯一命中的查询。22 题没有证明重排更好，热路径不加交叉编码器。
- 技能正文不进向量库。
- `--query` 不是 Cursor 里每句话的默认动作。人确认 `.cursor/memory/plans/` 之后才把改、编译、测试交给闭环。
- `UE_ALLOW_BLUEPRINT` 缺省 `false`。材质图、UMG、动画蓝图、Niagara 不论开关都不自动改。
- 监督者写不出唯一的类、蓝图 `refPath` 或 Actor 就失败，不猜。

| kind | 通过条件 |
| --- | --- |
