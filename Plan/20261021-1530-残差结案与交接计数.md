# 残差结案：交接计数、处置扇、聚类、单点杀伤

## 结论

同事一场 4.5 小时的编码代理停在变异门禁上：有效点 224，杀死 180，存活 44，分数 80.4% < 90%，判定 REJECT。它没有在同一段上下文里继续改代码，而是按闭集出口改派处置子代理：补测试杀掉，或逐条写成「测试盲区 / 等价变异 / 防御性分支」。分数从产物文件读。模型刚看到的「最近 30 行」只有约 29 条，前 15 条被截断。

本计划把这四条收进现有闭环。改动只在 `RAG/ue-rag`。不跑全量变异，不改 `Source/AIAgentProject`，不给 LangGraph 加节点。

一句话：

> 清单可以截短，总数必须在。编译失败仍走 `fix`。编译已过、Automation 仍失败时，本扇结束，父级另开处置扇。处置扇由代码追加，规划者写不出。一条残差要么被后续裁判杀掉，要么落在归因文件里。`passed` 仍只由对得上的裁判改写。

## 对照

| 同事的做法 | 当前代码 | 本计划 |
| --- | --- | --- |
| 分数从产物读，不信截断尾巴 | Automation 已要求解析出 `failed`，单词 `passed` 不算成功 | 保持。交接上补总数 |
| REJECT 后逐条处置，不在原上下文里空转 | `route_after_observe` 在 `test_judge` 失败时进 `fix`（`agent/graph.py`） | 仅 Automation 残差改道。坐标类 `editor_assert` 仍进 `fix` |
| 44 个存活点先收成簇，一扇吃一簇 | 窗口按句子里的动作拆 | 处置扇按失败测试名聚类，上限 4 扇 |
| 质量门通过之后，变异门仍可 REJECT | `observe` 按 `judge.kind` 改合同。`skip` 当通过 | 旁路单点杀伤：故意改错一条，现有 Automation 必须失败。不进默认三条 |
| 归因表进 HTML | `eval/report.py` 的 HTML 是 token 和失败分类 | 有归因文件时多一节。没有就空着 |

## 不动

- 图的节点仍是 `retrieve → plan → execute → build → test → observe → fix`。不新增节点，不改边的名字。
- `editor-cube`、`bp-gun-compile`、`cpp-typo` 的路径不变。位置没到位继续重试移动，不送去归因。
- `freeze_source` 的语义不变：只编译、不改源码。
- `integrate_verify` 仍由代码在任务书确认后追加。处置扇用同一条纪律，动作名单独一个。
- `passed` 不由模型正文、归因说明、HTML 改写。`manual` 保持 false。自动条款过了、仍有 `manual` 或未杀掉的残差，整句仍是「部分完成」。
- 交接给模型的仍是短 JSON，不附工具正文。`clip()` 继续丢掉含 `read_source` 的串。`unmet` 列表仍只留 8 条。
- 不换供应商，不改 `base_url`，不把 `--query` 接成 Cursor 每句话的默认动作。
- 不保存关卡，不 PIE，不放宽 `save` / `pie` / `allow_writes` / 五个 `UE_ALLOW_*`。
- 不上 mutmut、mull、Stryker、lizard。一次 `cpp_build` 预算仍是 300 秒，容纳不了 224 个变异点。
- 不改 `feature_list.json` 里已有条目的 `passed`。实施时只追加下面的 `pending` 行。

## 已确认决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 谁触发处置 | `build_judge.ok` 为真，且 `test_judge.kind == automation` 且 `ok` 为假 | 坐标断言失败是动作没做对，应重试。Automation 失败才是「测试没抓住」 |
| 本扇怎么停 | `observe_node` 把这种失败写成 `is_completed: true`、`final_success: false`，不进 `fix` | 与 `freeze_source` 同一手法：留下裁判原文，换一条新 `thread_id` |
| 谁开下一扇 | `run_windows` 在该扇结果上追加，规划者和理解器都写不出这个动作 | 与 `integrate_verify` 相同，避免模型自己宣布结案 |
| 聚类键 | `test_judge.errors[].message` 里的测试名；没有名字就归入一簇 `unnamed` | 同事的簇是同类存活点。咱们的同类是同一条失败测试 |
| 扇数上限 | 4。超出的名字收进第 4 扇的 `unmet`，并带 `unmet_total` | 防止一次失败拆出几十扇 |
| 归因标签 | `blind_spot` / `out_of_contract` / `equivalent` | 对齐同事的三类，词固定，代码校验 |
| 怎样算处置扇成功 | 每个残差 id 二选一：后续同 kind 裁判把它标成 `passed: true`，或归因文件盖住且标签是 `out_of_contract` 或 `equivalent` | `blind_spot` 只表示还要补测试，单独出现不能结案 |
| 单点杀伤放哪 | 只做旁路任务，仿 `inject_typo`：改错一条、Automation 必须失败、快照还原 | 全量变异不进 UE 模块。默认三条不跑它 |
| 结构门（函数长度） | 本计划不做 | 没有现成裁判。UCLASS 和生成代码容易误报。要做另开计划 |

## 阶段

### 阶段 1 · 交接写明丢掉了多少

改 `agent/harness.py` 的 `build_handoff`。

返回里保留 `unmet`（最多 8 条）。增加：

- `unmet_total`：截断前的条数
- `unmet_omitted`：`unmet_total - len(unmet)`，为 0 时也写 0

`handoff_note` 放进下一扇的短 JSON 带上这两个整数，仍不带第 9 条以后的正文。

`agent/board.py` 交接备注改成 `未完成 8/44：` 这种前缀，后面的句子仍切到 120 字。事件 `handoff` 增加 `unmet_total`。磁盘上的交接文件保存全量 id 列表，字段名 `unmet_ids`，只放条款 `id`，不放错误正文。模型看不到这份全量，父级聚类用它。

`eval/check_harness.py` 的 `check_handoff` 加一条：9 条未通过条款时，`unmet` 长度为 8，`unmet_total` 为 9，`unmet_omitted` 为 1，笔记里有总数，没有第 9 条的正文。0 条和 8 条时 `unmet_omitted` 为 0。

完成标记：`python eval/check_harness.py` 打印 `harness ok`。对应 `feature_list` id：`handoff-unmet-total`。

### 阶段 2 · Automation 残差另开处置扇

`agent/nodes.py` 的 `observe_node`：`build_judge` 已通过、`test_judge` 是失败的 `automation` 时，失败结果带 `is_completed: true`。`retry_count` 照旧加一，供 trace 分类。不进入 `fix_node`。`cpp_build` 失败、`editor_assert` 失败、`freeze_source` 三条路径保持今天的分支。

`agent/catalog.py` 增加动作 `dispose_residual`。注释写明只由代码追加，和 `integrate_verify` 一样。理解器的动作卡片里不要它。`plan_windows` 收到这个 action 时拒绝，不执行模型写出来的那一扇。

`agent/run_windows.py` 在窗口结果上识别「编译过了、Automation 没过」：用新 `thread_id` 追加 `dispose_residual`。交接用阶段 1 的文件。这一扇的合同条款从上一扇未通过的 `automation` 条款复制，`passed` 仍是 false。

归因文件写到 `data/handoffs/<run_id>/<window_id>.attribution.json`：

```json
{
  "items": [
    {"id": "c-automation", "label": "out_of_contract", "note": "过滤器不覆盖这一条"}
  ]
}
```

校验函数放在 `agent/harness.py`，不调用模型：

- `id` 必须来自这扇的残差，一条一次
- `label` 只能是那三个词
- `note` 走 `clip()`，最长 240，含 `read_source` 则当空串
- 缺 id、重复 id、未知标签都是这扇失败
- 标签是 `blind_spot` 的 id 不算盖住

结案规则：残差 id 被同 kind 裁判写成 `passed: true`，或被 `out_of_contract` / `equivalent` 盖住。全部有着落，处置扇 `ok`。合同里被归因的条款保持 `passed: false`，`contract_status` 仍是「部分完成」。

离线夹具放进 `check_harness.py`，用假裁判，不连编辑器：

- 编译失败仍会进 `fix` 的路由条件（断言 `route_after_observe` 的输入状态）
- Automation 失败且编译已过：`observe` 结果的 `is_completed` 为 true，`final_success` 为 false
- 归因盖住全部 id：处置判定为成功，条款 `passed` 仍是 false
- 只写了 `blind_spot`：处置判定为失败
- 模型风格的「已完成」字符串进 `note`：不改 `passed`

完成标记：`check_harness.py` 与 `check_routes.py` 仍打印 `harness ok`、`routes ok`。图的边集合不变。对应 id：`test-disposition-window`。

### 阶段 3 · 按测试名收成簇

`agent/harness.py` 增加纯函数 `cluster_residuals(errors) -> list[dict]`。每簇含 `key` 和 `ids`。键是错误消息里的测试名；抽不出名字的进 `unnamed`。超过 4 簇时，第 4 簇的 key 固定为 `overflow`，剩下的 id 都放进去。

`run_windows` 用这个函数决定追加几扇 `dispose_residual`。一簇一扇。每扇的 `unmet_ids` 只含该簇。簇内仍适用阶段 2 的结案规则。

`check_harness.py` 覆盖：两个测试名得到两簇；没有名字得到一簇；5 个名字得到 4 簇且第 4 簇 key 为 `overflow`。不叫模型。对应 id：`residual-cluster`。

### 阶段 4 · 单点杀伤（旁路）

新增 `eval/tasks/side/kill-check.json`，不进 `eval/bench_manifest.json` 的默认三条，不进 `run_eval.py` 的默认清单。

任务形状仿 `cpp-typo` 的 `inject_typo`：

- 先有一条已经通过的 Automation 过滤器（写明用哪一个现成过滤器，实施时从 `AIAgent.Pawn.Look`、`AIAgent.Pawn.Wasd`、`AIAgent.Enemy.Patrol` 里选一个离线夹具能伪造结果的；真跑留给人手，本阶段完成不依赖编辑器）
- 对契约相关的一处做一次故意改错
- 期望 `test_judge.ok` 为 false
- `finally` 用现有源码快照还原

离线要钉住的是期望，不是编辑器：

- 注入之后 Automation 失败：杀伤成功，残差可以结案
- 注入之后 Automation 仍 `failed: 0`：记为 `blind_spot`，处置扇不能仅凭这次归因结案
- 还原路径与 `inject_typo` 相同，不把试探改动留在 `Source/`

`report.py` 的 HTML 在 trace 或交接目录里真有归因条目时加一节：id、簇 key、label、截短的 note。没有条目就不写这一节，不填 0。对应 id：`kill-check-side`。

### 阶段 5 · 用法文档

实施落地后，把本节的行为追加进 `WORKFLOW.md` 的「裁判」和「多窗口的升级」里交接那一行：`unmet_total`、处置扇的触发条件、三种标签、单点杀伤不进默认三条。不要重写全文。

`data/harness/feature_list.json` 追加四条 `pending`：`handoff-unmet-total`、`test-disposition-window`、`residual-cluster`、`kill-check-side`。`passed` 只在对应的 `check_harness.py` 断言被跑过并记入 evidence 之后改，不在写文档时改。

## 验收

工作目录 `RAG/ue-rag`，Python 用该目录 `.venv`。

```powershell
python eval/check_harness.py
python eval/check_routes.py
```

通过时仍打印 `harness ok`、`routes ok`。不叫模型，不连 MCP，不编译游戏模块。

阶段 4 的真编辑器跑不在本计划的完成条件里。旁路任务文件在，离线期望在，即算这一阶段落地。

## 仍不做

- 对 UE 模块跑一轮 200 个以上的变异点
- lizard 或函数行数门禁
- 用处置扇替换 `editor_assert` 的重试
- 让归因说明把 `manual` 或 Automation 条款改成 `passed: true`
- 在 Cursor 对话里默认启动 `run_windows.py`
