## 0. 一句话

上一版把「人跑 30 条、人写证据、人亲手算 sha1、人跑换机」写成了拿分手段——那是**人给 AI 打工**。这一版把这四件事全部移交给机器，人只剩四处介入：**授权（安全边界）、PIE 看一眼（能力边界）、签一条判断、抽查 3/30（审计）**。人的总耗时从约两天降到约二十分钟，而且防造假更强：抽查是随机的，AI 事先不知道哪条会被查。

**分数口径一个字没改**：96 仍是「证据完备性」的上限（`BASE` 81 + 加分 15，`eval/check_scorecard.py:42-44`）。另加一份**自动化度报表**（§4.5），两把尺子分开报，不再混着说「96 分的 AI 工作流」。

### 0.1 这份计划的验收判据（用来防止再滑回「AI 辅助」）

一条改动算合格，只有两个条件同时成立：

1. **人的绝对动作数下降**（不是「更顺手」，是「不需要」）；
2. **机器自己证明自己做对了**（provenance + 抽查），而不是人替它写证明。

凡是**新增**人工确认点、新增 `manual` 条款、新增「请人跑一下」的，默认不做；要做得单独写理由。

### 2.1 四个 v1 没写到的发现（重要）

1. **B 的 16 底分比 v1 以为的早得多。** v1 §2 那张表写「十句各 1 轮 → 73」「setup 后 → 77」。按现在的代码，`_bench` 只要有一条 `status=ok` 且 `evidence_kind=machine` 的记录就返回 `machine_ok>0`，B 立刻 `verified` 并计入底分（`eval/check_scorecard.py:577-584`，`:262-263`）。**实测模拟（临时根，不改仓库）：10 条记录后已验是 89，不是 73；setup 之后是 93，不是 77。** B 的加分 3 分才是「30 条 + ≥90%」那一档。

3. **沙箱挡路（实测）。** `python eval\check_scorecard.py` 在 DSH 沙箱里跑到 `_write_closed_env` 就 `PermissionError`（`%TEMP%` 写入与 `tempfile` 清理的 chmod 被拒）。所以「长跑 + 收尾检查」**必须在普通 PowerShell 里跑**，不能塞进沙箱内的后台任务。
4. **`check_plan_parity` 现在红得没意义。** 它拿 `data/archive` 的目录名当白名单（`eval/check_plan_parity.py:61-64`、`:92-112`），但 `if archived and …`（`:110`）在 archive 为空时整段失效 → 现在任何 events 都被当成「真机」。有了记录才真的在比。

### 2.2 一条技术前提（已实测）

`bench_runner` 必须走 `run_windows.py`，不能走 `agent/run_task.py --query`：`sentence` 字段只由 `agent/harness.py:307-333 sentence_outcome` 在 `run_windows` 收尾时写（`agent/run_windows.py:2438-2442`），而 `agent/bench_record.py:257-267` 只认这个字段。`run_windows.py:3267` 会打印 `窗口结束，退出码 N。记录：<path>`——runner 直接拿这一行，不必猜。

## 4. 要写的五个东西（AI 写、AI 跑）

### 4.1 `agent/bench_runner.py`（核心，**先做这一件**）

```
python agent\bench_runner.py --rounds 3
python agent\bench_runner.py --only compile,open-level --rounds 1
python agent\bench_runner.py --only patrol-presentation --rounds 1 --no-record
python agent\bench_runner.py --rounds 3 --resume
```

一轮的固定动作（十步，一步都不许省）：

1. 扫 `live_run_ids`（`agent/run_guard.py:154-167`）；有活就**退 3 并打印 run_id**，不 `--force`。真互斥在 `claim_stdin`（`:35-63`）+ `data/locks/editor.lock`；`admit_live_runs`（`:187-217`）只是提示，不是互斥。
2. 该句在 `data/archive` 里已满 `--rounds` 轮 → 跳过（默认行为即 `--resume`；重跑要显式 `--force-round`）。
3. 记 `t0` + 快照 `data/runs/**/*.json` 文件名集合。
4. `Popen([sys.executable, "agent/run_windows.py", "--plain"], stdin/stdout=PIPE, CREATE_NEW_PROCESS_GROUP)`，喂「原话 + `:quit`」。
5. 逐行读 stdout，抓 `窗口结束，退出码 N。记录：<path>`；没抓到就用「新增 run 文件」兜底。
6. 超时（`--timeout`，缺省 2400 s/句）：整棵进程树杀掉，attempt 记 `timeout`。
7. 调 `agent.bench_record.record_round(run_id)`。`Refused` → **原样打印原因**，不写 archive（这就是 v1 里「被拒绝是对的」自动化的样子）。
8. 每次尝试追加一行到 `data/bench/attempts.jsonl`（**不是** archive）：`{ts, sentence_id, round, run_id, exit, status, refused_reason, seconds}`。
9. 成功 → `data/archive/<run_id>/verdict.json`（`round` 由 archive 计数自增，天然幂等：重试不产轮次）。
10. 句间 `--cooldown`（缺省 15 s），并确认编辑器已退出、端口 9316 没被占。

失败策略：同一句同一轮最多 `--attempts 2` 次；两次都拒 → 该句标 `give_up` 并把剩余轮次跳过，**不拿失败记录去凑分母**，最后打印「缺哪几句、原因原文」等人看。

跑完写 `data/bench/batch.json`：

```json
{"batch_id":"…","started_at":"…","finished_at":"…","rounds":3,
 "seed":"<32 hex，来自 secrets>","produced_by":"agent/bench_runner.py",
 "sentences":[{"id":"compile","round":1,"run_id":"…","status":"ok","attempts":1,"seconds":412}],
 "missing":[{"id":"…","round":2,"reason":"…"}],
 "sampled":["<run_id>","<run_id>","<run_id>"]}
```

`sampled` = `random.Random(seed).sample(sorted(所有三十条 run_id), 3)`，**批次结束后才算，且不可事后改**：`check_bench_audit` 用同一个 `seed` 重算，名单一动就红。

### 4.2 `agent/proof_bundle.py`（证据由机器生成）

```
python agent\proof_bundle.py --criterion patrol-presentation --run-id <run_id>
```

- 写 `data/proofs/<criterion_id>/<run_id>.md`：run_id、时间、backend、`sentence`、窗口 state 表、条款表（`id / evidence_kind / passed / evidence_sha1`）、判词行原文、`data/runs` 与 `data/events/<run_id>.jsonl` 里摘 ≤40 行日志、存在的截图/日志路径清单。
- 同路径 `.sha1`：**脚本算**，人不再碰 `Get-FileHash`。
- 写 `data/proofs/pending/<criterion_id>.json`：`criterion_id / evidence_path（绝对）/ evidence_sha1`，`person` 与 `signed_at` **留空**。
- 硬约束：不从模型文本取任何「成功」字样，只摘落盘事实。

### 4.3 `agent/attest_sign.py`（人一句话签，不碰文书）

```
python agent\attest_sign.py --criterion patrol-presentation --person "你的名字" --yes
```

- 读 pending；缺 → 「先跑 proof_bundle」。
- 重算证据 sha1，与 pending 不符 → 拒绝（证据被改过）。
- 先打印证据路径 + 三条看点，**必须加 `--yes`** 才算「我看过了」。

- `agent/manual_attest.py` **一行不改**：它的语义（哈希相符才算签）是对的，错的只是「让人去做文书」这件事。
- 不写 `.env`、不写 `session_task.json`、不碰 `feature_list.json` 的 `passed`。

### 4.4 `eval/check_bench_audit.py`（抽查做成真门）

全机械可判，任一不满足就红：

1. `data/bench/batch.json` 不存在 → 红（「没有一批机器基准」）；
2. `produced_by != "agent/bench_runner.py"` → 红；
3. archive 里的 `run_id` 集合与 batch 的记录集合不一致 → 红；
4. `sampled` 与自己用 `seed` 重算的抽样不一致 → 红（**名单被改过**）；
5. `data/bench/audit.json` 不存在，或 `person`/`signed_at` 为空 → 红（「还没抽查」）；
6. `audit.verdict != "ok"` → 红，并打印要删的目录清单（整批作废、重跑）；
7. `audit` 里每条 `run_id` 必须真在 archive，且抄的 `status` 与 archive 一致，否则红。

注册只需一处：`.github/workflows/offline.yml` 加一行 `- name: check_bench_audit` / `run: python eval/check_bench_audit.py`——`check_all` 是**从这个文件抓**检查清单的（`eval/check_all.py:20-36`），不写死。

## 7. 自动化第一次跑才会遇到的七个坑

1. **同句三轮的状态依赖。** `create-level` 第 2 轮时 `L_NewTest2` 已存在，行为会变（第一轮创建、第二轮撞已存在）。现在的 `eval/bench_manifest.json` 的 `sentences` **没有 `reset` 字段**。不做处理就是 26/30 = 86.7% → **95**。
   处理方式：给 `sentences` 加 `reset` 形状（`{"reset": "delete_level:L_NewTest2"}`），`bench_runner` 在每轮开始前执行；实现不了就先按 §9 决策 2 认账。
2. **`place-coins` 的 `unresolved` 占位。** 它记 `ok` 就是假通过（v1 §6 坑 2），所以它**永远**是 `partial` → 90% 上限（§6）。
3. **沙箱挡路。** 长跑与 `check_scorecard`/`setup.ps1` 必须在普通 PowerShell（或一次性 `danger-full-access` 授权）里跑；沙箱内会 `PermissionError`（§2.1 第 3 条实测）。
4. **单活真互斥在 `claim_stdin`。** runner 撞到「输入已被另一个进程占用」要**停**，不许 `--force`、不许并发第二实例。

## 11. 还能再削吗（诚实的答案）

削得掉的：换机脚本（已经是「机器跑、人看退出码」）、证据文书（已机器生成）、哈希（已脚本算）、benchmark 执行（已是机器跑）。
