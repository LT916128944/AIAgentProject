# 20261117-1613 — 材质（Material / MaterialInstance）域兜住升级计划

- 日期：2026-11-17 16:13 · 状态：计划
- 母文件：[`20261117-1610-UE5全域模型脚本边界总览.md`](20261117-1610-UE5全域模型脚本边界总览.md)
- 相关：`agent/sequence.py`（`_set_scalar_param`/`_query_material`）、`agent/catalog.CATALOG`、toolset `editor_toolset.toolsets.material.MaterialTools` 与 `...material_instance.MaterialInstanceTools`、`UE_ALLOW_MATERIAL`

## 0. 三句话结论

1. 材质域现在**只能“读参数 + 覆写材质实例的一个标量参数”**（`query_material / set_scalar_param`，后者裁判还是 `blueprint_compile` 而非参数读回）；**材质图（节点/连线/常量/纹理采样）没有任何一等动作**。
2. 材质图需求今天落 `solve`：模型 discover `material` 命名空间→describe→exec 原语，**没有确定性 kernel、没有图拓扑复核**——兜不住“把基础色改成红并连乘法节点”这种。
3. 工具层其实有 `MaterialTools` + `MaterialInstanceTools`；升级 = 先做**材质实例参数 Spec**（低垂果实），再做**材质图 Spec**（节点/连线/常量），都配只读复核与回灌。

## 1. 现状与证据

| 项 | 现状 |
| --- | --- |
| 一等动作 | `query_material`（读材质/MI 参数）、`set_scalar_param`（覆写 MI 标量参数，裁判 `blueprint_compile`） |
| 无 | 材质图节点创建/连线/常量设置/纹理采样——**零动作** |
| 工具集 | `MaterialTools`（材质图）、`MaterialInstanceTools`（MI 参数）——工具层可用 |
| 写闸 | `UE_ALLOW_MATERIAL`（人审门挡在 editor_exec） |
| 实测 | “把基础色改成红色并连乘法节点” → `solve`（非一等动作） |

**结论**：MI 参数“半兜”；材质图“不兜”。

## 2. 本域“模型-脚本”边界

- **模型**：产 **Material Spec**——要么 MI 参数覆盖（`{param, value}`），要么材质图（`{nodes:[{cls,params,pos}], edges:[{fromPin,toPin}], outputs}`）。
- **脚本**：MI → `MaterialInstanceTools` 设 scalar/vector/texture 参数；图 → `MaterialTools` 建节点/连引脚/设常量/接线到根输出；**只读复核**：MI 参数读回==期望；图节点类/引脚拓扑读回==Spec；材质编译通过。
- **硬规矩**：模型只产 Spec；写经 `UE_ALLOW_MATERIAL` 写闸 + 参数/拓扑复核。

## 3. Material Spec 草案

```jsonc
// 形态 A：材质实例参数（先做，低风险）
{"kind":"material_instance","target":"/Game/Materials/MI_Door.MI_Door",
 "params":[{"name":"BaseColor","type":"vector","value":[1,0,0,1]},{"name":"Roughness","type":"scalar","value":0.4}],
 "verify":["param:BaseColor==(1,0,0,1)","param:Roughness==0.4","compiled"]}

// 形态 B：材质图（后做）
{"kind":"material_graph","target":"/Game/Materials/M_Door.M_Door",
 "nodes":[{"id":"c","cls":"Constant3Vector","params":{"R":1,"G":0,"B":0}},
          {"id":"m","cls":"Multiply","params":{"ConstB":0.5}}],
 "edges":[{"from":"c.0","to":"m.A"},{"from":"m.0","to":"Root.BaseColor"}],
 "verify":["node:Multiply","edge:c->m.A","edge:m->Root.BaseColor","compiled"]}
```

## 4. 分期

- **P0 清点（0.5d）**：`scan_mcp_tools --query "material instance set parameter"` / `"material add node connect pin"` 摸清 `MaterialTools/MaterialInstanceTools` 的动作与参数（含能否读回图拓扑）。
- **P1 MI 参数 Spec + kernel + 读回复核（1d）**：`agent/material_spec.py`（先只做形态 A）；修正“裁判应为参数读回”而非借用 `blueprint_compile`。
- **P2 材质图 Spec + kernel（2–3d）**：节点/连线/常量/纹理；只读读回图拓扑做 verifier。
- **P3 回灌修复（1d）**：参数读回不符/拓扑不符 → 回灌模型改 Spec（≤2 次）。
- **P4 沉淀**：常见材质（纯色/自发光/MI 覆写）毕业。

## 5. 守卫

`check_material_spec.py`（MI 参数 kernel + 读回复核；图节点/连线拓扑复核；表外节点/参数拒绝）、`check_material_route.py`（“把基础色改红/调粗糙度/加自发光”稳定进链）。登记 `offline.yml`。

## 6. 风险与取舍

- 材质图节点类/引脚 schema 大且版本相关：**按需单点 describe，不整份注入**。
- “编译过”≠“视觉对”：verifier 到“拓扑 + 参数 + 编译”；视觉验收留给截图人工/后续。

## 7. 立即三件事

1. 清点 `MaterialTools` / `MaterialInstanceTools` 动作与读回能力。
2. 落形态 A（MI 参数 Spec + 读回复核），修裁判口径。
3. 落形态 B 的节点/连线 kernel + 一个只读拓扑 verifier。
