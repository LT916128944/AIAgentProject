## 3. 四道人工闸门怎么进的工作流（这是这次唯一新增的机制）

计划 §3 说人还剩四件事。原来它们是「人去手撸 JSON / 人在终端敲命令」；这次全部改成
`agent/bench_gate.py` 的四道闸门，**每一步都是「机器摊开落盘事实 → 人回一句话 → 机器记账并自检」**：

```
python agent\bench_gate.py --gate list          # 四道闸门现在的状态
python agent\bench_gate.py --gate authorize     # 只读，永不写 session_task.json
python agent\bench_gate.py --gate pie  --run-id <run_id>
python agent\bench_gate.py --gate attest --criterion patrol-presentation [--person X --yes]
python agent\bench_gate.py --gate audit        # 摊开 batch.sampled 那三条
python agent\bench_gate.py --gate audit --person X --verdict ok --mark <run_id>=ok --yes
```

退出码语义：**2 = 在等人回话**，1 = 这一步本身有问题，0 = 闸门放行。和「红了」区分开。

## 4. 三处口径纠正（计划与现在的代码不一致）

### 4.1 「patrol-presentation 把连线当任务跑即可」不成立

计划 §1 第 4 条结论是「部分采纳：`.env` 里 `UE_ALLOW_BLUEPRINT=true`，代码侧能连，把连线当任务跑即可」。
真跑一次（`20261112-123756`，865.9 s）的结果是：

```
source = solver-fallback
窗口 SBW-A-SOLVE (action=solve) state=failed
"求解方案没产出：方案里没有可执行的步骤（能力缺口：方案层接不住）"
sentence = failed
```

到不了 `bind_blueprint` 那一扇。而且仓库自己 2026-10-27 的复核（`data/harness/feature_list.json`
的 `patrol-presentation.notes`）早就写着：**monolith 蓝图词表没有「覆写组件 BlueprintImplementableEvent」
的节点类型（`resolve_node` 干跑实测）**。两条独立原因，任一条都够堵死。

**后果：`patrol-presentation` 永远拿不到一条 archive 记录**（再叠上 §4.3 第 2 条）。

### 4.2 §3 第 1 条「授权只能写在 `data/dsh/session_task.json`」对这条流水线不成立

- `data/dsh/session_task.json` 只喂 `config.run_policy("dsh")`，**唯一调用方是 `server/dsh_bridge.py`**。
- `bench_runner` 走的是 `agent/run_windows.py --plain`，那条路用 `config.run_policy("menu", task)`
  → `task_policy()`，`save`/`pie` 从 `.env` 的 `UE_DEFAULT_SAVE` / `UE_DEFAULT_PIE` 读，写开关从
  `.env` 的 `UE_ALLOW_*` 读。

所以本次四道闸门里的 `authorize` 对这条流水线**不是必需**——真正管授权的是 `.env`，而它现在
`UE_ALLOW_BLUEPRINT / UE_DEFAULT_SAVE / UE_DEFAULT_PIE / UE_ALLOW_MONOLITH_WRITE` 全为 `true`。
**人工触点因此是 3 条，不是计划 §3 说的 4 条。**（闸门工具照实把两条策略源都打出来，不假装。）

### 4.3 §6 的分数算术在现在的代码上算不出来

计划 §6 说「27/30 = 90.0%，零余量 → 96」。这条账有两个洞：

1. **`_bench` 要 30 条**。`eval/check_scorecard.py:264` 是
   `if len(done) < 30 or any(counts.get(item, 0) < 3 for item in ids): return 0`。
   少一句就是 27 条 → `len(done) < 30` → B 加分 **0**，不是「27/30 拿 3 分」。
2. **`record_round` 拒记没有证据的 run**。`agent/bench_record.py` 的 `_evidence_digest` 只认
   「`passed is True` 且带 `evidence_sha1`」的条款；patrol 那次 run 的 `criteria` 只有一条
   `c-automation`（`passed=false`、无印章）。实测原文：

   ```
   $ python agent\bench_record.py --run-id 20261112-123756 --sentence-id patrol-presentation --dry-run
   拒绝记录：这次 run 的 criteria 里没有任何 evidence_sha1：判词没把条款翻成 passed，
   或记录里没有判词窗口。不算成功证据，拒绝记录。
   ```

   这个「不拿失败记录去凑分母」是对的，但它的另一面是：**失败的句子进不了 archive**。

两条合起来还和第三条门打架：`eval/check_plan_parity.py` 把 `patrol-presentation` 当
`PARTIAL_SENTENCE`，**要求它必须有一条归档记录**（`status="missing"` → 直接退 1）。而它按
§4.1/§4.3 不可能有归档记录 → **`check_plan_parity` 必然红 → `check_all` 退 1 →
`setup.ps1` 的 `ok` 转述不成立 → I 维转不绿**。

**所以真上限是 81**：

| 项 | 现在 | 能不能到手 |
| --- | --- | --- |
| B 底 16 + C15 + D12 + E12 + F10 + G9 + H7 | **81** | 已在手（`scorecard.json` 实测） |
| A 底 7 + 1 | 0 | 需要一条哈希相符的人签；这次人决定不签（§5） |
| B 加分 3 | 0 | 需要 30 条 archive 且每句 ≥3 轮；patrol 拿不到，见 §4.3 |
| I 底 2 + 2 | 0 | 需要 `check_all` 退 0；`check_plan_parity` 红，见 §4.3 |

`python eval\check_scorecard.py` → `已验 81 / 未验 9（A、I）`。
`python eval\check_all.py` → **退 1：49 条里 48 绿，唯一红的是 `check_plan_parity`**。
