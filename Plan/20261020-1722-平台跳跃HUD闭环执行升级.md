# 平台跳跃 HUD：闭环执行缺口与升级

## 结论

**现有工作流执行不了** [`20261020-平台跳跃HUD-UMG人工步骤.md`](20261020-平台跳跃HUD-UMG人工步骤.md)。对这句话，闭环只会在 `UE_ALLOW_UMG=false` 时把同一份步骤写进 `Plan/`，然后停。`feature_list.json` 的 `umg-domain` 已 `done`，证据就是这份人工文档，不是 `WBP_HUD`。

把开关改成 `true` 也做不出 HUD。`agent/umg_manual.py` 在 `allow_umg()` 为真时直接返回空，人工文档不再写；`agent/catalog.py` 仍没有 Widget 动作，规划者只能把 UMG 放进 `unresolved`。开关打开之后，HUD 条款从合同里消失，Widget 也不会被建出来。

本文件只定升级，不改 `.env`、不改 Widget、不改 `feature_list.json` 的 `passed`。

## 人工步骤对照

| 人工步骤 | 闭环现状 |
| --- | --- |
| 新建 `/Game/UI/WBP_HUD` | 动作表无此动作。`UMGToolSet` 有 `CreateWidgetBlueprint`，未接入 `run_windows` |
| Designer：Canvas + 四个 Text、Anchor、字号、Hidden、文案 | 控件树不在蓝图 Graph DSL 里。`UE_ALLOW_UMG=false` 时 `editor_exec` 拒绝该工具集的写调用 |
| Graph：`BindProgress`、三条动态委托、单独的倒计时 Tick | 同上。蓝图索引导出跳过 `widget` / `wbp_`。`supervise` 把「UMG / 控件树」挡在普通蓝图改图外面 |
| 编译保存 `WBP_HUD` | 无对应窗口。关卡默认不保存；Widget 资产保存也没有单独授权 |
| Level Blueprint 或 GameMode 的 BeginPlay：Create Widget → Add to Viewport | 本机 `UE_ALLOW_BLUEPRINT=true`，但动作表没有「挂 HUD」这一扇，规划者排不出这三步 |
| PIE 看计数、倒计时、通关、失败 | 文档写明视觉不进裁判。默认不开 PIE。`manual` 条款裁判改不了 `passed` |

动作表里和表现层有关的只有 `set_scalar_param` / `query_material`（材质实例标量）。没有创建 Widget、摆控件、绑委托、挂视口。

## 升级原则

照材质域的收法：加一个写死的动作，不开通用 UMG 改图。

- 只服务这份 HUD 合同：路径 `/Game/UI/WBP_HUD`，控件名 `txt_CoinCount` / `txt_Timer` / `txt_Clear` / `txt_Fail`，数据来自 `UPlatformProgressComponent`。
- `UE_ALLOW_UMG` 缺省保持 `false`。验收那一扇由人临时打开，跑完复原。
- 关卡不保存，不开 PIE。只允许保存 `/Game/UI/WBP_HUD` 这一份资产。
- 已有同名 Widget 且四个控件名齐全时不重建，缺哪个补哪个。
- 工具全名和参数以实施时 `scan_mcp_tools.py` 的 schema 为准。扫描对不上就停，不编 JSON。

## 阶段

### 阶段 0 · 工具核对

扫 `UMGToolSet` 里创建 Widget、加控件、设 Anchor / 位置 / 字号 / Visibility / Text、编译这几项的 schema。委托绑定和 Event Tick 单独记「表达得了 / 表达不了」。表达不了的留在人工文档里，不硬写节点。

### 阶段 1 · `build_platform_hud`（控件树）

动作表新增 `build_platform_hud`。槽位固定为这份合同，不接受任意 Widget 路径。

写闸：`allow_writes` 且 `UE_ALLOW_UMG=true`。`editor_exec` 仍是唯一出口。

做完用只读复读当裁判（`editor_assert`）：四个控件名在、`txt_CoinCount` 左上、`txt_Timer` 在其下、`txt_Clear` / `txt_Fail` 默认 Hidden 且文案为「通关」「时间到」、Widget 编译通过。然后只保存这份资产。

开关为 `false` 时行为与现在相同：写 `Plan/` 人工步骤，合同保留 `manual` 条款。

开关为 `true` 时不再返回空。阶段 1 失败则条款保持未过，并写明缺哪一项。

### 阶段 2 · 控件图（有条件）

仅当阶段 0 证明工具能表达下面四件事，才写成同一动作里的固定脚本，失败进现有 `fix`，次数用尽即停：

- 自定义事件 `BindProgress`：找到 `APlatformProgressActor`，取出 `UPlatformProgressComponent`
- `OnCoinCollectedDyn` → `txt_CoinCount` 写成 `金币 <CollectedCount>/<TotalCoins>`
- `OnAllCollectedDyn` → `txt_Clear` Visible
- `OnTimeOutDyn` → `txt_Fail` Visible
- 只有 Event Tick 写 `txt_Timer`（剩余秒数 Ceil，格式 `0:00`）

工具表达不了委托或 Tick：阶段 2 不进动作表。人工文档缩成只剩控件图，阶段 1 的控件树仍可由闭环做。

### 阶段 3 · `mount_platform_hud`（挂视口）

独立一扇，依赖阶段 1 的资产已经在。优先唯一的 GameMode 蓝图 BeginPlay；没有唯一目标就改 Level Blueprint。两处都已挂过则停，不各挂一次。

这扇走现有蓝图改图门（`UE_ALLOW_BLUEPRINT`），不借用 UMG 开关去改任意事件图。复读：图上存在一条 Create Widget（`WBP_HUD`）→ Add to Viewport，且全工程只有这一处。

## 合同与台账

实施时追加 `feature_list.json` 一条，不改已有 `umg-domain`：

| 字段 | 值 |
| --- | --- |
| `id` | `umg-hud-exec` |
| `status` | `pending`（做完由裁判改，不由模型文本改 `passed`） |
| `evidence` | 阶段 1 的只读复读 run；阶段 2、3 能做则把复读写进同一条 notes |

`agent/harness.py`：`UE_ALLOW_UMG=false` 时 HUD 仍是 `manual`。开关为 `true` 且 `build_platform_hud` 复读通过，对应条款用 `editor_assert`，不再把 HUD 从合同里拿掉。`apply_judge` 继续不让模型文本把 `manual` 改成通过。

`WORKFLOW.md`「仍然没有的东西」里平台跳跃那句仍写四条 pending，与 `feature_list.json` 不符。实施时改成：四阶段已过；HUD 控件树见本文件；开关未开时仍是人工条款。

## 验收

- 开关 `false`：一句话仍只写出人工步骤，编辑器里没有新建或改动 `WBP_HUD`，关卡未保存，未 PIE。
- 开关临时 `true` 的一扇：复读四个控件名、Hidden、文案、编译通过；只多出 `/Game/UI/WBP_HUD` 的保存。跑完开关复原 `false`。
- 阶段 0 判工具不够时：动作表里没有半截控件图脚本，人工文档写明剩下的是哪几步。
- 离线检查仍绿。不把 HUD 像素塞进 `AIAgent.Platform`。

## 不做

- 不把 `UE_ALLOW_UMG` 的缺省改成 `true`。
- 不开放任意 Widget、材质图、动画蓝图、Niagara。
- 不因 HUD 去 PIE，不保存关卡。
- 不改 `umg-domain` 的 `done` / `passed`。那条表示「会写人工步骤」，本文件表示「按步骤做出这一份 HUD」。
