## 1. 结论

周计划是从零学到能投递的课表。工作流已经越过课表中段：检索、LangGraph 闭环、裁判、多窗口、任务书、续接、失败分类文本、句子到动作的四层路由都在跑。缺的不是再做一遍 Agent Loop。

挡「一句话生成会巡逻的敌人」和挡「拿这个仓库去面 UE5 + Agent」的是同一批没有交付物的行。[周计划.md](../周计划.md) 第 5 节写明：没有交付物的行不算覆盖。按这个标准，13 周里能拿去给面试官看的，主要是 W5 的导出器、W7 的图，以及 W8 的半成品记忆。W1、W4、W10、W11 的交付物还没有。

面试要的证明收成三句话：

1. 同一批任务在干净工程上重跑，成功率和 token 是算出来的，旁边有一条手工 Cursor 对照。
2. 验收看运行时读数。编译通过、蓝图编译返回空、模型说完成，都不算敌人会巡逻。
3. 工具和技能是这个项目自己注册的，带 schema、权限和版本。官方 830 个工具是被收窄使用的，不是作品本身。

升级顺序按这三句排，不按 W1 到 W13 重做。网关、Docker、仪表盘放在数字和验收句之后。

## 3. 面试时还缺的能力证明

下面每条都是 2026 年公开材料里面试官能追问的点。周计划的 31 行矩阵没有写进第 1、2、5 条，所以只做完周计划仍会在这三题上空手。

### 3.1 引擎里要有自己的 Toolset 和 Agent Skill

Epic 在 UE 5.8 把 MCP 工具收成 Toolset Registry：Python 继承 `unreal.ToolsetDefinition`，或 C++ 继承 `UToolsetDefinition`，静态函数标 `AICallable`，类型和注释变成 JSON Schema。`ToolsetRegistry.get_toolset_json_schema` 能把某个类的 schema 拿出来核对。技能是 `unreal.AgentSkill`（插件 ToolsetRegistry），字段是 `description` 和 `instructions`，`generate_prompt` 生成最终提示。Unreal Fest Chicago 2026 的讲法是：模型会叫错工具，系统要让它改得回来；技能里写的是模型上下文里没有的项目规矩（他们举的例子是打光要先太阳后天空）。

依据：

- [unreal.ToolsetRegistry](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/ToolsetRegistry)、[unreal.ToolsetDefinition](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/ToolsetDefinition)、[unreal.AgentSkill](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/AgentSkill)
- [Epic create-toolset skill](https://github.com/epicgames/unreal-engine-skills-for-claude-code-plugin/blob/main/skills/create-toolset/SKILL.md)
- [Unreal Fest Chicago 2026: Integrating MCP into the Unreal Editor](https://www.youtube.com/watch?v=lDf_y-YPELo)

当前仓库调用的是官方 MCP，规划者只看见 8 个动作。Cursor 侧技能是 markdown 卡片。引擎资产里还没有一条 `AgentSkill`，也没有一个项目自己的 `UToolsetDefinition`。B 类岗位（UE 编辑器工具 + AI）问「你给编辑器加过什么 AI 可调用接口」时，扫描官方工具答不上。

这一段做完要留下两样东西：一份 6 个高层工具的契约 JSON；编辑器里一个真正注册成功的工具集，schema 用 `get_toolset_json_schema` 导出存档。再加一条 `AgentSkill`，正文写本项目已经踩过的规矩：1 米 = 100 uu、编的是 `AIAgentProjectEditor`、路径不唯一就停、裁判不由模型宣布。

### 3.2 编译和资产检查盖不住运行时

CraftBench-UE（2026-09）在 UE 5.8 上用 70 个任务评测，检查是构建、资产和运行时断言，不用模型当裁判。同一玩法分别要求交 C++ 和蓝图时，C++ 完成率比蓝图高 30.0 和 42.9 个百分点。按时交上、并且资产检查通过的蓝图里，42.2% 和 50.0% 过不了运行时断言。

依据：[CraftBench-UE](https://arxiv.org/abs/2609.23142)。

这和当前验收句的形状一致。`ATestEnemy` 能编译，三个近战事件没有图，默认评测也不进 PIE。`blueprint_compile` 返回空只说明那张图能编过。面试 Demo B 如果只放编译成功的截图，正好落在这篇论文指出的空洞里。

GameEngineBench 用 9 个真实 UE 仓库里的 110 个 C++ 任务，最强配置 pass@1 是 55.5%，31 题没有任何配置做对。依据：[GameEngineBench](https://arxiv.org/html/2607.03525v2)。作品不必去刷这个榜。它说明面试官会把「改了 C++ 并且行为测试过」当成正常门槛，编译退出码 0 只是入场。

### 3.3 分数属于整套配置，交付要有门

[unreal-agent-benchmark](https://github.com/44-99/unreal-agent-benchmark) 把分数记在「模型 + Agent + MCP + Skill」上，并要求六项直接证据：可玩循环、PIE、保存再打开、Win64 打包、打包后启动、打包后冒烟，同时记录时间、费用、失败、重试和人工介入。

当前系统已经具备其中两件：裁判不是模型，trace 里有重试和 token。没有保存再打开的断言，打包计划没执行。面试时主动把范围说成「编辑器内闭环」，六项门里先补 PIE 行为断言。打包仍按 2026-10-13 那份计划，不在本轮升级里插队。声称「生成了一个游戏」之前，六项门不齐就不说。

## 4. 已经能当场讲的，保持不动

这些是面试答案，也是后面每段的约束。

- 为什么不把 830 个工具塞进上下文：扫描只回卡片，`--schema` 一次一个全名，规划者只看见动作目录。官方 MCP 版本记在事实库：2026-09-21，UE 5.8.2，52 个工具集、830 个工具。
- 蓝图是二进制，索引从哪来：关编辑器跑资产导出；编辑器开着时只读导出图名、变量名、事件名。检索正文里的 Actor 坐标是导出快照。
- 模型怎么停下来：有 `verify` 就不能自己 `finish`。连续读不写有熔断，写码成功后的空转会送进 `build`，避免快照把已经写对的 diff 还原掉。
- 危险操作：`save` 和 PIE 要任务显式打开；写前缀工具必须在 `allow_writes` 里；蓝图、材质、UMG、动画、Niagara 各有开关，缺省关闭；Cursor 的 `beforeShellExecution` hook 拦同一批写图工具。
- 换一句措辞为什么有时不用再叫模型：整句集成成功且 `unresolved` 为空，才把句式写进 `learned_routes.json`，上限 50 条。这就是现成的路由，第 6 段要把它的命中率算出来。
- 记忆里没有人格：只有项目约定、错误原文、句式模板、范围台账。

## 6. 实施顺序

每段的验收都是一个文件或一次命令输出。段内不做下一段的事。

### 第 1 段 — 评测能够恢复现场（W4）

已实现。
