## 二、这次没做、留给后续系统升级的（真实残差，不假装修好）

> **2026-10-29 更新：以下 1、2、3、4、5、6、7 已全部落地，本节保留原始问题描述作对照。**
> 落地结论见新增的第四节；其中第 1 条的前提被插件源码推翻（monolith 其实**能**绑控件事件），
> 第 7 条的架构红也一并修掉了。全离线 43 条检查绿。

1. **控件事件图绑定（`BindToEventProperty`）在 monolith 无对应 action。**
   monolith 只有 `blueprint.add_node` + `connect_pins`，语义与 UMG 控件事件绑定不同。当前 `UNSUPPORTED` 如实拒绝。
   影响：HUD 里「点按钮触发什么」这类交互做不了；纯显示（本需求）不受影响。
   升级方向：评估 `ui.list_widget_events` + `blueprint.add_node(AddDelegate)` 的组合能否形成稳定路径，先写一条 `eval/check_*` 离线断言再开开关。

2. **`SetNamedSlotContent` / `GetWidgetClassInfo` 无对应 action。**
   前者需要 NamedSlot 宿主，`ui.add_widget` 进不去（NamedSlot 不是 UPanelWidget）；后者 monolith 只有 WBP 级 `ui.list_widget_properties`。
   升级方向：需要 monolith 侧补 action，或 RAG 侧明确把这两人归入「人工清单」。

3. **`childIndex` 顺序丢失**：`ui.add_widget` 只能 append。需要精确 z 序时用 `ui.set_slot_property` 的 `z_order` 兜。

4. **求解扇的 JSON 稳定性**：`solve` 那次在模型返回纯文本时只能诚实失败（`方案不是 JSON`）。本需求已经绕开求解扇（确定性链），但**表外需求**仍会撞。
   升级方向：给方案层加「一次结构化重问 + 截断保护」，并把这几次失败样本喂进 `failure_patterns`。

5. **模型供应商稳定性**：本次实测遇到 `401 无效的令牌`、`500 分组无可用渠道`、`429 hf-mirror`、理解器返回纯文本。系统现在的应对是「诚实失败」，这是对的；但确定性链之外的句子仍会被这些抖动拖慢。
   升级方向：`core/llm_call.py` 记录错误分类并做有限次退避重试（只对 429/5xx），401 直接失败并提示换键。

6. **HUD 真值仍是占位**：血量写死 100（需求明确「暂时还没有扣血」）；`AFpsPawn` 没有 Health 组件，若以后要真扣血，需要给玩家加 `UFpsHealthComponent` 并把 `Health` 口径（0..1）与显示（0..100）分开。

7. **`eval/check_architecture.py` 现在红**（与本次改动无关，2026-10-28 遗留）：
   `agent/solver.py` 引用 `pipelines.export_capability_surface`，而边界规则只允许 agent 引用 agent/config/core。
   修法二选一：把被引用的常量搬进 `core/`，或把 import 收进函数内并按允许的包取数。属于独立的边界整改，没有混进这次提交。

## 三、可复用的样板（下次同类需求照这个做）

「复杂玩法需求低 token」的判据不是「模型多聪明」，而是**能不能把因果链写进代码**：

1. 句子的窗口结构固定 → 写成 `*_windows(query)` 纯函数，`plan_windows` 在 L1 之前调用，`source=<域>-rules`。
2. 每扇执行的参数形状固定 → 写成确定性执行函数（如 `build_fps_hud`），不进模型工具调用循环。
3. 必须有一条只读收口判词（如 `check_fps_hud`），缺一条就算没做完。
4. 边界外仍走原路径（非该域句子返回 `None`，一字不改）。
5. 加一条离线检查进 `offline.yml`，钉住「零模型」「依赖成链」「三处控件名一致」。

按这个样板，下一批可照做：`载具完整玩法`（上/下车 + 时速 + 射击）、`拾取物 HUD 提示`、`任务目标面板`。
