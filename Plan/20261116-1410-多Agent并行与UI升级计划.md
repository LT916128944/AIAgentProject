### 1.3 三个会把并行放大成事故的问题

**(a) 提交即 `running`，面板在撒谎。**
`running[wid] = pool.submit(...)` 之后立刻 `entry.update(state="running")`（`2169-2172`）。池只有 3 线程，第 4 扇起实际在队列里排队，面板照样画「▶ 运行中」并开始秒表。这不是显示瑕疵——它让「3 并发」这个结论在观测上永远无法被证伪。

> **修法（不新增状态词）**：entry 加 `dispatched_at` / `started_at` 两个字段，`_Pool.submit` 接受 `on_start` 回调，worker 真正取到任务时才回写 `started_at` 并发 `window_state`。**不加 `dispatched` 状态**——那要动 `agent/statuses.py` 这个 D11 唯一真值源，牵出 `_MD_STATUS`、`check_statuses` 的两条子集断言、面板图标表，代价远大于收益。

**(b) 两套写锁，判据不同源。**
`run_windows._GATE` 按 `agent/actions.py` 的 `read_only`/`editor_lock` 判；`core/editor_exec.exec_tool:233` 按 `core/risk.tier()` + 写前缀 + `BLUEPRINT_EDIT_TOOLS` 判。实测差异：`query_actor / query_material / check_platform_hud / check_fps_hud` 四条在 `actions.py` 里写了 `editor_lock: True`，但它们同时在 `READ_ONLY` 里，`_EditorGate.enter` 读优先 ⇒ **这个字段对它们完全无效**；而 `exec_tool` 对它们也不加文件锁（risk=low）。两份声明各说各话，谁也不报错。

跨进程那一半更实际：DSH 同时跑一份 run 时，第二个写窗口撞 `editor_lock` 抛 `RuntimeError("editor busy ...")`（`core/editor_lock.py:100-105`），被 `_run_window` 的 `except` 收成一条泛化 summary（`736-737`），`stop_reason` 记成 `judge_failed`。**该记的是 `editor_busy`。**

**(c) 全部窗口共写一个 checkpoint 库。**
`run_task.py:272` 用 `PROJECT_ROOT / "agent_checkpoints.db"`，实测 **118,509,568 字节**、WAL、`busy_timeout=5000ms`、`SqliteSaver.lock` 是**进程内** `threading.Lock`（对多线程无保护作用，靠 WAL + busy_timeout 硬扛）。3 扇并发时是写放大源；`--resume` 也只能在单库里按 thread_id 找。

## 3. UI：还用 CLI 吗，还是写 HTML？

### 3.1 四个选项摆在一起

| 方案 | 能画「每 agent 一窗 + 进度」 | 能画 agent 之间连线 | 改动面 | 风险 |
| --- | --- | --- | --- | --- |
| 保持 rich 终端面板（现状） | 部分。**最多同时画 3 个 pane**（`board.py:413` `shown = panes[:3]`），更多只写「另有运行中」 | **不能**。rich 没有跨面板连线 | 0 | 无 |
| 终端 TUI 换库（textual 等） | 能，但受终端字符网格限制 | 勉强（用 ASCII 线） | 大（重写 board.py，且 `input()`/Live 抢键盘的老问题更麻烦） | 中 |
| **HTML 只读观测器（推荐）** | 能，卡片自由布局 | 能，SVG 贝塞尔曲线 | 新增 2 个文件，不动执行链 | 低 |
| 把执行入口也搬到 Web | 能 | 能 | **极大**：`UE_RAG_STDIN` 独占、退出码 2、`--resume`、`session_task.json` 写策略、编辑器锁互斥全部重做 | 高，且会让「证据只从落盘文件读」这条原则失效 |

### 3.2 结论：**执行入口仍是 CLI，UI 只换「看」这一半**

四条理由，按重要性排：

1. **证据链在文件里，不在进程里。** `data/runs/YYYYMMDD/<run_id>.json`（机读全量）+ `.md`（人读）+ `.cli.jsonl`（回放）+ `data/events/<run_id>.jsonl`（事件流）+ `data/handoffs/<run>/<wid>.json`。HTML 只读这五个，就是一个纯投影；换掉它不改变任何一条证据。反过来，把执行搬进 Web，等于让「证据」多一个生产者，而 `manual_attest` / `verify` 那套「`passed` 只由裁判改」就要重新论证一遍。
2. **CLI 契约被别的东西依赖。** `start.bat` 的 `UE_RAG_STDIN` 原子改名占位（`96-102`）、`run_guard.admit_live_runs` 的活 run 互斥（退出码 2）、`--force`、`:resume latest`、DSH 侧只读 `data/dsh/session_task.json`。这些全是「人写的文件 → 进程读」的单向链，换成 Web 就要在浏览器和进程之间再造一套授权，收益为零、风险拉满。
3. **rich 的天花板就在这儿了。** 你要的「每个 agent 一块窗 + agent 之间有线」，`board.py` 结构上给不了：`_body` 只取前 3 个 pane，连线无处可画，`_road_lines` 只能用「← W1,W2」表达依赖（`380-399`）。这不是调样式能解决的。
4. **人工裁决反而更适合 Web，但那是第二步。** 现在为了 `input()` 能打字，要先停 Live、再暂停按键监听（`cli_log.pause_live`、`pause_keys`，`board.py:265-300`）。Web 上点按钮更干净——**但那需要一条写通道**（对应 `dsh-user-approval` 那一层）。所以分两步：先只读观测（本次），写通道单独立项。

### 3.3 顺带要修的 CLI 侧小毛病（不改架构）

- `board.py:413` 的 3-pane 上限：改成「并发数 ≤ 终端高度/12，其余进一行汇总」，并把 `max_workers` 显示在标题上（`子代理 · 并发 3/3`）。
- 面板标题 `子代理` 目前是**假的**（P1 之前没有子代理语义）。P1-1 落地后再叫这个名字，或者先改成 `窗口`，避免「名字先于能力」。

## 5. 每个 agent 一块独立窗口：卡片字段清单

## 6. agent 之间的 UI 示意

「有 UI 示意」不能只是排版好看，要能读出三件事：**谁等谁、谁在独占编辑器、谁把什么交给了谁**。

| 形态 | 表达什么 | 数据 |
| --- | --- | --- |
| 绿实线 | `depends_on` 且上游 `done`，下游已放行 | `dependencyMet(depState, childAction)` |
| 灰虚线 | 上游还没终态（`queued`/`running`…），下游在等 | 同上 |
| 深灰虚线 | 上游 `skipped` / `waiting_external`，对大多数下游其实是**没满足**，只有 `run_automation_test` 会放行 | 同上 |
| 红实线 | 上游 `failed` / `paused` / `interrupted` 且下游被挡住 | 同上 |
| 卡片左侧 3px 竖条 | **写锁独占**：谁在 `editor_gate(mode=write)` 里，卡片描边变橙 | P3 的 `editor_gate` 事件；**没这个事件时顶栏显示「写锁 —」而不是「空闲」** |
| 卡片底部 `↓未完成 1/1` | 这一扇交给下游的缺口 | `handoff` 事件 |
| 卡片底部 `↑<标题>` | 下一扇要做什么 | `handoff.next` |
| 顶栏 gauge | `并发 2/3`、`写锁 W6`、`队列 1`、`完成 5/6`、`停因` | `started_at` / `queue_ms` / `editor_gate` / `window_result` |
| 底部完成区（可折叠） | `✓ 5 已完成` + 每扇一行（状态、标题、摘要、`停因`、用时） | 对应你给的参考图右下角 |

连线的四个分支（按两卡的相对位置互斥选接点，避免线从卡片中间横穿）：

1. 目标在右下：下沿中点 → 上沿中点
2. 目标在右上（少见，回边）：上沿中点 → 下沿中点
3. 同一水平带跨列：右沿中点 → 左沿中点
4. 同列往下：下沿 → 上沿；回边：绕右侧

DAG 布局：拓扑分层（层号 = 最长路径深度）+ **重心排序**（按上游行号均值重排，再按下游均值反向修，两趟足够消同层交叉；不迭代到收敛，避免环依赖时死循环）。**不引前端框架、不引图形库**——分层 + SVG 路径就够了，`server/static/` 里一个文件、零构建。

## 10. 风险与已知不确定

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 线程不可强杀（P0-3） | 超时扇可能仍在改源码 | 超时只降级记账；`run_end` 必须点名「仍有 N 扇在跑」；写源码扇仍受 `snapshot` 保护 |
| 动态委派让「清单先定、跑完为止」的契约松动（P1-3） | 任务书人审看到的是**部分**窗口 | `max_windows=8` 硬上限 + 新扇一律 `supplement=True` 标记 + 集成时点名「本次委派新增了哪几扇」。**这条要先由人拍板**，不拍板就只做 P1-1/P1-2 |
| checkpoint 分库后老 run 续接 | `--resume latest` 对老 run 失效 | 保留单库只读回退路径；`run json` 里加 `checkpoint_path` 字段，续接按它找 |
| HTML 与 `statuses.py` 漂移 | 界面出现裸英文状态 | O-1 守卫（§7.2） |
| 8011 端口被占 | 观测器起不来 | 启动参数 `--port`，默认 8011；起不来就打印「改用 `--port`」，不静默重试 |
