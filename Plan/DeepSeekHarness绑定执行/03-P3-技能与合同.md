## 2. 三个技能（源 `.codex/skills`，同步 `.cursor/skills`）

frontmatter 只写 `name` + `description`（≤240 字）。正文 ≤50 行，不复制裁判实现，只写用法与禁止项。

### 2.1 `ue-dsh-route-skill`

触发：要动编辑器、编译、跑 Automation。

- 编辑器操作顺序：`scan_editor_tools`（卡片、无 schema）→ `get_editor_tool_schema`（只取一个）→ `exec_editor_tool`；
- 同一编辑器任务 ≤8 次调用；扫描两轮仍不相关就停，只报「未知工具」，不回退全量 schema；
- 失败原文交人，最多重试一次；
- 保存/PIE/写前缀由 `data/dsh/session_task.json` 决定；模型不得请求修改该文件；
- 纯问答、只改 C++ 源文件（走 `edit_cpp`/`run_task`）、只查资产（走 `search_project`）不扫描编辑器工具。

### 2.2 `ue-dsh-verify-skill`

触发：任何「完成 / 修好 / 通过 / 已生成」之前。

1. `read_contract(run_id)` 取条款；只认 `passed` 与 `evidence_kind`；
2. 对每条 `passed: false` 且非 `manual` 的条款调 `verify(run_id, criterion_id)`；
3. 引用返回的 `{ok, kind, summary}`；`ok: false` 就报未完成与错误原文（≤240 字），不得换说法；
4. 连续 2 条 verify 失败即停，把剩余 unmet 列表交给人和 `run_windows`；
5. `manual` 条款永远不碰；`verify` 不能改 `manual`。

### 2.3 `ue-dsh-handoff-skill`

触发：多步骤/多扇任务收尾。

- 一窗一份：`data/handoffs/<run_id>/<window_id>.json`；
- 字段：`did`（≤200 字）、`evidence[]{kind,ok,summary≤240}`、`unmet`（≤8）、`unmet_total`、`unmet_omitted`、`next`、`artifacts`；
- 不写工具正文；出现 `read_source` 长文即自检失败；
- 写完跑 `python agent/dsh_cli.py handoff-validate --file <path>`，通过才算收尾。

## 4. verify 映射补强（`agent/dsh_cli.py`）

- `criterion.windows` 为空 → 失败，不猜；
- 对每个绑定窗口，取 `window.task.verify[]` 中 `kind == criterion.evidence_kind` 的 spec；多个按顺序跑，第一个返回且 kind 匹配即用；
- `--all`：按 run JSON 里 criteria 顺序跑所有未过且非 manual 的条款，逐条输出结果，任一失败不中断其余；
- `--dry-run` 只算不写；真实写只经 `apply_judge`，且必须带 `judge.kind`；
- 结果里附 `criterion_id`、`window`、`judge` 原文（截 240）与 `policy`（拒绝时）。

## 5. 检查 `eval/check_dsh_contract.py`（fixture + 假 judge，不连编辑器）

夹具：`eval/fixtures/dsh_run_min.json`（新建，一个 run：1 条 `cpp_build`、1 条 `manual`、1 条 `editor_assert`，窗口带 `task.verify`）。

断言：

- 匹配 judge + ok → `passed: true`，其余条款不变；
- kind 不匹配 → 不变；
- `manual` + 任何 judge → 永远 false；
- `verify --dry-run` 不写文件（mtime/内容不变）；
- `criterion.windows` 为空 → 失败且不写；
- 模型文本 `"已完成"` 传入不改变任何 `passed`；
- `contract_status`：自动全过 + 有 manual → 「部分完成」；
- 打印 `dsh-contract ok`。

`feature_list.json` 追加（只追加）：`dsh-skills`（evidence 技能 frontmatter 检查，可挂在 `check_dsh_config.py`）、`dsh-contract`（evidence `eval/check_dsh_contract.py`）。
