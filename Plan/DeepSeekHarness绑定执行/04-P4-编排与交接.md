## 2. 只读工作流模板

### 2.1 `dsh/workflows/research.js`

给 DSH `workflow` 工具的模板，入参 `args = {question, top_k=5}`：

- 阶段 1：一个子代理调 `search_project(question)`，只返回标题/路径/类名（≤10 条）；
- 阶段 2：2–3 个子代理分别读「C++ 类」「蓝图/资产」「文档/历史错误」，每个最多读 5 个文件，结论 ≤500 字；
- 阶段 3：汇总写 `data/briefs/<ts>-<slug>.md`（≤120 行）与同名 `.json`（`{goal, findings[], files[], unresolved[], next}`）；
- 全程**只读**：不调 `exec_editor_tool`、不调 `verify`、不写工程文件；
- 用 `pipeline` 而不是 `parallel`，避免阶段屏障；脚本里 `log()` 只报阶段名。

### 2.2 `dsh/workflows/triage.js`

入参 `{error_text}`：

- 子代理 1：`search_project(error_text, where={"source_type":"ue_error"})`，top_k=1；
- 子代理 2：`search_project(error_text, where={"doc_kind":"debug"})`，top_k=1；
- 返回 `{root_cause, evidence_kind, next_step, confidence}`；证据对不上就返回 `root_cause: "unknown"`，不编。

### 2.3 `dsh/workflows/README.md`（≤40 行）

- 这两个模板怎么被 DSH 使用（复制到 `workflow` 工具的 `script`，或直接让技能引用文件内容）；
- token 预算：每 workflow ≤6 个子代理、结果 ≤8KB、禁止把整份文件塞进子代理提示；
- 只读红线：不得调写工具、不得调 `verify` 改 `passed`。

## 3. handoff 双向

3. 更新 `ue-dsh-handoff-skill`：写文件 → `handoff-validate` → 交付路径；不直接改 `run_windows` 的状态。

## 4. 写锁测试 `eval/check_dsh_lock.py`

- mock 模式、不连编辑器；

- 打印 `dsh-lock ok`。
