谓词用前三份计划已经落地的检查和档案，不重复实现它们：

### P3 — 一条离线命令、健康字段、换机脚本

`eval/check_all.py` 读取 `.github/workflows/offline.yml` 里已有的 `python eval/check_*.py` 行，逐条跑，写一份 JSON 摘要（名字、退出码、耗时）。不复制检查正文。新增的 `check_scorecard.py` 放在最后，这样它看到的是刚跑完的结果。CI 仍逐条列出，本计划不改 workflow 的触发方式；`check_all` 是给人在本机和换机时用的。

`/api/health` 在现有四个字段之外增加：`backend`、`index_present`、`circuit_closed`、`checkpoint_writable`、`disk_free_mb`。每一项带 `ok` 和 `reason`。不调用模型，不连编辑器去探活以外的写操作。`mcp_up` 保持现在的探活。

`RAG/ue-rag/shortcuts/setup.ps1`：找到 Python 3.12，创建 `RAG/ue-rag/.venv`，`pip install -r requirements.txt`。`.env` 不存在时从 `.env.example` 复制，已存在则不动。然后打印三条下一步：`python eval/check_all.py`、`shortcuts/ingest.bat`、`AIAgentProject/start.bat`。不下载 UE，不写密钥。30 分钟是人计时后写入当次换机笔记的数字，脚本不断言这个时间。

`eval/check_risk.py` 增加一条：抽样 `data/costs.jsonl` 时，出现形如密钥的字段就失败。写入成本的路径若还没脱敏，在 `core/llm_call.py` 的记录函数里去掉该字段。不扫整个磁盘。

`eval/report.py` 的成本汇总按 `caller` 分列。已有的 `caller=dsh` 节保持「没有行就省略」。菜单和求解扇同理，没有行就不填 0。

### P4 — 影子技能不得进已提升路由
