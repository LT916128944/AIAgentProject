## 5. 风险矩阵

新建 `data/harness/risk_matrix.json`：

```json
{
  "low": ["read", "search", "retrieve", "query_actor", "run_automation_test", "judge_pickup", "check_pickup"],
  "mid": ["edit_cpp", "compile_project", "compile_blueprint", "move_actor", "set_pickable", "place_actor", "place_blueprint", "apply_unified_diff"],
  "high": ["save_assets", "save_actor", "StartPIE", "StopPIE", "delete", "graph_write"]
}
```

动作名和 MCP 短名是两套。`tier()` 都要认识：`catalog.py` 的 `compile_project`、`edit_cpp`、`move_actor`、`set_pickable`、`place_actor`，以及契约里的 `query_actor`、`run_automation_test`。`graph_write` 展开成 `write_graph_dsl`、`create_node`、`connect_pins`、`add_event`、`add_variable`、`set_pin_value`。材质、UMG、动画、Niagara 的写工具仍由 `editor_exec._domain_blocked` 决定，不要在矩阵里再写一套开关。

新建 `core/risk.py`：

- `tier(name) -> "low"|"mid"|"high"|""`。矩阵里的名字返回对应级。空字符串表示未登记。未登记的 MCP 短名不要当成 high 拒掉，`set_actor_transform` 这类要靠现有 `allow_writes` 放行。
- `decide(name, task) -> {"allow": bool, "reason": str, "tier": str}`。熔断打开时 `allow` 为 false，`reason` 含 `circuit`。其余 `allow` 为 true，把拒绝留给现有逻辑。

`editor_exec.py` 在现有拒绝之前只做追加拒绝：

- 熔断的 `error` 用 `circuit open`，`policy` 仍含 `save`、`pie`、`allow_writes`、五个 `UE_ALLOW_*`。
- 保存、PIE、写前缀不在 `allow_writes` 时，`error` 必须仍是 `write refused`。`check_harness.py` 精确匹配这句。
- 开关为 false 时，改蓝图现有文案是 `blueprint edit disabled`。不要改这句，也不要让 `decide` 再拒一次。

新建 `eval/check_risk.py`，不连编辑器：

- 缺省任务下 `save_assets`、`StartPIE` 被拒绝，且 `error == "write refused"`
- `query_actor` 不在 `allow_writes` 时仍允许
- 临时把 `UE_ALLOW_BLUEPRINT` 设为 false 时 `create_node` 被拒绝，接受 `blueprint edit disabled` 或 `write refused`。测完恢复环境变量
- 矩阵里每个 high 名字都能被 `tier()` 认成 high
- 连续 5 次同一短名失败后 `decide` 拒绝，reason 含 `circuit`。计数文件用 `UE_CIRCUIT_PATH` 指到临时目录
- 通过打印 `risk ok`

用临时 dict 做 task。不要改 `UE_EXEC_MODE`。

## 6. Schema 与故障分类

新建 `eval/check_schema.py`，读 `contract/tools.json`。每个工具必须有：

- `name`、`summary`、`permission`、`timeout`
- `summary` 同时含「适用」和「不适用」。现在的 summary 若只有一句话，补上这两个词，不改变工具行为
- 字符串字段补约束时只加 `maxLength` 和 `description`，不加 `pattern`。`contract_server.py` 不做入参校验，但 `pattern` 会让以后的校验误伤合法路径。现有字段按这张表补，不改工具名：

| 工具 | 字段 | 补什么 |
| --- | --- | --- |
| `query_actor` | `name` | `maxLength: 200`，`description` 含「Actor 名字」 |
| `query_blueprint` | `ref_path` | `maxLength: 300`，`description` 含「/Game 路径」 |
| `find_asset` | `name` | `maxLength: 200`，`description` 含「资产名」 |
| `run_automation_test` | `filter` | `maxLength: 200`，`description` 含「Automation 过滤器」 |
- `output_schema.required` 含 `ok`
- `error_schema` 含 `ok` 与 `error`
- 新增 `retryable` 布尔：参数错误为 false，超时和连接失败为 true。挂在工具对象上

超时只允许 60 或 300，与第 1 节一致。改 summary 和补约束时不要改工具名，不要改 `server/contract_server.py` 的转发名单。

新建 `core/fault.py`：

```text
compile / test / tool_refused / level_precheck → retryable false
mcp_down → retryable true，最多 1 次
retry_exceeded → retryable false
other → retryable false
```

连续同一 `tool` 短名失败达到 5 次，写入 `data/harness/circuit.json`：`{tool, opened_until}`，冷却 30 秒。路径可被 `UE_CIRCUIT_PATH` 覆盖。冷却期内 `decide` 拒绝，reason 含 `circuit`。过期靠 `opened_until` 判断，不删条目。不要把冷却做成线程池。

`check_schema.py` 通过打印 `schema ok`。另加三个纯函数断言：参数类错误不重试；`mcp_down` 可重试；第 5 次失败后 `circuit` 拒绝。可以放在 `check_schema.py` 末尾，也可以放在 `check_risk.py`。两处不要各写一套阈值。阈值只在 `core/fault.py`。
