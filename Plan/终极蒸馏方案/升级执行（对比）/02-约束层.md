## 5. 风险矩阵

`data/harness/risk_matrix.json`：

```json
{
  "low": ["read", "search", "retrieve", "query_actor", "run_automation_test", "judge_pickup", "check_pickup"],
  "mid": ["edit_cpp", "compile_project", "compile_blueprint", "move_actor", "set_pickable", "place_actor", "place_blueprint", "apply_unified_diff"],
  "high": ["save_assets", "save_actor", "StartPIE", "StopPIE", "delete", "graph_write"]
}
```

**两套名字并存**：`catalog.py` 的动作名（`compile_project`、`edit_cpp`、`move_actor`、`set_pickable`、`place_actor`）和 `contract/tools.json` 的工具名（`query_actor`、`run_automation_test`）都要被 `tier()` 认识。`graph_write` 指 `write_graph_dsl`、`create_node`、`connect_pins`、`add_event`、`add_variable`、`set_pin_value` 及材质/UMG/动画/Niagara 写工具。

`core/risk.py`：

- `tier(name) -> "low"|"mid"|"high"`。未登记的写前缀（`Set`/`set_`/`Spawn`/`Delete`/`Add`/`Remove`/`Create`）视为 `high`。纯读视为 `low`。
- `decide(name, task) -> {"allow": bool, "reason": str, "tier": str}`。  
  `low` 允许。  
  `mid` 只有落在 `allow_writes`、或是 `read_source`/`apply_unified_diff`/`cpp_build` 时允许；路径仍在 `Source/AIAgentProject`。  
  `high` 保存类要 `task.save`，PIE 类要 `task.pie`，其余默认拒绝。图写入看五个 `UE_ALLOW_*`，false 拒绝。

**`editor_exec.py` 改动原则（关键）**：

- `exec_tool` 在现有拒绝逻辑**之前**调用 `decide`。
- `decide` **只做额外拒绝**（circuit、未登记 high、图写开关）。现有逻辑会拒绝的路径（save 无 `task.save`、pie 无 `task.pie`、写前缀不在 `allow_writes`），`decide` 不改变其 `error` 文本。
- 现有拒绝的 `error` 必须仍是 `"write refused"`，`policy` 必须仍含 `save`、`pie`、`allow_writes`、五个 `UE_ALLOW_*`。`eval/check_harness.py` 的 `error == "write refused"` 是精确匹配，动了就红。
- 新增拒绝（circuit）可以用新 `error` 文本（如 `"circuit open"`），并带 `policy` 和 `reason`。
- 若两套判断冲突，收紧的生效，但保持现有文本。

新建 `eval/check_risk.py`，不连编辑器：

- 缺省任务下 `save_actor`、`StartPIE` 被拒绝，`error == "write refused"`
- `query_actor` 在不在 `allow_writes` 时仍允许

## 6. Schema 与故障分类

新建 `eval/check_schema.py`，读 `contract/tools.json`。每个工具必须有 `name`、`summary`、`permission`、`timeout`、`retryable`。`summary` 含「适用」和「不适用」。`output_schema.required` 含 `ok`。`error_schema` 含 `ok` 与 `error`。超时只允许 60 或 300。

**string 字段约束**（现有 4 个字段，全都没有约束，照原文会红）：

| 工具 | 字段 | 补什么 |
| --- | --- | --- |
| `query_actor` | `name` | `maxLength: 200` + `description` 含「Actor 名字」 |
| `query_blueprint` | `ref_path` | `maxLength: 300` + `description` 含「/Game 路径」 |
| `find_asset` | `name` | `maxLength: 200` + `description` 含「资产名」 |
| `run_automation_test` | `filter` | `maxLength: 200` + `description` 含「Automation 过滤器」 |

先读 `server/contract_server.py` 是否做运行时校验：**没有校验就只加 `maxLength` + `description`；有校验就只加 `description`，不加会拒绝合法输入的 `pattern`**。`check_schema` 的 string 断言接受「`maxLength` 或 `pattern` 或 `enum` 之一，或 `description` 含标识符/路径/名字」。这样不改变运行时行为。

`retryable`：参数错误 false，超时和连接失败 true，挂在工具对象上。不改工具名，不改 `contract_server.py` 转发名单。

新建 `core/fault.py`，阈值只在这里：

```text
compile / test / tool_refused / level_precheck → retryable false
mcp_down → retryable true，最多 1 次
retry_exceeded → retryable false
other → retryable false
```

连续同一 `tool` 短名失败 5 次写 `data/harness/circuit.json`：`{tool, opened_until}`，冷却 30 秒。冷却期内 `decide` 拒绝，reason 含 `circuit`。进程内计数 + 文件持久，过期靠时间判断，不删条目。路径可被 `UE_CIRCUIT_PATH` 覆盖，供测试用。

`check_schema.py` 通过打印 `schema ok`，末尾加三个纯函数断言：参数错误不重试；`mcp_down` 可重试；第 5 次失败后 circuit 拒绝。
