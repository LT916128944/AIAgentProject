## 1. 本次真修掉的 3 个 bug（都已验证）

### BUG-1 跳跃落不到比起点高的平台（玩法致命）

- 现象：`UpdateJump` 只要下落就 `NewLocation.Z = JumpStartZ` 硬夹回起跳高度，
  高处平台直接穿过去。审计实测六个跳点**全部 impossible**。
- 位置：`Source/AIAgentProject/Private/TestPawn.cpp::UpdateJump`（改前 290-312 行）
- 修法：下落段改用 `FindGroundBelow()`（`LINE_TRACE` / `ECC_Visibility`）探脚下支撑面，
  命中就把 Z 夹到该面、`VerticalVelocity=0`、`bJumping=false`；探不到就继续下落。
- 同批：`MoveSpeed` 100 → 300（原值下水平可达仅 90.4uu，而相邻平台中心距 104–200uu，
  无论怎么修落地都跳不过去）。
- 验证：`Automation` 新增落地断言 + 纯数值断言，见 BUG-3。
- 命令：`.\.venv\Scripts\python.exe -c "from core.judge import judge; print(judge({'kind':'automation','filter':'AIAgent.Platform'}, {'allow_writes':[],'save':False,'pie':False}))"`
- 真实输出：`失败数 0（1 个测试） tests=AIAgent.Platform.Run`

### BUG-2 Pawn 只在跳跃时受重力（走出平台不掉、也不站不住）

- 现象：`Tick` 里只在 `bJumping` 为真时跑 `UpdateJump`，其余时间没有任何垂直位移。
  结果是玩家悬在空中一直朝前飞。
- 位置：`TestPawn.cpp::Tick` + `UpdateJump`
- 修法：垂直更新每帧都跑；`bJumping` 只决定「空格还能不能再触发跳跃」，
  不再决定要不要跑重力。落地判定沿用 BUG-1 的 `FindGroundBelow`，不另写一套探地。
- 验证（PIE 实测，把 Pawn 抬到平台正上方 200uu 再放手）：

  | 时刻 | Pawn 位置 |
  | --- | --- |
  | t=0.0s | (200.0, 30.0, 131.1) |
  | t=0.6s | (200.0, 30.0, **40.0**) |
  | t=3.6s | (200.0, 30.0, **40.0**) |

  `Platform_Front_1` 的坐标正是 (200,30,40)，顶面 z=40。掉落 → 落到真平台 → 站住。

### BUG-3 关卡里 4 个游离实例让「收齐金币」永远不成立（通关致命）

- 现象：`L_NewTest` 里多出 4 个在原点附近的实例，`place_actor` 用默认坐标放出来的：

  | label | 坐标 | 危害 |
  | --- | --- | --- |
  | `BP_Progress` | (0,0,100) | 进度中枢变成 2 个 → `FindWorldProgress` 第 109-110 行「不唯一就返回空」→ 金币不注册、HUD 绑不上、门不响应 |
  | `BP_Coin` | (0,0,300) | 金币总数多 1 → 7 枚永远收不齐，门永不开 |
  | `BP_Door` | (0,0,150) | 多一扇门 |
  | `BP_Platform` | (0,0,100) | 多一块悬空平台 |

- 修法：新增确定性动作 `remove_batch`（不叫模型），按 **label + 坐标 2uu 容差**
  双重条件精确删；筛不出唯一一条就整批不删。
- 验证：15 个实例（= 设计图 6 金币 / 7 平台 / 1 门 / 1 进度中枢），
  且 PIE 里 6 枚金币全部收掉、门 z 420 → **720**。
- 位置：`RAG/ue-rag/agent/sequence.py::pick_removal_target` /
  `_remove_batch`；任务体 `RAG/ue-rag/data/dsh/task_remove_strays.json`

## 2. 工作流缺陷（本次已修，但值得记住）

### WF-1 `edit_cpp` 窗口把用户需求整段丢掉（影响面最大）

- `run_windows._build_graph_task`（`action == "edit_cpp"` 分支）用
  `_try_cpp(f"{title}。类 {class_name}。编译")` 重建任务句，
  **只有标题和类名，原句需求一个字都不带**。
- 实测后果：整句 run `20261024-011917` 的 W1 只拿到「改 C++ 并编译。类 ATestPawn。编译」，
  模型只好去猜，最后改了个无关紧要的 `bCanBePossessed = true`，编译 exit 0 就算成功。
  **这是「低 token」的代价被错误地转嫁到了正确性上。**
- 修法建议（**遗留，未做**）：`edit_cpp` 分支应把 `origin`（原句）里的需求半句带进
  `task["query"]`；`_try_cpp` 自己（rules 路径）本来就保留了原句，只有 `run_windows`
  的窗口重建把它丢了。这是本次唯一没动的缺陷，见第 4 节。

### WF-2 `_pinned_class` 找不到类时静默回落到别的类

- 句子点名 `Private/PlatformRunTest.cpp`（该文件没有 `UCLASS`），`_FILE_RE` 命中
  `PlatformRunTest`，但 `_resolve_class` 返回空 → `_pinned_class` 返回 `None` →
  `_unique_class` 从句子里的其它 token 挑中 `ATestPawn` → 生成
  「只改 Public/TestPawn.h 与 Private/TestPawn.cpp」，**与用户点名的文件矛盾**。
  模型读到这条自相矛盾的指令后一次 diff 都没写，W1 判失败。
- 现状：**未修**。本次绕过办法是改用 `run_task.py --task` 直接给固定 `query`。
- 修法建议：`_pinned_class` 里 `_FILE_RE` 命中但解析不出类时，应返回一个
  「钉死到该文件、不要求类」的任务（只做 `cpp_build`，不生成「只改 X.h」那句），
  而不是回落到 `_unique_class` 猜别的类。

### WF-3 菜单 2 会假成功（菜单 3 不会）

- 详见 `RAG/ue-rag/data/dsh/key-impact.md`（本次由 `key-impact-analyst` 只读查证产出）。
- 401 时菜单 3 必落 `_paused` 暂停扇，不会假成功；
  **菜单 2 的 `_planner_failed` 回退绕过 `_rules_cover`**，直接吃 `_plan_rules` 裸结果，
  实测平台跳跃句在菜单 2 下只剩 1 步 `place_blueprint(BP_Coin)`，
  平台/门/进度中枢全丢、无 PIE 验证步，却 `return 0`。
- 现状：**未修**。修法建议：让菜单 2 的回退分支也过 `_rules_cover` 这同一道闸。

### WF-4 verify 读不到 verify spec（DSH 侧合同空洞）

- 已修。`dsh_cli._verify_specs` 只从 `entry["window"]["task"]["verify"]` 取，
  而 run 记录里的 `window` 是规划窗口定义，从来没有 `task` 键 → 所有
  `editor_assert` / `automation` / `cpp_build` 条款在 DSH 侧都只能说
  「窗口里没有 spec」。
- 修法：写侧 `run_windows` 落 `entry["task"]` 快照；读侧四处来源按可靠性排回落，
  **取到就不再往后走**（记录里 verify 为空就是「本来没留 spec」，不许拿规则补一条）；
  `detail.build`/`detail.test` 一律不当 spec。
- 验证：`eval/check_verify_spec.py` → `verify-spec ok`；`check_dsh_contract.py` → `dsh-contract ok`

### WF-5 `.env` 里 `DEEPSEEK_API_KEY` 是失效 key（本次第一个卡点）

- `.env` 第 1 行 key（尾 `1Hei`，len 51）实测 `401`；第 2 行被注释掉的
  （尾 `4e11`，len 35）实测 `200`。`load_dotenv` 默认 `override=False`，
  而进程环境里本来就有那把有效的 → **第 1 行的失效 key 一直在覆盖它**。
- 人要做的最短修复（只动一行，本次**未代改**，按规矩 `.env` 只由人写）：
  把 `.env` 第 1 行换成第 2 行那把 key 的值，改完必须重开 python 进程。
- 验证（零 token，`GET /models` 不计费）：
