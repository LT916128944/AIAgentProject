# 实施计划模板

按下列六段写。缺一段则 Plan 不完整。不要贴整份头文件；签名 + 职责 + 落点即可。

仅当本次**将改 UE 项目**（C++ 或蓝图）时落盘：`.cursor/memory/plans/YYYY-MM-DD.md`（一天一份；同日多需求用 `## 主题` 追加）。改 Cursor / 分析文档 / 没动手 → 不写。不要写进 `documents/`。

## 1. Summary

一句话目标。放哪（模块 / 目录）。仿谁（已有类或文件）。

## 2. Current State

| 文件 | 现状要点 | 本次 |
|------|----------|------|
| path:line | 能复用什么 / 缺什么 | 新建 / 改 / 不改 |

只列真正读过的文件。

**范式锚点**：一个已读过的文件 + 要照抄的行为（懒初始化、Timer、`ShouldCreateSubsystem` 等）。只写签名和职责。没有可仿的文件就写「无」。

## 3. 已确认决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 职责放哪 | … | … |
| 仿谁 | … | … |
| 不改谁 | … | … |
| 使用约束 | … | 这个落点容易踩的坑；没有则删本行 |

未确认的分叉不要写进 Proposed Changes。

## 4. Proposed Changes

按文件：

- **新建** `Public/…/X.h` + `Private/…/X.cpp` — 职责、公开 API、生命周期
- **修改** `Y.cpp` — 改哪一段、改成什么
- **不改** — 明确排除的文件 / 模块 / Build.cs

能不改 `Build.cs` 就不改。

改动多于一个文件时，在本节末尾写实施顺序（1. 2. 3.）。单文件不写。

## 5. Assumptions

未拍板但必须先假定的点。写清「若用户否定则停」。

## 6. Verification

只验用户要的那一项。写：编译目标（若需要）+ 一条运行/日志期望。编辑器能验就不 PIE。用户说不用运行 / 不用保存 → 不 StartPIE、不存盘。
