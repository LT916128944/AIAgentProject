- **目标**：让 `BP_TestEnemy`（父类 `ATestEnemy`）能在自己的 EventGraph 里接 `OnPatrol` / `OnChase` / `OnMeleeAttack`，从而让 `patrol-presentation` 这句基准有可执行路径。
- **操作**：
  - `Public/TestEnemyPatrolComponent.h`：文件头加三条 `DECLARE_DYNAMIC_MULTICAST_DELEGATE`（`FTestEnemyPatrolSignature` / `FTestEnemyChaseSignature` / `FTestEnemyMeleeSignature`）；类内加三个 `UPROPERTY(BlueprintAssignable)` 属性 `OnPatrolDyn` / `OnChaseDyn` / `OnMeleeAttackDyn`。三个原有 `BlueprintImplementableEvent` 一字未动。
  - `Private/TestEnemyPatrolComponent.cpp`：四处事件调用点各补一次 `XxxDyn.Broadcast()`（`:39` / `:65` / `:75` / `:86`）。
  - 关编辑器（`editor.run_console_command QUIT_EDITOR`，先 `list_dirty_packages` 确认 0 脏包）→ `Build.bat AIAgentProjectEditor Win64 Development -Project=… -WaitMutex` 全量重建 → 重启编辑器。
- **结果**：
  - 编译 **Succeeded**，0 error，`TestEnemyPatrolComponent.cpp` 被 adaptive non-unity 单独编译并成功链接（证明 UHT 生成了委托代码）。
  - `blueprint.resolve_node` 干跑三次全部命中：`resolved_class=K2Node_AddDelegate`，`node_title` 分别是 `Bind Event to On Patrol Dyn` / `On Chase Dyn` / `On Melee Attack Dyn`，`pin_count=4`、`warnings=[]`。**Actor 蓝图现在确实能绑这三个事件。**
  - `editor.run_automation_tests` prefix=`AIAgent.Enemy.Patrol` → **1 passed / 0 failed**，与改前一致，未破坏既有行为。
- **经验**：
  - **`BlueprintImplementableEvent` 只能由声明它的类自己实现。** 事件声明在组件上，挂在 Actor 上的该类组件事件，Actor 蓝图接不到——这不是 monolith 词表缺节点类型，是 UE 语义。补 `BlueprintAssignable` 委托（`Bind Event to XxxDyn`）是正解，`K2Node_AddDelegate` 走的是已有节点类型。
  - 因此 `data/harness/feature_list.json` 里 `patrol-presentation` 那条「monolith 蓝图词表没有覆写组件 BlueprintImplementableEvent 的节点类型（resolve_node 干跑实测）」的归因**已过时**：词表从来没缺，是选错了事件形态。`override_parent_function` 也不适用——它只覆写**父类**的可覆写函数，而这三个事件声明在组件上，`BP_TestEnemy` 的父类 `ATestEnemy` 并没有它们。
  - 组件场景里委托与 BMP 事件可以并存，同项目范式见 `PlatformProgressComponent.h:10-14,53-60,81-88`；用 `Dyn` 后缀区分，避免蓝图里两个同名入口。
  - **新增 `DECLARE_DYNAMIC_MULTICAST_DELEGATE` 必须关编辑器全量重建**，Live Coding 干不了（又一次印证 conventions 第 39 条）。

- **经验**：
  - `variable_name` 要填 **C++ UPROPERTY 名**（`PatrolComponent`），不是 `CreateDefaultSubobject` 的子对象名（`Patrol`）。填错会静默生成一个 `title="Get"`、`pins=[]` 的空 VariableGet，不报错——`get_node_details` 也看不出问题，只有 `pins` 空这一处可判。
  - `ComponentBoundEvent` 只认 SCS 组件；native 子对象（`is_native: true`）用它会被拒（"must be a named subobject on the BP — SCS component"）。native 组件绑定走 **`AddDelegate` + CustomEvent** 这条路。
  - `AddDelegate` 的 `Delegate` 输入不需要 `K2Node_CreateDelegate`：直接接 `CustomEvent` 的 `OutputDelegate` 输出即可（`add_node` 的类型表里没有 CreateDelegate，无需去找）。
  - 验证蓝图接线不能只跑 automation——`AIAgent.Enemy.Patrol` 只测组件逻辑，完全不覆盖 EventGraph。必须 spawn 实例 + PIE + 读 `LogBlueprintUserMessages`，才看得到 `PrintString`。
  - 当前关卡里原本没有 BP_TestEnemy，直接 PIE 会"通过但什么都没测到"。先 `mesh.get_level_actors` 确认目标 Actor 在场。
