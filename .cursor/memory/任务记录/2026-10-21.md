### 任务 1：定位失败原因
- **目标**：整句要「能玩的平台跳跃关卡」，跑完只有 WBP_HUD，金币/平台/门一个没放，为什么还记 6/7 扇成功。
- **操作**：
  - 读 `data/runs/20261021/20261021-221446.md` 与 `data/events/20261021-221446.jsonl`
  - L1 理解器的 `unresolved` 原话：「金币、门、平台的具体蓝图资产名与摆放位置」「前段平台静止、后段平台移动的关卡布局与运动参数」
  - 窗口清单只有 `edit_cpp` / `create_widget_blueprint` / `edit_widget_blueprint` / `check_platform_hud` / `run_automation_test` / `probe_play`，一扇 `place_batch` 都没有
  - 合同三条：`c-cpp_build` / `c-widget_graph` / `c-automation`，没有一条要求关卡里有东西
  - 编辑器实读：`L_NewTest` 里 17 个 Actor，没有 `Coin_*` / `Platform_*` / `Door_*` / `Progress_*`
- **结果**：四层原因叠加
  1. `intent.validate_intent` 只要求 `goals` 非空，`unresolved` 纯记录，不阻塞也不转窗口
  2. 唯一的「需求被丢」护栏 `_unbound_demand` 只挡 learned 路线，理解器路径没有

  - 附带：`level-assembly` 记 passed（证据 20261020-164911「幂等跳过 6」），但关卡现在确实是空的——那次「已保存」之后被覆盖或没真正落盘，本次重新放置才算数
- **经验**：
  - 「模型说完成了」和「场景里真有」之间必须有一条只读读数。UI 编译通过、内存自动化失败数 0，都不能证明关卡被搭起来
