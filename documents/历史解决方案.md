## 这句话写不成任务：自然语言移动 Actor

现象：多 Agent 里输入「帮我操作UE编辑器场景的Cube到(X=120.000000,Y=400.000000,Z=150.000000)位置，并且验证一次即可保存退出」，或把 Cube 写成「Actor Cube」，返回「这句话写不成任务。需要唯一的类、蓝图、Actor 或过滤器。」坐标其实已经能读成 (120, 400, 150)。

原因：`agent/supervise.py` 以前只把「移动 / 移到 / 放到」当成编辑器任务。对不上就交给模型，模型被要求看不准就 `kind=none`。取名用了 `\b`，中文也算单词字符，「的Cube」「的Actor」切不开；`(X=120` 里的 X、Y、Z 又变成额外英文词，于是放弃，不猜。任务里还写死了不要保存。

改法：已经落在 `.cursor/skills/ue-history-skill/SKILL.md` 和 `agent/supervise.py`。用关卡语料里的 `actor_label` 对句子，边界只看 ASCII 字母数字。唯一的 `Cube` 再加上一组 x/y/z，就是移动任务，不要求用户说「移动」或「名为」。说了「保存」才 `save: true`，并允许 `save_assets`（`asset_paths` 传空数组）。「退出」只是结束这轮对话，不关编辑器。模型说 `none` 时，句子里已经有唯一 Actor 和坐标，也不覆盖。两个真实名字同时出现才拒绝。现象对不上这一节时，不要用本说明硬修，改走 `ue-debug-skill` 或当前域技能。

## 查关卡是否已存在失败：UE_EDITOR_BACKEND=monolith

现象：新建关卡（例如 L_NewTest3）在 W2 失败，原文是「查关卡 /Game/Maps/L_NewTest3 是否已存在失败：UE_EDITOR_BACKEND=monolith」。编辑器已经起来，MCP 也通了。

原因：`create_level` 用官方 `AssetTools.exists`。`UE_EDITOR_BACKEND=monolith` 时 `exec_tool` 第一行就拒绝，不会去查资产，也不许失败后再改连 9316。

改法：后端是 monolith 时，`agent/sequence.py` 的 `_create_level` 直接走 `project.get_asset_details`，没有就 `editor.create_empty_map`（空白关卡，会自己落盘；Monolith 没有通用的关卡复制），还没切过去再 `editor.load_level`。索引里没有写成「不存在」；连不上、子系统没有，仍算查存在失败。official 仍是 exists → duplicate 模板 → save_assets → load_level → get_current_level。

## 两个 MCP 插件同时开着，集成仍报能力缺口

现象：插件里 Unreal MCP 和 Monolith 都勾着。一次「新建 L_NewTest3 并做简易 FPS」跑完后，W1、W2 成功，W3 失败，原文含「能力缺口：没有可执行的窗口」和「玩家可操控的射击主体」。

原因：范围 C 被 `data/skills/lexicon.json` 的 FPS / 射击行标成 unplannable，窗口数为 0。人审确认后，集成按缺口判未完成。这和两个端口同时在听不是同一件事。W2 摘要「已新建空白关卡」说明写操作已经走了 Monolith。另外，`mcp_up` 以前固定探官方 `8000`，后端是 monolith 时会把官方插件的响应当成「MCP 已连通」。

改法：`core/editor_launch.py` 按本次后端探 `9316` 或 `8000`。另一边也有响应就拒绝，原文点名要关的插件，不改连那一边。FPS 那句仍是能力缺口，关插件不会自动拆出射击窗口。
