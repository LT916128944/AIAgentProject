# 框架选型

闭环里进运行路径的只有 LangGraph。下面四段说明本仓库用或不用的理由。

## LangGraph

本项目的闭环图在 `agent/graph.py`，用的是 LangGraph 的 `StateGraph`。节点是 retrieve、plan、execute、build、test、observe、fix，边按裁判的 ok 分流。`verify` 非空时模型不能自己结束，失败才进 fix。菜单 2 和菜单 3 都进这一张图，checkpoint 用 `langgraph-checkpoint-sqlite` 的 `SqliteSaver`，按 `thread_id` 续。LangGraph 是唯一进运行路径的框架。

## LangChain

模型调用在 `plan_node` 和理解器里，直接用 OpenAI SDK 打 `UE_LLM_MODEL`。工具 schema、角色裁剪、最近 6 条工具结果都是项目自己的代码。动作表在 `catalog.py`，归地在 `grounding.py`，任务不经过 Chain 或 AgentExecutor。`requirements.txt` 没有把 LangChain 列成业务依赖。运行路径上不从 LangChain 编排任务。

## LlamaIndex

检索在 `core/retrieve_funnel.py`：专有名词能唯一命中就停，否则 BM25 和 bge 各取 20 条再做 RRF。向量库是 Chroma，模型是 `bge-small-zh-v1.5`。四列对照写在 `eval/reports/20261016-154827-retrieval.md`。这套漏斗没有 LlamaIndex 的索引或查询引擎。

## Semantic Kernel

技能注册是 `skill_cards.json` 的触发、工具、版本和冲突，引擎里另有一条 AgentSkill。选动作和槽位在理解器和 `intent.py`，裁判在 `judge.py`。这里没有 Kernel、Plugin 或 Planner。编排留在 LangGraph 的状态和条件边上。
